# `unused` rules

Dead declarations and dead code. One section per rule, by id; each rule's language, default and fix marker are in the [rule index](../../lint-rules.md#unused), and a suite test fails when a registered rule has no section here or a section names no rule of this category.

## `dead-code`

a statement made unreachable by a preceding unconditional `return` / `throw` / `break` / `continue` in the same block — purely structural (no type information); `--fix` deletes the whole dead run (every statement from the first unreachable one to the block's end)

## `dead-store`

an assignment to a local / parameter whose value is provably never read on any path (overwritten, or the function exits first) — a wasted computation that usually indicates a logic slip; `Info`, report-only. Two forms: a plain assignment (`x = e;` then never read) and a `var` initializer reassigned before any read (`var x = e; x = f;`). Backward-**liveness** engine embedded in the check (the dual of `NullFlow`, over-approximated in the opposite direction — every uncertainty makes MORE names live, so a report means dead-on-all-paths): branches union their arms; a loop keeps every name read anywhere inside it live at its boundaries and branch seams (back-edge safety, and the pre-loop state survives a zero-iteration run — a reassign-then-reassign within one straight-line run is still caught), `switch` / `try` seeded likewise; a `return` clears the state but a `throw` makes every name live (its continuation is an unmodeled `catch`); `break` / `continue` (which project as plain identifier expressions — `RefShape.loopJumpNames`) make every name live; a short-circuit right operand (`&&` / `||` / `??`) or the arguments of a call whose callee chain contains a `?.` evaluate conditionally, so their kills never leak into the skip path; a name a closure reads or writes is excluded entirely, as is a name bound more than once in the unit (name-keyed liveness cannot tell shadowed bindings apart); a multi-binding `var a = 1, b = 2;` (projected as one node) is never reported though its initializers' reads still count; `macro` reification makes everything live; a `'$name'` interpolation counts as a read (`RefShape.stringInterpIdentKind`). Partition with `unused-local`: that check owns the binding never referenced at all (its text scan counts a write as a reference), so a written-then-never-read local is this check's finding, and a dead `var` initializer is reported only when the name IS referenced elsewhere in its enclosing scope; a `final` initializer is never flagged. Report-only: deleting a store is behavior-preserving only when its right-hand side is side-effect-free — an autofix promotion can follow once the engine has earned trust

## `self-assignment`

a LOCAL variable assigned to itself (`x = x`), a provable no-op — flagged only when `x` resolves to a local declaration; a field / property self-assignment (`p = p` or `this.x = this.x`) may invoke a setter and is left alone; `--fix` deletes a flagged local self-assignment

## `unused-case-binder`

a switch case-pattern BINDER that neither the arm's guard nor its body ever reads — dead weight the wildcard should replace; `Warning` (the rank `unused-local` and `unused-parameter` carry), `--fix` rewrites it. `case _data:` becomes `case _:`, `case Node(x, y): use(y);` becomes `case Node(_, y): use(y);`, `case var q:` becomes `case _:`, and an unread `=`-capture head is DROPPED outright (`case q = P(v):` becomes `case P(v):`). A binder counts as unread only when the number of nodes MENTIONING its name anywhere in the whole arm — pattern, guard, body, a nested switch's own labels — equals the number of BINDER occurrences the pattern scan found, so a guard read (`case x if (x > 0):`), a `'$x'` string-interpolation read and a nested re-binding of the same name all block the fix; the count is deliberately coarse, since over-counting can only REFUSE. Or-pattern alternatives are unbound TOGETHER — Haxe requires `case A(x), B(x):` to bind the same set in every alternative, so one finding carries every occurrence's edit and `case A(_), B(_):` stays legal, while an alternative that still reads the name blocks the whole group. Binder positions are a WHITELIST (shared with `redundant-case-body` in `CasePatternScan`): an identifier, a `var x` capture, an `=`-capture's left slot, a constructor call's ARGUMENTS (never its callee), an array element, a structure field's VALUE (never its label), a parenthesised sub-pattern, and an extractor's RIGHT side — its left side is an EXPRESSION evaluated on the subject, so identifiers there are reads. Constant leaves (a dotted path, a string / numeric / boolean / null literal, a negated numeric) bind nothing; anything else makes the scan REFUSE the arm, so an unmodelled grammar shape can never read as "binds nothing". The family SPELLING assumption `prefer-case-guard` and `collapse-nested-switch` already make — a bare identifier is a capture binder unless it opens with an uppercase ASCII letter — is not universally true in Haxe: a LOWERCASE `enum` / `enum abstract` value AND any `static inline` field resolve unqualified in a pattern too (the latter both inside its own type and through a static import), so `case one:` may denote a CONSTANT — and widening a constant to `_` would change what the arm matches while still COMPILING, the one failure mode a compiler oracle could not catch. Two gates bound that, and both apply ONLY to bare identifiers (a `var x` capture and an `=`-capture head are binders by syntax): (1) NO DECLARED CONSTANT of that name — `CasePatternScan.declaredConstantNames` collects, from every file in the lint scope, each member of an exhaustiveness-checked type (`bareConstructorTypeKinds`), each member of ANY abstract or alias declaration (`aliasingDeclKinds` — which is what reaches a legacy `@:enum abstract`, projected as a plain abstract with no marker the scan can read), and each STATIC member of any type, so a single-file run refuses LESS than a project-wide one and project-wide is the intended `--fix` scope; (2) a binder that IS THE WHOLE PATTERN must sit in the LAST arm of its switch and be that arm's only pattern. Under the binder reading the arm is a catch-all and `_` is exactly equivalent — Haxe compiles a bare capture to a wildcard plus a binding, so the two decide identically for every subject, `null` included (checked on `--interp` and `-js`); under the constant reading the arm list compiles today, which for an `enum` / `enum abstract` subject means the compiler proved it EXHAUSTIVE, so at the last position `_` covers precisely the values the constant did. Both readings agree without knowing which holds — a NON-final position has no such agreement (`case one: a; case two: b;` would turn `two` into dead code) and neither does a subject the compiler does not check for exhaustiveness (a `String` switch), which is exactly what gate 1 has to carry. A NESTED bare identifier rests on the spelling assumption plus gate 1 alone: the rule's one documented residual, a constant declared OUTSIDE the lint scope. It is NOT the residual the sibling rules carry — `prefer-case-guard` excludes bare lowercase identifiers from its whitelist outright and its own residual is a hard compile error, not a silent behaviour change. An arm holding a conditional-compilation region or a macro reification is skipped outright, and the walk never descends into a reification subtree. Seam-driven via `CasePatternScan.seamsOf` (a required kind unset → no-op, report and fix alike). Idempotent: every flagged name becomes `_`, which is never a binder

## `unused-local`

a local `var` / `final` never read in its enclosing scope. Every binding of a multi-variable declaration counts (`var a = 1, b = 2;` reports `b`), but the autofix DELETES BY LINE, so any binding SHARING its line with another is reported and left in place — cutting one would take its live siblings with it. The reference test is a raw word-boundary scan of the enclosing scope, and a scan that DOES find a reference is re-run once with the regions another binding owns excluded as well: the body and binder of an inner self-scoped declaration (`RefShape.selfScopeDeclKinds` — a `for` iterator in either position, a `catch` exception, a key-value loop's VALUE binder), and a RE-DECLARATION of the name in the same statement list. The second of those is legal Haxe and resolves by position, so `var a = 1; var a = 2; return a;` leaves the FIRST binding dead while the name still appears below — invisible to a scan that counts the name, and the finding carries the re-declaration's line so the report does not read as wrong. Only the re-declaration's binder TOKEN and everything past its end are excluded, never its initializer: `var a = a + 1` reads the first binding in the second declaration's own right-hand side. DIRECT children of the scope only — a declaration in a nested block, a `switch` arm or a conditional-compilation arm is scoped to what encloses it and takes nothing over, which is how the last of those reaches the same refusal `RefactorSupport.exclusiveBranchRedeclaration` makes for `rename` / `extract-method`. The reverse direction is NOT refused — a first declaration guarded by `#if` with the re-declaration outside it is dead in the configuration that has it and absent in the rest. The FIRST declaration must also bind a value of its own: an initializer-less `var x;` has no value, so a WRITE is what would make it live, and a `@:build` macro that rewrites the whole statement list can supply one (Pony's `@:async` methods pre-declare `var err; var _;` ahead of an `@await`, and `com.dongxiguo.continuation` binds each bare declaration as a continuation step). Only the FIRST link of a re-declaration chain is reported per pass (an earlier declaration's own binder token reads as an occurrence of the middle one); `--fix` loops to a fixed point and clears the rest

## `unused-parameter`

a function parameter never referenced in its body — purely structural. `Warning` (with a delete `--fix`) for the autofixable subset — a named local function, or a confined private method (the same `isPrivateMemberConfined` proof `unused-private` uses) — whose call set can be proven complete WITHIN the file by the shared `RemoveParam.paramSlotEdits` core; `fix` removes the parameter AND its positional argument at every in-file call site (one parameter per function per pass, the rest follow as the fixed-point loop re-runs the proof). Everything else stays `Info` and is REPORT-ONLY by default: a public / unconfined method is a cross-file signature change the `remove-param` op performs with its own advisory. Setting `renameSilence` (an `apqlint.json` option on the rule, default **false**) adds the conservative `_<name>` silence-rename to the `Info` bucket — a decl-site-only, cross-file-safe edit skipped on a `_<name>` collision; it is opt-in because it only HIDES the finding (no dead weight removed, no behaviour changed), so a blanket `--fix` does not rewrite every unprovable signature. Skipped entirely: an `_`-prefixed name (the intentional-discard convention), a body-less interface / abstract method declaration, a method of a type carrying a supertype clause (`extends` / `implements`), whose signature may be a fixed contract — a local function and a method of a supertype-less type stay in scope — and a function CAPTURED AS A VALUE in the same file (its name referenced outside callee position: `addEventListener(E, onFoo)`, assigned to a var / field, returned, `.bind`-partialled, or reached through a COMPUTED callee such as `(cond ? f : g)(x)` — a merely parenthesised callee `(f)(x)` stays a direct call), whose signature is fixed by whatever consumes the reference, making the finding unactionable; the capture scan is by name and file-scoped, so it only ever drops a finding (never invents one) and a capture in ANOTHER file stays invisible

## `unused-private`

a `private` field / method never referenced — flagged only when the type is provably confined to its file (no subtype, `@:access`, `@:allow`, or skip-parse). A member the supertype chain declares is never flagged: an `abstract` / `override` member is carved out by its modifier, and the IMPLEMENTATION of an abstract member — which carries neither, because Haxe rejects `override` on one — by asking the widest index whether a supertype declares the name The fix's string gate (a name any string in scope spells is a possible `Reflect.field` target) is REACH-AWARE for a PRIVATE STATIC of a class (`StaticReflectionReach`): `Reflect.field` / `getProperty` / `fields` on an INSTANCE never expose a static (eval, js, hxcpp), so the string matters only when a CLASS VALUE of the owner, a subtype (eval and ES6 js expose an inherited static through it) or an alias can reach reflection — the class name in a value position, a `C.x()` naming no member of `C` (a `using` extension receiving the class), an unconsumed `Type.getClass` / `Type.typeof` (on `this`: the enclosing chain only; otherwise every class) or non-literal `Type.resolveClass`, a literal naming the class's path, or the js handles `constructor` / `__class__` / `$hxClasses`. A value handed straight to `Type.getClassName` / `createInstance` / `createEmptyInstance` / `Std.isOfType` is consumed. The scan reads the PROJECT half of the scope; a string spelled in a library, a macro-using file or a native-code carrier, an unparseable or `#if`-opaque project file keep the gate closed. A PROJECT macro module that obtains or reifies a class identity (`getLocalClass`, `getType`, `$p{`, `TPath`, …) keeps every type declared in a file naming it, and their subtypes; `getClass(this)` inside a macro module opens every class; `getDefinitionByName` / `getDefinition` with a non-literal name counts like `resolveClass`; a string naming a class source opens every class; a receiver-less `x.isOfType(v)` counts as consumed only under the file's own `using Std`. RESIDUAL: library code — a library build macro, or ANY library call returning a `Class` value — turning a project instance or a computed name into a class value and applying a name the project hands it by reflection. Instance members keep the plain string gate.

## `unused-public-member`

a PUBLIC METHOD of a class whose NAME occurs nowhere in report UNION resolution scope outside its own declaration — the public-facing sibling of `unused-private`, whose confinement proof stops at the file boundary. `Warning`, DEFAULT OFF (opt in via `apqlint.json` `"rules": { "unused-public-member": { "enabled": true } }`, or an explicit `--rule`), `--fix` DELETES the method with its modifier/metadata run and its leading doc comment, whole-line. The reference test is TWO complementary raw-text mechanisms: a global identifier-token count map built ONCE per run over every source in scope (the cost-bounded pre-filter — a per-candidate scan of a scope carrying the configured libraries would be quadratic), which must count the name EXACTLY as often as the member's own exclusion region does; then the authoritative confirm `SymbolIndex.nameOccursOutside` on the REPORT index, whose `referencedInRange` also sees the `\x24name` interpolation ESCAPE the plain tokenizer reads as one long token. The exclusion region is `docExtendedSpan(declGroupSpan(…))`, so the member's own doc comment and modifier run do not read as references to it. Raw text means the rule is conservative in the SAFE direction — a name that merely OCCURS in a comment, a string literal, a library, a `#if` branch, or as an unrelated same-named member elsewhere suppresses the finding, so a common name (`update`, `run`, `dispose`) is practically never reported and what survives is a name unique to its own declaration. Member gates (the modifier/metadata run is walked as `orphan-accessor` walks it, RESETTING at every member so a `public` or `@:keep` on a preceding FIELD never answers for the next method): no explicit `public` keyword (an unqualified Haxe member is private — `unused-private`'s), `override` (reached polymorphically), ANY `@:meta` in the run, a guarded one included — the region is descended into, so its metadata surfaces as an ordinary sibling, and a region that merely CARRIES a modifier out makes the run uncertain and skips the member instead — metadata makes a member implicitly reachable, the grammar's own `isImplicitlyReachable` rule, treated as a class rather than a `@:keep` whitelist that would leak by category, and the names the LANGUAGE calls with no written token: `new` / `main` / `toString`, the `for`-desugaring names `iterator` / `keyValueIterator` / `hasNext` / `next`, the `haxe.Serializer` pair `hxSerialize` / `hxUnserialize`, a dunder `__x__`, plus every `get_` / `set_` prefix, which is `orphan-accessor`'s territory and is skipped outright so the two rules can never claim one method. A member a FRAMEWORK reaches is skipped through the very predicate `unused-private` uses (`NamingSupport.frameworkReachable` — a utest `test*` method of a class transitively extending `Test`), so the two unused-* rules cannot disagree about one member. Class gates: `@:keep` / `@:build` / `extern` on the class, `SymbolIndex.transitivelyCarriesRtti`, an ANCESTOR carrying `@:autoBuild` (it generates into DESCENDANTS, so it is read walking the chain UPWARD), unresolvable anything → skip (unlike `orphan-accessor` there is no report-only third arm), and a supertype link that fails to RESOLVE. There is deliberately NO supertype / interface / subtype member query: the text scan SUBSUMES all three, since a same-named declaration anywhere in scope — above, beside or below the class — is itself an occurrence of the token. ANY REPORT file that skip-parses aborts the whole run: it could hold the only call. The RESOLUTION scope needs no such gate, because the token map is built from its RAW SOURCES (`SymbolIndexHost.resolutionFiles`), which a skip-parse does not withhold — reading them off the index instead would drop such a file from both `allFiles` and `sourceOf` and make a call inside it read as absent. The map is also a strict SUPERSET of the report set (unioned in by path), without which the `global == own` count comparison can hold by coincidence against library occurrences the report-scope confirm cannot see. **`RiskyFix`**: the reachability gate list is a NEGATIVE one (every entry is a shape somebody found leaking — the implicitly-called `iterator` / `hasNext` / `hxSerialize` family was exactly that) and the fix DELETES a public method, so the edits are applied only through the compiler oracle's typecheck-and-revert pipeline, and the rule is report-only where no `compilerOracle` is configured. The DELETE adds one gate of its own: no static `Literal` FRAGMENT of an INTERPOLATED string in report scope may be CONTAINED IN the name (`'do$suffix'` may name it at runtime; fragments under 4 characters carry no intent and would veto every deletion). A reflection literal carrying the WHOLE name needs none — its content is raw source text, so the reference test already refuses to REPORT the member, a strictly stronger outcome than `orphan-accessor`'s. The honest gap is a name no single literal spells: `Reflect.field(t, 'zqxwvDo' + 'Thing')` defeats both mechanisms and both gates and breaks SILENTLY at runtime; asking containment the other way round for every whole literal would veto far too much, so `RiskyFix` is the answer. Scope is class bodies (`class` / `final class` / `abstract class`); an interface declares a contract, an abstract's members reach the underlying type by rules the index does not model. Registered in the `--fix` loop's full-scope set: every gate is whole-project, so on an active SUBSET a call site in an unchanged file reads as absent — run it whole-project, a subdirectory run is a preview, not a verdict A method written inside a member-position `#if … #end` is scanned too, branch by branch (the grammar emits one node with every branch's members flattened; boundaries are recovered from the directive text, as `member-order` and `missing-visibility` do) — a call in ANY branch still counts as a reference, since the token scan reads whole files, and a method whose `public` only SOME builds see is skipped rather than judged. Its deletion carries the doc / modifier run from inside the region, and is withheld when it — together with the pass's other deletions in the same class — would take a region's member count to zero (an emptied region is a shape the grammar does not model, and the rejected splice would drop every other edit the pass had for that file). The reference test, the type gates and the member-run reading live in `PublicReach`, which `naming`'s privatize arm asks too; the deletion keeps the `@:autoBuild`-ancestor veto (`chainOutOfReach(…, autoBuildCounts: true)`) the privatize arm waives.

## `unused-return-value`

a call whose provably non-Void result is discarded in statement position — a possibly-lost value.
