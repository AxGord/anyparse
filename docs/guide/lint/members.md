# `members` rules

Fields, accessors, modifiers, visibility, member order, signatures. One section per rule, by id; each rule's language, default and fix marker are in the [rule index](../../lint-rules.md#members), and a suite test fails when a registered rule has no section here or a section names no rule of this category.

## `default-repeated-argument`

a parameter with NO default that at least two call sites hand the same `static inline` constant — the default the signature never declared; `Info`, `--fix` writes `= <constant>` onto the parameter and drops the argument at every agreeing site, atomically across files. Sites passing something else keep their explicit argument, which is what makes the rewrite meaning-preserving. Default OFF. The constant must be a REFERENCE to a `static inline` member, never a literal: Haxe rejects a plain `static final` as a default (`Default argument value should be constant`), and an `inline` one whose initializer is not a LITERAL (a string concatenation or an interpolation `inline` folds, which a default refuses), and a repeated literal is `magic-number`'s finding first. Visibility is judged from the DECLARATION — a bare constant is the caller's own member and is accepted only when caller and callee share a type. The callee must resolve to a declaration IN SCOPE (a bare name, `Type.member`, or `receiver.member` through the receiver's declared type), the parameter must be trailing or followed only by defaulted ones, a site counts only when the constant is its LAST argument and sits inside the leading run of required parameters (Haxe binds by position: cutting `K.T` out of `d(K.T, 1)` leaves `d(1)`, which compiles and hands `1` to the wrong parameter, and past an optional parameter a slot may have been skipped by type) — so a call passing later arguments keeps all of its own, and a later `--fix` pass that defaults an earlier parameter judges every call against the signature the previous pass left, the function must be referenced nowhere as a VALUE (adding a default makes `(Int) -> T` into `(?Int) -> T`, which does not unify), and a member name declared by more than one type is refused — a default on an implementation leaves the interface's signature alone

## `field-init-at-declaration`

an instance field with no declaration initializer assigned exactly once in the constructor — as an unconditional top-level `x = expr;` / `this.x = expr;` — whose `expr` is context-free (no ctor params or locals, no `this`, no instance members, no static of the SAME class; literals, FOREIGN statics/globals and `new T()` constructions qualify, `new T(param)` does not): the user's rule is to initialize at the declaration site when the value does not depend on the constructor; `Info`, `--fix` moves `= expr` onto the declaration and deletes the ctor statement (decl-inits run BEFORE the ctor body; the reference gate makes the move order-safe, and a field READ in the ctor before its assignment rejects the candidate). An init hoisted across an explicit `super(...)` (the prologue runs BEFORE the base constructor) is refused unless every EARLY-INIT NARROWING holds: the RHS is an INERT COLLECTION (an array / map / object literal of inert elements — never a bare scalar or string, since a `null` String answers `length` on hxcpp instead of faulting, and never a call, `new`, identifier or `null`); the declared type is absent, an anonymous structure, `Dynamic`, or an unqualified core array / map the file does not shadow (an import or alias of that name, any wildcard import, an own / same-package / root-package declaration of it — decided by the resolution index; an abstract or class refuses); the write is the SOLE one; the field is not public and its type not public-by-default; the project's declared `resolutionRoots` matched at least one `.hx` (a root matching nothing reads as undeclared); and every occurrence of the field name across that project scope that may denote the field — a subclass in another file included — is the receiver of `.member` / `[i]` or a callee, OUTSIDE any `try` body, a lambda or local function written inside one included, where an early `null` faults. An `==` / `??` / `?.` / argument / `return` / assignment-RHS / literal-element / interpolation occurrence, a reflective string spelling the name, or an unparseable scope file mentioning it refuses. This is NOT a proof: RESIDUAL — the fault can still be caught further out (a caller of the reader, or library code between the base constructor and the reader), and a program relying on that catch changes behaviour; a library reading the field through `Dynamic` is outside the scope; a project consumed as a library exposes even a private field to downstream subclasses; and `resolutionRoots` covering only part of the project (a subclass under a directory no root names) leave that part unscanned, so a narrow lint can disagree with a whole-project one. The chain path never crosses. A crossing those narrowings refuse — a `new T()`, a call — is PROVEN instead, on the sole-write path only, where the run declares its builds complete (`reachConfigurationsComplete`) and the compiler facts are the truth: the field is not public; no code the hoist crosses (every constructor statement before the init, `super(...)` and the base-constructor chain, the overrides it dispatches to, every function value it hands out — a listener a later prefix statement fires — into library code) can READ the field (`MemberReach.mayReach` `Proven`); and the right-hand side COMMUTES with it — everything it runs writes only the `this` of a constructor or field initializer it entered (objects it allocated), reads no structure or dynamic field, calls no stateful library member (`ExecutionShape.statefulLibraryCalls`: `Math.random`, `Std.random`, `StringBuf.add`), every body read through the facts (`MemberReach.freshOnlyReads`), and no member of shared state it reads may be written (a string / number / boolean) or mutated (anything else) by the crossed code. The class's own field initializers are part of both walks (the graph wires them to the constructor as a site-less call), so a prologue write the right-hand side could observe refuses. Any `Unknown` refuses; without the truth nothing changes. Coarse by design: a method's `this` is never fresh, nor is an object stored in a field and then changed through it, so a UI constructor (openfl's `DisplayObject` bumps the static `__instanceCount`) still refuses. RESIDUAL: an exception or non-termination in the right-hand side now pre-empts the crossed code's effects; an init whose file the same `--fix` run already rewrote waits for the next run (its facts are stale). Gates: single-`new` classes only, statics and properties excluded, no unresolved write to the field NAME, and cross-file `FieldWriteIndex.writeCount == 1` — OR, when the cross-file write count DIFFERS FROM ONE (the `dispose()` null-out shape), the ACCEPTED-CANDIDATE CHAIN: every top-level ctor statement before the init must itself be the init of another accepted candidate of the same ctor (an empty prefix is trivially chained). Anything else in the prefix — a leading call statement, `super(...)`, a local `var`, a branch or loop, a write to a static / property / inherited / already-decl-initialized field — breaks the chain. Declaration order is NOT constrained. The chain does NOT claim the prefix runs no foreign code (`new T()` is context-free and allocates); it rests on two pillars: (1) no prefix RHS can leak `this`, so the field's other writer is unreachable in the window the move opens, and (2) moved inits all land in the ctor prologue in whatever sequence the compiler emits, so the gate is permutation-proof rather than order-restoring — a RHS must resolve NOTHING in-class, and that is demanded of the CANDIDATE, hence of BOTH acceptance paths (the sole-write path's earlier permissive spelling was a live regression: an init reading `ns[0]` from a `static final` array the ctor had yet to fill moved ahead of the statement that filled it), plus — for a chained candidate only — of any field that ALREADY carries a decl initializer. Read that as the strong form it is: not "no init reads a member another assigns" (Haxe forbids that anyway, which would make the gate vacuous) but NO init in that prologue directly reads in-class state at all, hence none can observe an in-class static that another one's FOREIGN CODE writes — which is why `_a:Int = s` beside a chained `_b = new Bar()` is refused though neither mentions the other. Covering the existing decl inits is also what makes `--fix` safe at a FIXPOINT: a candidate one pass refuses cannot be unblocked by the co-mover that pass moved out. A `#if` member REGION anywhere in the container refuses every CHAINED candidate (the chain's order proof needs one build's member sequence and a region's branches are several; the sole-write path still applies, and the region's own members are scanned; an `#if` inside an initializer EXPRESSION is a real node and is walked normally). `--fix` additionally skips a violation whose ctor prefix holds a candidate-shaped init that is not itself in the violation list (a `// noqa` must freeze the whole run), reporting each skip once per field on stderr. Known gaps — the gate decides what a RHS READS, never what the code it invokes DOES: foreign code reached from a moved RHS may mutate any state (external global or in-class static) and that mutation reorders with the move; a moved RHS and any other init sharing the prologue (another moved one, or a pre-existing decl initializer) can communicate through such state and still swap; and the SOLE-WRITE path still reorders against arbitrary EARLIER CTOR STATEMENTS, though only through effects the gate cannot see — `new() { s = 5; _a = s; }` and `new() { _b = bump(); _a = n; }` are now refused outright (each RHS resolves an in-class name), while `new() { Foreign.arm(); _a = Foreign.read(); }` still fires and still breaks. The in-class veto is deliberately coarse, and the tempting relaxation is WRONG: `static final` fixes the BINDING, not the VALUE — `static final ns:Array<Int> = []` is what the live regression read from. Only an `inline` static, or a `final` one whose initializer is a scalar literal, could be exempted. Over real libraries the coarse form costs almost nothing, and the sites it does refuse are correct refusals (`__contextID = __lastContextID++`, `useWorker = ENABLE` on a `public static var`), so it stays unmade. Emission order is an observation, not a contract (reverse of declaration order on `--interp` and `js`, hxcpp unmeasured) and nothing above depends on the direction. Chains with `prefer-final-field` through the `--fix` fixed point: the moved initializer makes the decl-assigned case flag `var` → `final` A field written inside a member-position `#if … #end` is scanned too, and its init moves to the declaration inside the branch; the static-member, sole-constructor and fix-side field lookups all descend into the region with it. A field name declared in TWO mutually exclusive branches is refused outright — the rival declarations share one constructor statement, only one of them is the binding it resolves to, and the move deletes that statement for both.

## `field-init-in-constructor`

A private instance field whose constant default is overwritten by exactly one CONDITIONAL write
in the constructor. The two spellings of its value fold into one unconditional assignment of a
conditional value, which leaves the field with a single write — after which `prefer-final-field` can
make it `final`. The mirror of `field-init-at-declaration`. `Info`, DEFAULT OFF: the fold trades a
declaration default for a constructor ternary, which not every project prefers; opt in with
`"field-init-in-constructor": { "enabled": true }`.

The fold emits a ternary rather than an `else` branch on purpose: Haxe does not check that a
`final` field is assigned on every constructor path, so one assignment that always runs is the only
form whose completeness the code itself proves. Refused for public and static fields, a field written
anywhere else, an `if` with an `else` or a side-effecting condition, an early exit or `super()` before
the `if`, a `#if` region on the path, and a comment the rewrite would drop.

```haxe
private var cells:Int = 20;
public function new(?palette:Array<Int>) {
	if (palette != null) cells = palette.length;
}
// --fix: private var cells:Int;   …   cells = palette != null ? palette.length : 20;
```

## `inline-constant`

A `static final` of a scalar type (`Int`, `Float`, `Bool`) whose initializer is a compile-time
constant, missing the `inline` that folds it into an immediate at every use. Also a `static inline
var` constant, which can be `final` with no other change. `Info`; `--fix` inserts `inline` (or swaps
`var` for `final`) and keeps the type annotation, so a `Float` constant written `5` stays `Float`.

The initializer is a literal, a negated number, or a bare reference to another `static inline`
constant of a literal (a chain converges over successive `--fix` passes). `String` is not inlined:
on hxcpp an inlined string is copied at every use. Inlining erases the runtime field, so a constant
is skipped when its name appears in any string literal in scope (a possible `Reflect.field`), when it
or its class is `@:keep` / `@:rtti`, when its class has a build macro, and — for a `public` one —
when its class is mentioned in macro code or carries `@:nativeGen`.

```haxe
static final MAX_DEPTH:Int = 32;   // --fix: static inline final MAX_DEPTH:Int = 32;
```

## `member-order`

a type whose members are not in the canonical declaration order; `Info`, `--fix` reorders them. The order: constants (static fields, public then private; not sub-split by property-ness), instance fields (public read-only properties `(default, null/never)`, public getter properties `(get, …)`/`(dynamic, …)`, public final, public var, then the same private quartet — property classification via `TypeInfoProvider.propertyAccessors`, so a grammar without the provider keeps the plain final/var split), constructor, property accessors (`get_*`/`set_*`), instance methods (public then private), static methods (public then private). Within one rank plain unconditional members carry a sub-order: `inline` members lead, then fields WITH a declaration-site initializer lead init-less ones; the accessor rank is exempt, so a get/set pair keeps its adjacency. Rank groups must be separated by EXACTLY one blank line; same-rank FIELDS are unseparated; same-rank METHODS keep their blank separators untouched. Wherever the WRITER forces a member gap under the file's own `hxformat.json`, its answer wins, read through ONE policy the writer itself calls (`anyparse.format.MemberGap`, reached by the check through `GrammarPlugin.memberGapPolicy`): a doc-commented member is set off as `afterFieldsWithDocComments` / `beforeDocCommentEmptyLines` say (`one` by default — so `private var a; /** doc */ private var b; private var c;` on their own lines is REPORTED, `a doc-commented member is not separated from its neighbour by one blank line, as the formatter writes it`, and the fix lands both blanks; `none` removes the blank, `ignore` leaves the slot to the source), and under `aroundMultilineFields: N` a field the writer renders over several lines is set off by N blank lines instead of being glued into its tight group (a blank there was a finding the fix could never clear: the canonical round-trip put it back). Only unconditional pairs: the members of an `#if` body are written with their source gaps. A slot led by a line or block (non-doc) comment is left to the source, as the writer leaves it. The opt-in `separateInlineSubgroup` option (`"rules": { "member-order": { "separateInlineSubgroup": true } }`, default OFF, so a project that does not set it lints byte-identically) carves a rank's tight field group in two: an `inline` field and a non-`inline` field of the same rank, both unconditional and neither comment-led, want EXACTLY one blank line between them instead of none (`private static inline final A = 9;` / blank / `private static final B = 'x';`), reported as `the inline members of a rank group are not separated from the rest of it by a blank line` and inserted (or collapsed to one) by both fix arms — the reorder rebuild and the spacing-only fallback. It is spacing only: no rank, sub-order or content-ranking gate reads it, the inline subgroup and the rest each stay tight, a comment-led slot keeps its exemption, members inside one `#if` block (which carry no inline-leads sub-order) are untouched, and methods keep their separators. The report path and the fix path resolve it from the same file, so they cannot disagree about the gap. The autofix rebuilds the member region with normalized blanks; when non-whitespace sits between member slots (a stray `;` — `EmptySemiMember` is not a collected member) it falls back to plain slot swaps and the spacing check is disabled for that container, so every reported violation stays fixable. The sibling of `modifier-order` one level up — that orders one member's keywords, this orders one type's members (the same slot-permutation). Reordering METHODS is always safe; reordering FIELDS can change init order, so the autofix BAILS a container (report-only) when the canonical sort would change the relative order of any side-effecting field initializer, or move a field before a sibling it reads — in both bails counting only INITIALIZED, non-`inline` partners: an init-less field runs no code in the init phase, and an `inline` field's initializer is a language-mandated constant folded at compile time, so crossing either is unobservable — but only among fields of the SAME init phase (static fields init at class-load, instance fields in the constructor, so a static const reorders freely past instance fields). Pure literal consts (even many at one rank) reorder freely under the stable sort. Members guarded by `#if` conditional-compilation blocks reorder too: each member is collected with the condition it is declared under (nested `#if` conditions conjoin, an identical conjunct deduping), and the autofix regroups the sorted members under regenerated `#if … #end` directives, coalescing every member of one condition into a SINGLE block per section (a condition guarding both fields and methods therefore yields two independent blocks, each ranked on its own). Such a block moves as ONE atomic unit but sorts by its CONTENT: when every member of the block carries the same rank, the block sorts AT that rank among the plain members of its section (trailing them within the rank — crossing a rank boundary is the point, position inside one rank is not), so a guarded `public var` no longer trails the private instance fields it outranks. Content ranking is gated three ways and any doubt PINS the block back to the section END (conditional fields right before the constructor, conditional methods at the bottom of the methods section, first-occurrence order between blocks, each internally rank-sorted — the pre-existing placement): (1) all members of the block must share ONE rank — a mixed-rank block would have to be split, and atomicity beats ordering; (2) every byte of the conditional construct must be covered by a member slot, an absorbed lead doc, a REGENERABLE directive line or whitespace, and the `#end` line must end there — anything else (a stray `;` — `EmptySemiMember` is not a collected member; opaque region text; a note the rebuild cannot regenerate, on a directive line like `#if X // why` or after the `#end`) would be dropped, duplicated or re-attached to the wrong member by the rebuild, so it pins the block AND bails the whole container's reorder to the spacing-only fallback; (3) no field initializer may tie the block to its position, in EITHER direction — a field IN the block whose initializer has a side effect (call / allocation / assignment) or reads another field of the container, or a field OUTSIDE it whose initializer reads one inside — deliberately independent of the `movableArglessNew` option, since the report path reads no ORDER option (its one option, `separateInlineSubgroup`, is spacing only) and an option-dependent rank would make report and fix disagree. A gate on position-sensitive constructs in the `#if` CONDITION itself is a documented no-op for this grammar (a Haxe conditional-compilation condition is a pure compile-time define expression evaluated before parsing). One residual report-only case is specific to content ranking: a moved block that would flip with a same-phase side-effecting UNCONDITIONAL initializer is flagged and then bails to spacing-only. Demoting the block and re-sorting would close it, but the sole trigger is the one bail `movableArglessNew` relaxes, so a retry would reintroduce exactly the report/fix option disagreement the config-independent gates exist to prevent — and the finding is the same advisory shape a plain unsafe container already produces. A doc comment written before a member's `#if` travels with it inside the regenerated block. A blank line is required BEFORE a member-level `#if` and AFTER its `#end` (a directive gluing to `public function new(` masked the fields→ctor group boundary before). A BRANCHED construct (`#if` / `#elseif` / `#else` / `#end`) moves as one unit too: the parse tree flattens every branch into a single node, so the branch each member was declared in is recovered from the construct's own directive lines and becomes part of its sort key — branch before rank, so the branches keep source order and each sorts internally, and the directives are regenerated rather than dropped. Two constructs merge into one block only when their whole branch shape matches, and a doc written above a branched `#if` stays above the regenerated `#if` (it describes every branch, not just the first). It still bails — report-only — on an `#else` shape the branch model refuses: a nested conditional inside a branch, a construct whose members span two sections, one whose first branch is empty, or an orphan comment stranded in a directive gap. The REPORT also resets its rank comparison when crossing an `#else`/`#elseif` — an alternative branch is a sibling sequence, not a successor, so a container whose every branch is itself canonical is not flagged

## `missing-visibility`

a class / abstract member declared without an explicit `public` or `private` modifier; `Warning`. Interface members (implicitly public) and enum-abstract values are exempt. Haxe defaults an unmodified member to `private`, so the omission is not a bug — but stating visibility on every member is a documented project rule. Members written inside a member-position `#if … #else … #end` are scanned too, branch by branch (the grammar emits one node with every branch's members flattened; boundaries are recovered from the directive text, as `member-order` does), and a region holding nothing but a visibility keyword is treated as a modifier for the member after `#end`, not as a region of its own — which also means a keyword reaching into a branch EXEMPTS its member rather than proving it public. A `#if` splitting a member's own signature rather than listing whole members parses as a straddling `CondSplice*` form and stays uncovered. `--fix` inserts `private` (the Haxe default, so a behaviour-preserving change) at the canonical position, after any `override` / meta and before `static` / `inline` — inside the member's own branch when it is `#if`-guarded; an `override` member instead gets the overridden member's own keyword, resolved through the SymbolIndex supertype closure (unresolvable — unindexed / colliding / unmarked base — stays report-only). An **`extern` class is not reported at all**: its unmodified members are already `public`, so `private` would break every caller and `public` is noise on a bodyless foreign-API declaration — the finding could only be "fixed" wrongly. A `@:publicFields` class IS reported (an ordinary class where `private` on one member is a real opt-out) but skipped by `--fix`, which would otherwise lower visibility

## `modifier-order`

a member whose modifier keywords are not in the canonical order `override` → `public` / `private` → `static` → `inline` → `final`; `Info`, `--fix` reorders the run (each ranked keyword moves to its slot; unranked modifiers stay in place). A method's `final` (the grammar folds it into the `final function` wrapper rather than a sibling node) ranks last, so `final` before any other modifier is flagged; a field's `final` is the storage keyword, not a modifier, and is never ranked. Purely cosmetic — the order carries no meaning to the compiler. Modifiers with no documented order (`extern`, `dynamic`, `macro`, …) are ignored. A project `checkstyle.json` `ModifierOrder.modifiers` overrides the canonical order (mapped to the ranked kinds; `PUBLIC_PRIVATE` expands to public/private, `FINAL` to final, unranked tokens dropped)

## `optional-param-shorthand`

a function parameter written `name:Null<T> = null` or `name:T = null` — a nullable-or-plain type with a `null` default — that the `?` optional-parameter shorthand `?name:T` replaces, and an already-`?` parameter carrying a redundant `null` default (`?name:T = null`) (the user's rule: prefer `?style:ScrollBarStyle` over `style:Null<ScrollBarStyle> = null`, and — since a `null`-defaulted plain-type parameter types identically — `?position:Point` over `position:Point = null`); `Info`, `--fix` rewrites it — unwrapping ONE `Null<>` layer when present (else keeping the type as-is), dropping the ` = null`, and prepending `?`; on an already-`?` parameter the type stays verbatim (no unwrap — `?x:Null<T> = null` fixes to `?x:Null<T>`) and only the ` = null` goes. The forms are equivalent for a nullable-defaulted parameter (a live compiler probe: `$type` gives `(?p:Null<T>) -> Void` for BOTH `p:Int = null` and `?p:Int`, and the `haxe.PosInfos` call-site auto-fill magic fires in both forms; an omitted `?x:T` argument already yields `null`, so its explicit `= null` default changes nothing), so no call site changes. Grammar-agnostic over `RefShape.paramKinds`; the parameter's last child (the default) must be exactly the `null` literal, and the type text between the name's `:` and the default's `=` is — for a required parameter — either a single balanced `Null<...>` (nested `<>` and a function-type `->` balanced correctly, the matching `>` at the type's end) or any other non-empty type text that does not itself open as a `Null<` wrapper, and — for an already-`?` parameter — any non-empty type text, kept verbatim. Covers class methods, constructors, and local functions. Deliberate misses: `name:Null<T> = <non-null default>` (different semantics), an already-`?` parameter WITHOUT a `null` default (`?x:T` / `?x:Null<T>` — the nested-unwrap fix itself lands at `?x:Null<T>`, which the one-layer rule leaves as-is), a `Null<T>` with no default, an untyped `name = null` / `?name = null` (no type text to carry the rewrite), and a `Null<`-prefixed type text the unwrapper rejects (decorated — e.g. a comment between the type and the `=` — or malformed; coercing it into the bare-type arm would prepend `?` without unwrapping). The whole parameter span is replaced, so commas, parentheses, and sibling parameters stay intact. TWO further arms drop a `?` that a default already makes redundant: `?name:T = <non-null default>` becomes `name:T = <non-null default>`, and `?name:T` whose EVERY read in its function is `name ?? <compile-time constant>` becomes `name:T = <constant>` with each `??` collapsed to a bare `name` (Haxe compiles a signature default into `if (name == null) name = CONST;`, so the two spellings are the same program and no call site changes). Both make the same signature change (`(?p : Null<T>)` -> `(?p : T)`) and share gates G1-G5: a body-less declaration, an `override`, a supertype clause on the enclosing type unless the function is the constructor or `static`, and any instance method that is not provably un-overridable are all refused. The hoist arm adds four of its own: the default must be a value Haxe accepts in a signature (a literal, a negated numeric literal, a `static inline` field, or an enum-abstract value, the last two proven through the cross-file `SymbolIndex` — a non-inline `static final` is `Default argument value should be constant`), every occurrence of the name inside the enclosing function must be the declaration or one of the collected `??` left operands (a textual completeness scan; the hoist removes `null` from the parameter's value range, so any other read dies silently), all the fallbacks must spell the SAME constant, and the declared type is the annotation with one `Null<>` layer removed — a text still nullable after that unwrap is refused

## `orphan-accessor`

a `get_X` / `set_X` method that no property slot ever reaches — the accessor half of a property whose declaration was changed to `(default, set)` / a plain field, or removed, while the method stayed behind. Haxe calls an accessor only because the property's `(get, …)` / `(…, set)` clause names it, so with the slot gone the body is dead weight that still reads like live behaviour. `Warning`, DEFAULT OFF (opt in via `apqlint.json` `"rules": { "orphan-accessor": { "enabled": true } }`, or an explicit `--rule`), `--fix` DELETES the method with its modifier/metadata run and its leading doc comment. The property is resolved through the WHOLE inheritance chain — the class, then its `extends` superclass and every `implements` interface, transitively — and a slot counts as declared when the accessor ident is anything but `default`/`null`/`never`, so `dynamic` declares it (`MemberInfo.hasGetter`/`hasSetter`, populated only where the plugin supplies a `TypeInfoProvider`, so the rule is meaningful only where accessors are reported). An `override` accessor needs no property redeclaration in the subclass. Statics and instance members are separate namespaces, so a candidate matches only a member of its own staticness; its staticness and its `@:keep` come from the modifier/metadata run, which resets at every MEMBER and is read per conditional BRANCH (a `static` only some builds see would stop an instance accessor pairing, so a run the branches disagree on refuses the member) (a `static` on a preceding FIELD is that field's). Haxe resolves an accessor UPWARD from the property, so a property declared by a SUBTYPE is legitimately served by a method inherited from here — checked via `SymbolIndex.subtypeDeclaresMember` on the found-nothing arm only, since an `X` found at or above the class forbids a subtype redeclaring the field; that query walks from the subtype DECLARATION and treats an ambiguous supertype link as a MAY, because here `true` means leave the method alone. Three arms: (1) `X` IS declared in the chain but WITHOUT the slot — proven orphan, and proven even under an unresolvable supertype, since Haxe forbids redeclaring an inherited field so a second `X` cannot hide behind it; (2) no `X` anywhere in or below the chain AND every supertype link resolved — proven orphan; (3) no `X` but a supertype did not resolve — `Info`, report-only, never fixed. Two macro shapes take the class out of scope: `@:build` on the class itself, and `@:autoBuild` on ANY ancestor (that one generates into DESCENDANTS, not its carrier, so it is read while walking the chain — the canonical `@:autoBuild interface` + `implements` idiom). A supertype link the name binding (`TypeNameBinding`, the compiler's order, parent packages included) does not pin to one indexed declaration is still walked when its simple name has exactly one project-wide declaration, but SPECULATIVELY: it may prove a slot EXISTS, never that the property is declared without one, and the link stays counted unresolved, so such a chain is never deleted from. The DELETE adds four gates: no report file skip-parses; neither the class nor the member is `@:keep`; the method name has ZERO direct call or value references in report scope (no `IdentExpr`/`FieldAccess`/string-interpolation ident carries it); and no string literal there names it — an INTERPOLATED string is matched the other way round, its static `Literal` fragments collected and a fragment CONTAINED IN the name blocking the delete (`'get_$suffix'` may name it at runtime; fragments shorter than an accessor prefix are ignored). That zero-reference gate is NOT the orphan test — a REAL accessor is invoked through property access and shows zero textual calls too, which is exactly why the orphan test is the property-slot absence; it only catches a `get_X` that is also called by hand. REPORT SCOPE bounds every scan here, so a subdirectory run narrows both halves: `--fix` can delete a method the rest of the project calls, and a REPORT can raise a `Warning` on an accessor whose property a subtype outside the scope declares — run it whole-project. Scope is class bodies (`class` / `final class` / `abstract class`): an `interface` declares no accessor bodies, and an `abstract` type's accessors are left alone. Registered in the `--fix` loop's full-scope set, since the chain resolution, the subtype query and the reference scans all mis-answer on an active subset An accessor written inside a member-position `#if … #end` is scanned too, branch by branch; the property slot is resolved through the SymbolIndex, which collects every branch's members at once, so a slot in ANY branch pairs and the accessor stays unreported. Its deletion carries the doc / modifier run from inside the region, and is withheld when it — together with the pass's other deletions in the same class — would take a region's member count to zero (an emptied region is a shape the grammar does not model, and the rejected splice would drop every other edit the pass had for that file).

## `overridden-inline`

an `inline` instance method a subtype `override`s, and that override — reported at both ends. The compiler rejects the pair (`Field m is inlined and cannot be overridden`) only in a build that compiles the override, so a superclass named in one `#if` branch of an `extends` clause (`class C #if a extends A #elseif b extends B #end`) leaves the error for whoever builds that branch. Every branch is a superclass in some build (`SubtypeGraph.overriddenDeclarations`), and an override binds to the NEAREST declaration on each path, so overriding a plain override of an inline method is clean. Asked of the resolution index, so an override outside the report still flags the inline method the report holds. `Error`; `--fix` drops the `inline` modifier at the inline end (what every call computes is unchanged, only the inlining is lost); an extern's inline method is reported only

## `prefer-access-meta`

an expression that waives every privacy check inside it — Haxe `@:privateAccess expr` — where the rule is to name the type whose private members the code reads, with `@:access(T)` on the member that reads them. `Info`, DEFAULT OFF; the fix is RISKY (it stands only where the compiler oracle accepts the edit). `--fix` drops the waiver and adds, on the enclosing member, one `@:access(<package>.<Type>)` per type declaring a private member the expression reads: each member access through a receiver the operand binder types (`OperandBinder.receiverDecls`), each construction through its constructor, the member found where its type declares or inherits it, privacy read as the compiler does (written `public`, or an extern or interface member with no visibility, needs none). The enclosing type's own members need no grant, and a grant the member or its type already carries is not repeated. A receiver the binder cannot type, a member it cannot find, a waiver outside any member or a comment between the waiver and its expression keeps the waiver, reported with the reason.

## `prefer-enum-abstract`

two arms over the same advice, both `Info`. **Whole-type arm**: a type whose ENTIRE body is three or more `static inline final` members of ONE primitive type, every value a distinct literal, and nothing else — no method, no constructor, no supertype clause, no mutable or instance field. Such a type IS the enumeration already, and its members are read from other files, so no in-file use is required as evidence; the finding names the type (`consider enum abstract HorizontalAlignment(String)`). The gate is a positive whitelist over the container's children (modifier | metadata annotation | qualifying constant), so a method, a constructor, an `extends` / `implements` clause and an `abstract`'s underlying-type node all refuse without a per-shape exclusion list. Left alone: a non-`inline` member (storage, not a compile-time substituted value — and a non-`inline` constant bag is far more often a namespace of unrelated knobs), a non-literal value, two primitive types in one body, two members on the SAME value (aliases), fewer than three members. **Prefix arm** (for constants living inside a type that has other members): three or more `static [inline] final <PREFIX>_*` numeric constants that share a name prefix (`RANK_ACCESSOR` / `RANK_CONSTRUCTOR` → `RANK`) **and are used interchangeably** — they read as a closed enumeration but carry no distinct type, so any `Int` flows where one is meant. The prefix alone is not enough: a domain namespace of independent tuning knobs (`FUZZY_MAX_DIST`, `FUZZY_TOP_K`, …) shares a prefix yet each is its own magnitude, only ever a comparison operand, never an alternative to a sibling. A group is flagged only when two or more of its members appear as a **result value** feeding one sink — a `return` of one function, or an assignment to one lvalue — reached through result-preserving containers (parentheses, ternary branches, switch / case values) but never as an operand of a comparison / arithmetic / call. One finding per prefix group; a container the whole-type arm flagged is not re-examined, since that finding already names every constant the type declares. Left alone by both arms: an existing enum abstract, a mutable `static var`, an instance `final`. **The whole-type arm has an autofix; the prefix arm does not** — its constants live inside a type with other members, so converting them means SYNTHESISING a type that does not exist yet, naming it and rewriting every reference, which is a different operation from rewriting a declaration in place. The fix is SINGLE-FILE and stays that way: it rewrites the head to the grammar's enum-abstract spelling (`RefShape.enumAbstractSyntax`, Haxe `enum abstract Name(U) to U`) and strips from each constant the modifiers and the `:U` annotation an enum-abstract value may not carry (`static` would make it a private static field instead of a value; `:U` would type it as `U` instead of the abstract). Member order, doc comments, per-member metadata and blank lines all survive, because the edits are one head replacement plus two deletions per member and nothing else. **The `to <underlying>` clause is always emitted, and that is the whole reason no other file is touched**: an `enum abstract T(U)` does not implicitly convert to `U`, so without it every reference that flowed into a `U`-typed slot stops compiling — converting one type without the clause breaks references across many files, while WITH it every convertible type of a real application converts with no annotation and no call site changed, and the project typechecks unaltered. Only a `from` clause would let a bare `U` back in and dissolve the distinct type; `to` costs nothing the conversion is for, and exhaustive `switch` — the payoff, which turns a missing branch from a runtime `case _: throw` into a compile error — is unaffected. `RiskyFix` + `GroupedFix`, because `to U` is not a proof: a member bound to an INFERRED local and then used as a `U` (`var a = T.CENTER; a.toUpperCase()`) and a collection whose element type is inferred from the members (`[T.A, T.B].indexOf(u)`) both stop compiling, and neither is decidable without real inference — so every conversion is typechecked project-wide and the one edited file reverts to report-only when any call site anywhere breaks, and the rule stays report-only wholesale where no `compilerOracle` is configured. The grouping is not a nicety: measured before it existed, the verifier's per-edit bisect found a COMPILING subset of a failing conversion — an `enum abstract` still carrying `public static inline final A = 'a'`, which is a plain static field on the abstract and no longer a value of the enumeration, indistinguishable from success to anything that only asks whether the tree builds. STRUCTURAL REFUSALS cover the one thing the oracle cannot see. An `enum abstract` ERASES to its underlying type, so every VALUE behaves identically at runtime and the only observable change is that the TYPE stops existing as a runtime class — measured: `haxe.rtti.Rtti.getRtti(A)` reads three statics off the `@:rtti class`, and the same call against the converted type does not compile at all (`Cannot use abstract as value`). So the fix refuses a container carrying ANY metadata (whether `@:rtti` / `@:keep` / `@:build` behaviour survives the change of declaration kind is not knowable from the annotation's name), a type whose NAME occurs as a plain string literal anywhere in scope (`Type.resolveClass('Name')` — the same proof `static-constant` uses, narrowed by a raw-text pre-filter to the files that even mention a candidate), and one the index reports a subtype or a transitive `@:rtti` hierarchy for. Two more refusals are about what the head template would silently DROP, neither of which projects as a tree child: a multi-word declaration keyword (`abstract class`), and anything between the type name and the body opener — type parameters above all, `class Generic<T>` being indistinguishable from `class Plain` in the AST. The plan is built in `run`, where the whole-file set is in hand, and `fix` without a preceding `run` yields nothing: fail-closed, so a conversion whose whole-project refusals were never evaluated cannot be applied

## `prefer-final-class`

a class declaration carrying the `@:final` metadata tag — the user's rule: use `final class`, not the `@:final` meta, for a class not designed for inheritance; `Info`, `--fix` removes the `@:final` meta and inserts the `final` modifier before the `class` keyword, and for a redundant `@:final final class` removes the meta only. Grammar-agnostic over `RefShape.finalClassMetaName` / `plainClassDeclKind` / `finalClassDeclKind` plus `MetaShape.metaKinds`. The decorated declaration is the meta's nearest following sibling that is not itself a meta, resolved by SOURCE order (span, so child-array order and an intervening meta / doc comment do not mislead); the finding spans only the `@:final` token (not the class body, so a `// noqa` inside cannot swallow it). The fix removes the meta and its trailing whitespace back to the next non-whitespace char (no blank residue) as ONE combined `[meta, keyword)` replacement when only whitespace separates them, else two disjoint edits so a doc comment or another meta sitting between the meta and the class is preserved. Deliberate misses: `@:final` on an interface / enum / enum abstract / typedef / `abstract class` (none is a class the `final` modifier applies to — `final abstract class` is not valid Haxe), and `@:final` on a method or field (its decorated decl is a member, not a class); a plain `final class` with no meta is already idiomatic. Multi-meta order variants (`@:final @:keep class` / `@:keep @:final class`) fix cleanly, keeping the other metas

## `prefer-final-field`

RESIDUAL: a finality-branching builder whose module is not in the index.

## `prefer-inline`

a method whose inlining BUYS something — the body is one of three benefit classes: EMPTY (the call compiles away), an accessor / thin forward / trivial mutator (a bare field chain, a call through a chain with only chain / literal arguments, an assignment / increment over a chain — collapses to a direct read / write / call), or a constant / small-arithmetic expression (literals, chains, operators only — folds at the call site), the latter two bounded by a 32-AST-node budget (`MAX_BODY_NODES`); `Info`, `--fix` inserts `inline ` before the `function` keyword. Everything outside the benefit classes — an allocation (`new`, array / object / interpolated-string literal, a `macro` reification), a lambda / computed argument, a loop, a switch, a multi-statement body — is never a candidate: inlining it would only duplicate codegen at every call site. Every class body — plain / `final` / `abstract class` (`CheckScan.isClassBodyKind`) — is inspected. Soundness gates (a miss over a wrong flag), each conservative: a method referenced ANYWHERE in scope as a VALUE — a method-value cannot be inlined — skips it, detected by a project-wide name scan for a value-position occurrence (not a call callee) via `IdentExpr` / `FieldAccess` / `SafeFieldAccess` / `ForceFieldAccess` (so `.bind`, a callback argument, a stored reference — resolvable or not — all block it); an `override` method and a method OVERRIDDEN by a subtype (`SymbolIndex.hasSubtype` plus `SymbolIndex.subtypeMemberNames`, a walk of the memoised subtype adjacency) is skipped (inlining breaks the override — Haxe rejects the modifier outright with "is inlined and cannot be overridden"). That veto used to be asked by scanning EVERY type in the index and testing `isSubtype` on each, which is quadratic in corpus size; the adjacency walk keeps the rule linear, so it runs over a whole haxelib tree at the cost of parsing it. It is also more correct: `isSubtype` refuses when the SUBTYPE's own simple name is ambiguous in the index, so an override declared by a type whose name another module also declares was invisible and the rule recommended inlining a method Haxe forbids inlining (a method overridden by a root-package `Main` while a second `Main` in another package made the name ambiguous); a method filling an abstract-superclass slot is skipped (`SymbolIndex.supertypeDeclaresMember` — Haxe requires no `override` on such an implementation); a method an implemented interface declares is skipped (`SymbolIndex.typeProvablyLacksMember`, which also refuses an unresolvable interface); a `dynamic` / `macro` / constructor (`new`) / `@:keep` method, any method carrying a compiler annotation not on the inline-neutral list (the target-binding family `@:native` / `@:hlNative` / `@:cs.native` / … and the code-injection family `@:functionCode` / `@:functionTailCode` make the written body a placeholder the backend discards, so inlining substitutes the placeholder and the redirect never happens — a USER annotation is accepted, no backend reads it), an `extern` field, and any method whose name is passed to `Reflect.*` as a string literal anywhere (reflection-accessed), is skipped; and a self-recursive body (a bare `foo` / `this.foo`) is skipped — a delegation to a same-named method on ANOTHER receiver (`other.foo()`) is not self-reference and stays a candidate. An already-`inline` method is a no-op. The finding is spanned at the method's `function` keyword; mirrors `trivial-getter`'s soundness model A method written inside a member-position `#if … #end` is scanned too, branch by branch — so an `override` in one branch binds to that branch's method only, and a guarded `inline` is no longer missed — and the `inline` insert lands inside the branch. A method whose modifier run only SOME builds see is skipped.

## `prefer-read-only-field`

## `redundant-bypass-accessor`

## `redundant-isvar`

## `redundant-property-access`

a property whose BOTH accessors are `default` — `var x(default, default):T` — restating to the compiler exactly what a bare `var x:T` already declares (same storage, same read, same write); `Info`, `--fix` deletes the clause (`public var isSnap(default, default):Bool = false;` → `public var isSnap:Bool = false;`). DEFAULT OFF, for two reasons. **(a)** A project may spell the plain shape on purpose: in the reference project every real-corpus site sits in a run of accessor-bearing siblings (`bold(default, set)` / `italic(default, set)` / `dispatchEvents(default, default)`), where the clause buys column parallelism the fix would break. **(b)** The two spellings are NOT identical to a `@:build` / `@:autoBuild` macro, which sees `FProp('default', 'default')` before the fix and `FVar` after — a project whose macros switch on field kind must leave the rule off. Opt in with `"redundant-property-access": { "enabled": true }` (or an explicit `--rule`). Fires on the exact pair ONLY: every other accessor is a real declaration (`get` / `set` route through a method, `dynamic` re-binds at runtime, `null` / `never` restrict write access, a method name is a custom accessor), so any of them on EITHER side, an arity other than two, or a clause the identifier scan cannot read (a `#if` directive inside it) is a safe miss. Outside the walk entirely, and so never flagged: `final` members, local declarations (`eachFieldMember` visits mutable FIELD members only) and INTERFACE members (`visibilityContainerKinds` covers classes and abstracts, not `InterfaceDecl`) — Haxe treats an interface `(default, default)` the same way, so that one is a safe miss rather than a decision. The fix is ONE edit — the clause plus the whitespace before it, `[name end, ')' + 1)` — so visibility, `static`, the type annotation, the initializer, the doc comment and the metadata all survive verbatim; `@:isVar` is metadata on the member, not part of the clause, and is left in place (inert on a plain field, which always has physical storage). **Comment guard**: a comment marker anywhere from the declaration's start through the clause's `)` withholds the finding. That is deliberately WIDER than the deleted region, because the field-name token is located by text search: a comment quoting the name (`var /* x(default, default) */ x:Int;`) would otherwise send the scan into the comment's own text and report an already-plain field A property written inside a member-position `#if … #end` is scanned too, branch by branch.

## `scratch-field`

a private field that is only a per-call SCRATCH value of one method — every read and write in that method's body, each read after a write of the same call — turned into a local of that method; `Info`, `--fix` deletes the field and declares the local at its first write (`final` when it is the only write, else `var`), keeping the field's declared type and dropping its leading underscores when the method mentions no such name (`KnobSlider._sliderPointLocal`). Reported only on positive proofs: a plain mutable instance field (no modifier but the default visibility, no metadata, no accessor clause) of a class-like type, every reference to it in its own file (`MemberWriteScan.referencesConfined`: no subtype or `@:access` grantee MENTIONS it — a subtype that never does keeps nothing from it — no `@:allow`, no skipped file spells it), no `@:rtti`, its name in no string literal of the resolution scope, every occurrence in ONE method's body outside closures, reifications and conditional regions, no binder of its name, no other receiver's member spelled with it, and at least one read. The fix additionally needs, else the finding is report-only and names the gate: DOMINANCE by a pessimistic forward walk (a branch assigns only when both arms do; a loop body, `switch` arm, short-circuit operand, `try` and `do … while` body assign nothing that survives) — the one gate that fails in `run`, with its own message; a declaration slot (the first write is a `name = value;` statement of a block holding every later use); a declared type; a droppable initializer (none, side-effect-free, or a construction of a class whose sole constructor only assigns its own fields side-effect-free values); no method CALLED on an object value (it may start work that outlives the call, and only the field kept the object alive); a method that does not name itself (recursion would share the field between calls; a constructor naming `new` builds another object). `RiskyFix` + `OracleRelaxable`: a type a build macro reaches is declined without a compiler oracle and typechecked with one; indirect re-entry through a synchronously fired listener is the accepted residual

## `static-constant`

an INSTANCE `final` field whose initializer is a pure compile-time literal — every instance stores its own copy of a value the compiler already knows; `Info`, DEFAULT OFF (opt in with `"static-constant": { "enabled": true }`), `--fix` inserts `static` before `final`. Composes with `inline-constant`, whose input is exactly this rule's output, so a second pass makes a promoted scalar `static inline final`. The initializer gate is a POSITIVE criterion rather than a blacklist: an `inlineConstantLiteralKinds` literal, a negated numeric one, or a PLAIN string literal (`stringFoldSupport().literalOf`, which answers null for anything interpolated). Everything else refuses by construction — an array literal `[]` is never reassigned yet mutated through `push`, a `new Sprite()` is per-instance identity, and a CALL INSIDE INTERPOLATION (`'${UUID.uuid()}: close'`) differs per instance exactly as a call in value position does. The literal is only a DEFAULT, so the second half of the proof is a write scan: an instance `final` with an initializer can still be REASSIGNED in the constructor (measured — the two constructions print 5 and 9), which the `static` form rejects with "This expression cannot be accessed for writing"; any assignment to the name in the file refuses. Reachability is cross-file and the rule FAILS CLOSED on all of it, because `Check.fix` is handed ONE file: a subtype reads an inherited private INSTANCE field unqualified and it resolves, while the same bare read of a private STATIC is `Unknown identifier` (only `Owner.NAME` works), so ANY mention of the name by a subtype or an `@:access` grantee refuses; `this.NAME` / `obj.NAME` are both `Cannot access static field NAME from a class instance`, so a member access on the name in the declaring file refuses and a PUBLIC field refuses wholesale; and `Reflect.field(instance, "NAME")` goes from the value to `null`, so the name appearing as any string literal in scope refuses, as do `@:keep` / `@:rtti`. Also skipped: `@:structInit` (an initialized `final` there is an OPTIONAL CONSTRUCTOR ARGUMENT), a `@:build` / `@:autoBuild` file (a macro can inject a read no text scan sees), a non-class-like container (an `enum abstract` value is not an instance field), and a member whose modifier run the `#if` branches disagree on. The shared OBJECT case — a `TextFormat` several text fields receive — is deliberately out of scope: whether it is shareable depends on what a library consumer does with the reference, which is a config-allowlist question, not a structural proof. Registered in the `--fix` loop's full-scope set: every reachability gate is whole-project, so a subdirectory run is a preview, not a verdict

## `static-init-order`

a static field initializer that reads a static field of the same type declared BELOW it (`static var a = b + 1; static var b = 5;`). Haxe runs static initializers in declaration order, so the read sees the later field before its own initializer ran: `null` on the interpreter, `undefined` on js, the type's zero on a static target — a non-inline `static final` constant included, since only an `inline` one is folded at compile time. `Warning`, Haxe only, on by default. A read is a binding, not a word (`MemberInitDeps.firstEarlyRead`): an identifier that binds to the later field's declaration, or `<ThisType>.field`, and the finding names the field actually read (`ob.b` reads `ob`). A static method the initializer calls runs right there, so a read in its body counts too, however deep the calls go (`static var a = f(); static function f() return b;`); a method only named as a value (`static var g = f;`) runs nothing. Left alone: a read inside a function literal (`static var f = () -> b;` runs when called), the name in a string, a comment or an object-literal key, another type's static of that name, a local binding of that name, a read of an `inline` field or of one with no initializer, and an instance field (another phase; the compiler already rejects an instance initializer reading a member). `member-order` keeps its own, deliberately conservative word scan (`initReadsSibling`). Report-only: moving the read field above the reader can break member order or another initializer that reads it, and which declaration should move is a human call.

## `trivial-getter`

a property accessor that does nothing but forward a private backing field, collapsible into direct storage; `Info`, `--fix` rewrites the property, deletes the dead accessor(s) and the backing field, and renames every in-class reference of the backing field to the property name. Four shapes: `(get, never)`/`(get, null)` with a trivial getter → `(default, null)` (the original read-only case); `(get, set)` with a trivial getter and a REAL setter → `(default, set)` — external writes to the backing field outside `set_x` (each a deliberate setter bypass; renaming one would start routing through the setter) pick the arm: NONE → the plain collapse; 1..`maxBypassWrites` (an `apqlint.json` option on the rule, default 3), ALL statement-level (`_x = …;` a whole statement) → the collapse proceeds and `--fix` prefixes each such write with `@:bypassAccessor` (a bypass write on `(default, set)` is a direct field write — the original semantics, exactly); MORE than the cap, or any write nested inside a larger expression → no collapse, `--fix` instead marks the trivial getter `inline` (the finding is skipped entirely when the getter is already `inline` or carries `override`). Reads anywhere are safe since `(default, set)` reads are direct, and a backing-field declaration initializer (or the one movable constructor-init literal) moves onto the property; `(get, set)` with BOTH accessors trivial → a plain `var`; a REAL getter with a trivial setter → `(get, default)` — READ-GATED: no read of the backing field outside `get_x` (a `(get, default)` getter reading the property compiles to a direct physical read, verified against Haxe codegen), where compound-assign/incr/decr targets COUNT as reads (`x += 5` lowers to `get_x()` + set) and only a pure `=` target does not. Every class body — plain / `final` / `abstract class` — is inspected; the accessor must be the standard `get_`/`set_` pair, non-`dynamic`, its body exactly `return _x;` / an equivalent single assignment, and the backing field a PRIVATE same-class field whose declared type MATCHES the property's (`declaredTypesMatch` — a getter performing an implicit conversion, e.g. `Array` -> `ReadOnlyArray`, would retype the merged slot and break mutating uses). A renamed reference is qualified `this.x` whenever ANY binding of the property name is visible in the enclosing function — parameter, local (`static` local and multi-var continuation included), loop / comprehension iterator, the value slot of a `for (k => v in m)` header, catch variable, case-pattern capture (`case x:` and `case var x:`), local function (plain / `inline`), lambda parameter — and `C.x` for a static property or inside a static method, so a collapse can never re-bind a reference to the shadowing binding (`if (color == _color)` in a `for (color in …)` loop must not become the always-true `color == color`). Assumes no direct `get_x()`/`set_x()` call sites (the rule family's standing accessor assumption) A property, backing field and getter written inside a member-position `#if … #end` are scanned too, and the collapse's edits — accessor clause, field deletion, getter deletion, modifier runs included — land inside the branch. Every member the collapse touches — property, backing field, accessors — must sit in ONE branch (a getter duplicated per branch would otherwise lose the other branch's body silently), a guarded property whose backing field is mentioned outside its branch is refused (the collapse renames that field into the property's name, which only exists where that branch compiles), and a collapse that would empty a region is refused too. The backing field has a SECOND spelling: the property ITSELF, where a trivial getter returns the property's own name — legal in Haxe only when the property has physical storage of its own, which `@:isVar` grants to `(get, set)` / `(get, never)` and an already-physical write side grants to `(get, null)`. The same four shapes collapse to the same clauses, but the fix is a strict SUBSET of the bridged one: no field deletion, no initializer relocation, no reference rename, no `@:bypassAccessor` marking — external access routes through the accessors before AND after, which is the very property the bridged arm's three-way write decision exists to restore. Two outcomes differ: `@:isVar` is dropped WITH the collapse (every target clause has a physical side, so the metadata is dead once the getter goes — and it cannot go first, since Haxe rejects the pre-collapse shape without it: `Add @:isVar here to enable it`), and a self-backed `(get, never)` collapses to `(default, never)` rather than `(default, null)`, since `never` refuses a write from every position including the constructor and widening would buy nothing. `subtypeOverridesProperty` still gates; `subtypeReferencesField` and the cross-file slice do not apply (nothing is deleted); and an `override` accessor REFUSES, because a self-backed property can legally sit over a supertype's plain `get_x`, whose callers the deletion would re-point. Note that `hxq encapsulate-field` emits exactly the self-backed both-trivial shape as a seam, so this rule reports and collapses a freshly encapsulated field until real logic lands in its accessors.

## `unstored-property`

A property whose physical field nothing ever stores: its read access is `default` or `null`, its
write access is `set`, and its own setter never names the field. Every write hands its value to a
setter that drops it or puts it elsewhere, and every read returns the field's initial value.
`Warning`, report-only — storing the value changes what every read returns, which is a human's call.

When nothing in scope reads the property either, the finding is `Info` and `--fix` turns the read
access into `never`. That fix rests on a whole-project proof of absence, so it is a `RiskyFix`,
applied only under a `compilerOracle`. Nothing is reported when anything else could reach the
storage: an initializer, an extern owner, `@:bypassAccessor`, a reflective string naming it, or a
write through `Dynamic`.

```haxe
public var size(default, set):Int;
function set_size(v:Int):Int { layout(v); return v; }  // reported: size is never stored
```
