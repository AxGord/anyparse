# `loops` rules

Loops and the collection / map idioms they spell. One section per rule, by id; each rule's language, default and fix marker are in the [rule index](../../lint-rules.md#loops), and a suite test fails when a registered rule has no section here or a section names no rule of this category.

## `dead-binder-counter-loop`

a `for`-in that iterates a collection ONLY to count it — `var i = 0;` immediately followed by `for (x in coll) { … i++; }` where NOTHING reads the binder `x` — which a range `for` says directly; `Info`, `--fix` rewrites the pair to `for (i in 0...coll.length) { … }`, dropping both the declaration and the trailing increment. DEFAULT OFF (`DefaultOff`) — the input compiles and behaves correctly, so replacing it is a style choice: opt in with `"dead-binder-counter-loop": { "enabled": true }`. A container with no `length` is counted through `Lambda.count` (`for (i in 0...coll.count())`) and a `using Lambda;` is inserted when the file lacks one — which costs ONE extra traversal the original did not pay (`count()` walks, then the range loop walks again); a rival `using` that could also supply `count` refuses those rewrites (the inserted one would lose to it, silently retargeting the call), and the `using` is decided only from the edits that SURVIVE containment filtering, so a swallowed nested rewrite cannot leave an unused one behind. Grammar-agnostic over the shared `LoopScan` seams plus `postIncrKind` / `continueStatementKind` / `exprStatementKind` / `mutableLocalDeclKinds` and `GrammarPlugin.controlFlowSupport`; any unset → no-op. The pair scan runs over STATEMENT LISTS only (`ControlFlowSupport.blockKinds()`), which deliberately EXCLUDES the conditional-compilation node: a `#if` region projects as one node holding every branch's statements as flat siblings, so pairing across it would splice through the `#else` and delete it — a pair written inside a `#if` is simply not matched. Soundness gates (all required): the declaration is a single-variable `var i = 0;` (NOT `final` — the counter is incremented) whose declared type, if any, is `Int`, and it is the immediately-preceding sibling of the `for`; the binder is DEAD — proved by a TEXT scan over the body span, not a node walk, because a bare `'$x'` interpolation read and a `macro` reification subtree are both invisible to the tree and a missed mention here is a licence to DELETE the binder; `i` is a pure counter — the trailing `i++;` is its ONLY write, it is the body's LAST statement, nothing after the loop reads it (a range `for` scopes `i` to the loop, whereas the `var` leaves the final count visible), nothing re-declares it in the body, and no closure in the enclosing scope captures it; no `continue` (which in the `for`-in form SKIPS the increment, leaving `i` below the element count, but in a range `for` advances — a `break` is fine, both forms stop at the same iteration); and `coll`'s length cannot move (the same body-local stable-collection scan `prefer-keyvalue-loop` uses, with the same documented aliasing limit). Unlike its sibling, this check does NOT report an unresolved container: the replacement TEXT depends on the type, so a finding it cannot spell would be noise. `coll` must be a bare identifier whose binding is declared `Array` / `List` (→ `length`) or `Map` / `StringMap` / `IntMap` / `ObjectMap` / `EnumValueMap` / `BalancedTree` (→ `count()`), and PROVED the std one: `SymbolIndex.stdDeclarationOf` must bind the written type in the file's scope to exactly ONE declaration under the discovered std root, the compiler's way (`TypeNameBinding`: any import / `using` / wildcard / ambient source nothing can read that could bind the name leaves it unknown; an alias makes it the aliased type), over a run whose declared `resolutionRoots` all matched (`RefactorSupport.projectIsComplete`) — anything unknown is no proof, so a project or library `List`, an unindexed import that could bring one, or a run without a complete project index leaves the loop unclaimed. No std map declares a `count` of its own, so the `count()` call always reaches `Lambda`'s. Everything else — a path receiver, a call, an unannotated binding, a range — is silently skipped. That list is a WHITELIST on purpose: `Lambda.count` needs an `Iterable`, and "everything `for (x in …)` accepts" is strictly wider — an `Iterator` is accepted by `for` but CONSUMED by a count, which would silently run the rewritten loop zero times, and `haxe.ds.HashMap` iterates but is an abstract that does not unify with `Iterable` at all; `Vector` is off the list because a geometry `Vector`'s `length` is a magnitude, not a count. A comment in either dropped region (the declaration plus the `for` header, or between the increment and the body's `}`) refuses that rewrite, leaving the finding report-only; the body interior is carried verbatim, so comments there survive. The finding is spanned at the `var i = 0;` declaration

## `join-array-pushes`

an empty-array binding immediately followed by a run of `a.push(<expr>);` statements — an array literal written the long way; `Info`, `--fix` folds the pushed expressions into the `[]` and deletes the push lines. Two acceptance paths over one fold-and-splice core. **Path A** (a fresh local declaration, nothing moves): a local `var` / `final` DECLARATION whose initializer is the empty array literal, followed by a MAXIMAL run of adjacent push statements in the SAME statement list — `final a:Array<Int> = []; a.push(x); a.push(y);` -> `final a:Array<Int> = [x, y];`. The elements land in the order the pushes stood in, nothing foreign sat between them, and the declaration BINDS the name so nothing before it could read what the pushes fill — hence no purity proof, and `a.push(new T()); a.push(f());` folds here. An ASSIGNMENT to an existing name (`_a = []; _a.push(e);`) is NOT accepted: the assignment RUNS, and folding moves the elements ahead of it, so an element reading the name indirectly (`_a.push(count())` where `count()` reads `_a.length`) would see the pre-assignment value and a property target would see one setter call instead of two. **Path B** (field declaration, across the constructor prologue): an INSTANCE field initialised `[]` plus a run of `f.push(e)` / `this.f.push(e)` statements at the TOP LEVEL of the constructor body (a push nested in an `if`, a loop or a `#if` region is never part of a run). Here the elements really move, so Path B adds: every element is a CONTEXT-FREE CONSTANT — pure by `PurityScan` (a `new T()` or any non-stdlib call refused; a collection literal admitted by the rule itself, as `unnecessary-switch` does, since each element is still evaluated exactly once) AND context-free by the shared `RefactorSupport.contextFreeRhs` (no `this`, no other instance member, no constructor parameter or local — what makes the moved text legal at declaration-initializer position); `RefactorSupport.ctorPrefixUnconditional` (a run behind an early `return` / `throw`, or after a loop that need not terminate, must not become unconditional); the prologue must RUN NOTHING — no top-level statement before the run may hold a call or a `new` anywhere in its subtree, with the `super(...)` statement the one exemption, because a plain `log();` whose method reads the field's `length` would observe an empty array today and a filled one after the fold and purity says nothing about it; no reference to the field anywhere in the constructor BEFORE the run; under `super(...)`, no `override` member of the class may read the field (a base constructor can only observe the populated array through a virtual call — deliberately NOT `field-init-at-declaration`'s blanket refusal of every constructor that calls up, whose reason, foreign code running early, the purity and prologue gates already exclude); `FieldWriteIndex` must report ZERO writes to the field and no unresolved write to its NAME; and a name the container declares twice (mutually exclusive `#if` branches) is refused. Gates BOTH paths share: the binding must be provably an ARRAY — an explicit annotation's outer nominal name (`NominalTypes.outerNominalOf`, which drops the package qualifier and the type arguments) must be a `RefShape.arrayTypeNames` entry, and a head the annotation reader cannot attribute to the declared name (`RefactorSupport.DeclaredType.Unreadable`, e.g. `final stack:pkg.stack = []`) refuses too, since only a positive `Absent` proves the initializer types the binding; a user `abstract` over `Array<T>` may declare a `push` that PREPENDS, and an unannotated `= []` needs no proof. Also shared: the run is maximal and its pushes are consecutive siblings (on Path A the declaration is the sibling before it; on Path B the binding is a field, tied to the run by the receiver); no comment in the folded region, scanned to the END OF THE LINE the last push sits on rather than to the statement end (Path A scans one region, declaration start through that line end; Path B scans two disjoint ones, the field declaration's span and the run's start through that line end); no self-reference to the array in any element (plain identifier or `$a` interpolation); and the name read after the run — on Path B with the field's OWN declaration excluded, so a field declared below the constructor cannot satisfy the gate with itself. The fix joins elements with `, ` and introduces no line breaks, and each push deletion spans `[end of the previous line, statement end]` and never extends forward; `lint --fix` then canonicalises what it writes, so the project's own `hxformat.json` array-wrapping policy has the last word on layout. Grammar-agnostic over `RefShape.callKind` / `fieldAccessKind` / `exprStatementKind` / `arrayLiteralKind` (any unset -> no-op); most other seams cost only REACH, but FIVE fail CLOSED — `stringInterpIdentKind` and `opaqueKinds` disarm the whole rule (without them `referencesName` stops seeing `a.push('$a')` and stops fail-closing on reification, so a grammar declaring neither gets the rule as a silent total no-op — a deliberate choice documented in the rule's own doc), `newExprKind` disarms Path B, and `superReferenceText` / `overrideModifierKind` only TIGHTEN it

## `loop-bound-length-mismatch`

an indexed loop `for (i in 0...Y)` READING `xs[i]` while the length of `xs` PROVABLY comes from another expression `X` — "the length of `_points` comes from `numPoints` (line N), this loop runs to `Grid.GRID_NUM_HORIZONTAL + 1`"; `Warning`, report-only (`NoAutofix`: which bound is right is a bug fix). Silent unless the length is proven: filled empty and then appended by ONE statement directly in the body of one top-level `for (_ in 0...X)` with no jump, return or throw (a field in its sole constructor, never a static; a local in a later statement of its block — arrays appended in the same loop are parallel and share `X`), a `k`-element literal (no comprehension, no conditional region), or `new haxe.ds.Vector(n)` (`ExecutionShape.fixedLengthArrayTypes`, a simple name only when the file imports that path — OpenFL's `Vector` grows); every occurrence in scope keeps the length (an index read — an index write only on the fixed-length type — a `length` read, a `for`-in subject, a `nonMutatingArrayMethods` call, the source's own append or initialization), no binder takes the name, a field is non-public, a non-property and referenced from its file only, and a declared type is the built one. A bound naming the array or a parallel one is related; otherwise both fold to integers under `ExecutionShape.integerFoldOperators` and `static final` constants of the run (`4 + 1` equals `5`) or compare as whitespace-free text, a read of `xs[i + k]` moving the loop's reach by `k`. `VolatileMessage`: the line is masked out of the finding's identity

## `loop-guard`

a loop (`for` / `while`) whose braced block OPENS with a bare `if (g) continue;` guard — that block being the loop body itself, or the then-branch of a header `if` the loop body already is — the user's rule: combine `for` + `if` into `for (...) if (...) {`, preferred over a leading `if (!cond) continue;` that inverts the condition and wastes a line; `Info`, `--fix` lifts the guard into the loop header with an INVERTED condition: `for (x in xs) { if (c) continue; REST }` → `for (x in xs) if (INV) { REST }`. TWO ARMS share that equivalence — a `continue` in the FIRST position of a block IS "do not enter the body". The LIFT arm is the one just shown (the loop body IS the block, and the inverted guard becomes the header the loop did not have). The MERGE arm covers a loop whose body is ALREADY a lifted header `if (c) { … }` whose braced block opens with the guard: `for (x in xs) if (c) { if (g) continue; REST }` → `for (x in xs) if (c && INV(g)) { REST }`, joining the inversion onto the existing header with `RefShape.andOperatorText` instead of creating a second `if`. Precedence is handled on BOTH sides: the KEPT header condition is parenthesised when its kind is in `RefShape.andLowerPrecedenceKinds` (the list `collapsible-if` merges with), and the INVERSION is parenthesised when it binds looser than `&&` — a De Morgan `a && b` guard negates to a top-level `||`, so `if (!o.locked) { if (o is P && !(t && n == o.type)) continue; … }` merges to `if (!o.locked && (!(o is P) || t && n == o.type)) { … }`. That slot is SYNTHETIC (there is no `&&` node to pass as a parent), so `NegationScan.negateConditionText` / `BooleanLogicSupport.negateCondition` take the slot by KIND (`slotKind`) where `simplify-negated-compound` passes a parent node. The inversion is sound over IEEE floats AND over `null`: `!e` → `e` (stripping a redundant paren), `a == b` → `a != b` and `a != b` → `a == b` (NaN-safe — `NaN == x` is false, `NaN != x` true, so `!(a == b)` ≡ `a != b`), and everything else — ordered comparisons `<` / `<=` / `>` / `>=` (whose flip differs from the wrap under NaN and under a null operand alike, UNLESS both operands resolve to a type `<` orders TOTALLY — `Int` / `UInt`, or a non-float literal — through the run's `SymbolIndex`, which licenses the flip `a >= b`. A `Null<T>` RECEIVER is unwrapped for that member lookup (`Null<String>.length` IS `String.length`); an operand's OWN `Null<…>` type is not, and still refuses (`null` is not a value `<` orders, and what a target does with it varies) — see `guard-return` for the full rule. `String` is NOT such a type `String` is NOT such a type, Haxe having no non-nullable string), `&&`, `||`, a call — is wrapped `!(c)` rather than flipped, with the parens dropped when `c` binds tighter than unary `!` (a bare identifier / call / field access → `!c`). Grammar-agnostic over `RefShape.loopStatementKinds` (loops whose body is the last child) / `continueStatementKind` / `ifStatementKinds` / `blockStmtKind` (any unset → no-op), plus `notKind` / `eqKind` / `notEqKind` / `parenKind` and the atomic-expression kinds for the inversion, and `opaqueKinds` to skip macro reification. Gates: the inversion must be WORTH doing — when the negation engine has to DECLINE an ordered-comparison flip it knows how to perform (the operands are not provably free of NaN and `null`), the lifted header would read `if (!(x < 10))`, which buys nothing over the `continue` guard, and the site is NOT flagged (`NegationScan.negationIsClean`); a wrap the engine could never avoid — `!(a is B)`, `!(a ?? b)` — is not a decline and still fires. Also: the guard is the body's FIRST statement, the body a braced block with at least one statement after it (a guard-only body is a no-op loop, left alone), and the guard a bare `if` (no `else`) whose then-branch is exactly `continue;` (bare or braced-single). A CASCADE — the statement right after the first guard is ANOTHER `if`-continue — is NOT flagged (the user keeps sequential `continue` guards, each introducing its own checks, rather than nesting them); a later `continue` deeper in the body is fine (the wrapped body still continues the same loop) and does not block the flag; an unbraced body, an `else` branch and a comment inside the guard (the rewrite would drop it) are safe misses. The MERGE arm adds three gates of its own: the header `if` must carry NO `else` (that branch fires on `!c` today and would fire on `!c || g` after the merge), its then-branch must be a BRACED block, and BOTH `&&` seams must be set — `RefShape.andOperatorText` for the joiner and `RefShape.logicalAndKind` for the slot the inversion is parenthesised against (either unset, only the LIFT arm runs; a merge emitted without the slot would drop the pair and re-associate)

## `map-keys-lookup`

a `for (k in m.keys())` loop whose body re-looks-up the same map by the same key (`m[k]` or `m.get(k)`) — the user's rule: use `for (k => v in m)`, since the keys-then-lookup form re-looks-up every value; `Info`, with an autofix: it drops `.keys()`, binds the value once, and replaces every `m[k]` / `m.get(k)` with that binding — reusing the name of a leading immutable value local (and deleting its declaration) when its annotation is a grammar-guaranteed builtin, so the annotation cannot be a nullable alias whose widening the rewrite would lose. The iterable must be EXACTLY `<recv>.keys()`, where `<recv>` is an identifier or a PATH of plain field accesses over one (`session.files`, `this.files`); a link that is a call, an index access or a `?.` disqualifies the path, since those carry side effects of their own. Every gate below is keyed on that whole path, and a leading `this` is normalised away in the SKIP gates (never in the match gate — widening a skip can only lose findings, widening the match would equate a local with a same-named member). The body must contain at least one lookup of that same path by the same key, as an index access `m[k]` or a `m.get(k)` call (a different key `m[j]` or a different map `n[k]` is not a match). Grammar-agnostic over `RefShape.forStmtKind` / `identKind` / `callKind` / `fieldAccessKind` / `indexAccessKind` (any unset → no-op), plus `writeParentKinds` for the mutation gate, `localDeclKinds` / `paramKinds` for the re-binding gate, `nullableIndexTypeNames` / `nullableWrapperTypeNames` and `SymbolIndex` member resolution for the type gate, and `opaqueKinds` to skip macro reification. Conservative gates (a miss over a wrong flag): any mutation of the map in the body — `m[...] =` (or a compound-assign / increment via `writeParentKinds`), or a `m.set(…)` / `m.remove(…)` / `m.clear(…)` call — SKIPS the loop, since iterating `keys()` while mutating may be deliberate; so does RE-BINDING what the path denotes (`m = other`, `o.files = other`, `o = p` — a write target that is a prefix of the iterable, inclusive of equality; a deeper write like `o.files.inner = 1` is the mutation gate's business, not this one); a re-binding of the path's root or the key name anywhere in the body (a local, a nested-function parameter, or a nested loop variable) SKIPS it; and, when the plugin provides type info, a receiver whose type resolves to a concrete NON-map-family nominal is SKIPPED — for a path this resolves the ROOT and then walks each field segment's member type, which is CROSS-FILE, so the rule is registered as full-scope in the `--fix` fixed-point loop (on a changed-files subset a type declared elsewhere would read as unresolvable and re-flag the very loops the gate skips). An unresolvable receiver still flags — a deliberate false-positive tolerance, identical for paths and identifiers, not a proof of Map-ness. The finding is spanned at the `.keys()` iterable

## `prefer-array-literal`

an empty-argument `new Array()` / `new Array<T>()` replaceable with the array literal `[]`; `Info`, `--fix` rewrites it (the element type carries through the assignment target's annotation; an unannotated `var x = new Array<Int>()`, whose only type source is the constructor's own parameter, is left alone). A plain ASSIGNMENT `x = new Array<T>()` / `this.x = new Map()` also rewrites when the lvalue resolves — shadow-guarded, via `TypeResolver.identDeclaredTypeSource` (typed local / param / own field) or `SymbolIndex.memberTypeSourceOf` for `this.<field>` — to a declaration whose explicit annotation's outer nominal is `Array` (resp. `Map`); a `Dynamic`/non-collection or unresolvable target is never rewritten

## `prefer-comprehension`

an empty-array local declaration `var/final a = []` immediately followed by a `for` or `while` loop whose only effect is `a.push(<expr>)` — the user's rule: use a `[for]` / `[while]` array comprehension instead of `[] + push` when each iteration produces exactly one element; `Info`, `--fix` replaces both statements with `final a<:T> = [for (x in xs) <expr>];` (or `[while (c) <expr>]`). Grammar-agnostic over `RefShape.forStmtKind` / `whileStmtKind` (optional — unset costs only the `while` form) / `localDeclKinds` / `callKind` / `fieldAccessKind` / `exprStatementKind` / `blockStmtKind` / `identKind` (any required one unset → no-op), plus `ifStatementKinds` for the guard form and `opaqueKinds` to skip macro reification. The comprehension is transcribed from source, so a key-value `for (k => v in m)`, nested `for (a) for (b)`, a `while (c)` header and one trailing `if (cond)` guard all transfer verbatim; the produced element is the push argument. `do … while` is a separate kind and never matches. Soundness gates: the initializer's source (whitespace-stripped) must be EXACTLY `[]` (`new Array()` is left to `prefer-array-literal`, whose `--fix` produces `[]` this then catches next run); every body layer must be a `for`, a `while`, a single-statement block, a no-`else` `if`, or the terminal `a.push(e)`, so any second statement, an `else`, a non-push call, or a `break`/`continue` (which would be an extra statement) is a safe miss; `a` must not appear in the element, an iterable, a `while` CONDITION, or a guard condition (a self-reference would change semantics — `while (a.length < 11) a.push('')` is the measured case that no comprehension can express, since the comprehension's own array is not that binding); `a` must be read after the loop (else it feeds no one — `unused-local`'s territory); and a comment trailing the declaration refuses the pair (an own-line comment between an adjacent pair is hoisted above the result instead, and a hoist that would weld together two comments code separated refuses). The fix always emits `final` (the binding becomes single-assignment, matching `prefer-final`) and preserves the type annotation verbatim. Two more loop shapes fold: a SEQUENTIAL INDEX FILL `for (j in 0...n) a[j] = v;` into the still-empty `a` (every write lands at `a.length`, so it appends — equivalent on `--interp` and js, `n == 0` included) becomes `[for (j in 0...n) v]`, only when the declaration is unannotated or annotated `Array<…>` (a `Map` would not compile, an `@:arrayAccess` abstract would lose its setter calls), only as the whole loop of the match, from the literal `0`, at exactly `a[j]`, the binder left for `unused-loop-binder` to blank on the next pass; and a NESTED BUILD `for (…) { final inner = []; <fill>; a.push(inner); }` becomes `[for (…) [<fill>]]` when the fill is itself a loop the rule folds. Both arrays pass the self-reference gate (`a[j] = a.length` diverges at runtime), an inner annotation the outer element type does not restate stays as an ascription, and an extra statement in the outer body refuses. A comment on its own line between an ADJACENT declaration and loop is hoisted above the result; one trailing the declaration still refuses.

## `prefer-count`

a manual COUNTING loop replaceable with `Lambda.count` — `var n:Int = 0;` immediately followed by `for (x in xs) if (cond) n++;` becomes `final n:Int = xs.count(x -> cond);`; with no filter, `for (x in xs) n++;` becomes `xs.length` over an identifier whose WRITTEN type is PROVED the std `Array` / `List` (no call, no walk, no `using`; the positive proof `dead-binder-counter-loop` shares, `SymbolIndex.stdDeclarationOf`: exactly one declaration, under the std root, as the compiler binds the written name (`TypeNameBinding`; the DECLARATION's name counts, so an alias spelling `List` for another type is that type), over a complete project index — anything else, a project or library `List` included, gets `count()`) and `xs.count()` over anything else. The FLAG form of the `prefer-exists` / `prefer-foreach` twins with a counter for the sink, over the same `LambdaLoopScan`. The step is `n++` / `++n` / `n += 1` (each bare or a single-statement block, under an `else`-less `if` or alone); the declaration a MUTABLE single declarator opening at the literal `0` with no annotation or an `Int` one; the loop its immediate next sibling in a statement list (never across a `#if` region); the increment `n`'s ONLY write in that list; neither the iterable nor the condition reading `n` (the fold moves both into `n`'s own initializer — `rows[n]` would read an outer `n`; a TEXT scan, so a `'$n'` interpolation counts, while a dotted tail `item.n` and an inert literal do not), the loop binder not named `n`, and no `super` in the condition (it becomes a lambda body). The sink-name and binder gates guard the twins' flag forms too, and the `super` gate every form of all three, the RETURN form included. NO purity gate, deliberately, and that is the difference from the twins: `Lambda.count` walks the whole collection and calls the predicate once per element in order, never short-circuiting, so an effectful condition runs exactly as often either way. Collection: no key-value / range loop; a CALL iterable only when its type proves `Array` / `List` / `Iterable` or — this direction only, since no map declares `count` — `Map` and the concrete `haxe.ds` maps (`m.count()` and `m.count(f)` both compile); a receiver PROVEN an iterator and not an iterable refused for every iterable shape and all three directions, structurally (`StructuralTypes.satisfiesIterator` and not `satisfiesIterable`, so `ArrayIterator`, `IntIterator`, `StringIteratorUnicode` or a project `hasNext` / `next` class as surely as `Iterator`, a `new T(…)` judged by the `T` it writes — a field included, `haxe.xml.Access.elements : Iterator<Access>`: `for` accepts it, `Lambda.count` does not); a receiver whose type declares `count` takes the QUALIFIED `Lambda.count(xs, x -> cond)` with no `using`. A comment in a dropped region, or a rival `using` that could supply `count`, leaves the finding report-only. `Info`, DEFAULT OFF (`"prefer-count": { "enabled": true }`); `RiskyFix` + `GroupedFix` as `prefer-exists`, because an identifier / field iterable is claimed without a type proof — the oracle reverts one that turns out not to be `Iterable`, and the inserted `using Lambda;` shares the revert. The follow-up `return n;` is `join-return`'s to fold

## `prefer-exists`

a manual ANY-MATCH `for` loop replaceable with `Lambda.exists` — `for (x in xs) if (cond) return true;` with a `return false;` fallback becomes `return xs.exists(x -> cond);`, and the FLAG form `var f:Bool = false;` + `for (x in xs) if (cond) f = true;` becomes `final f:Bool = xs.exists(x -> cond);` (the `var` becomes `final` because the fold leaves the binding written once). The flag form carries ONE gate the return form does not need, and it is the reason the arm exists at all: the CONDITION must be side-effect free (`PurityScan.isPure` — safe skeleton kinds, a field / index READ that is not a property getter, a provably-pure stdlib static; every other call impure). A `return` LEAVES the loop at the first match, so the emitted call's short-circuit is invisible; a flag assignment does not, and FIVE of those eleven sites call a function doing the loop's work on every element (`addItem(item, false)`, `itemData.removeLocks(removeList)`, `locks.remove(rm)`, `addSessionToLock(…)`, `removeSessionFromLock(…)`) — folding them would silently stop processing the tail of the collection. `RefactorSupport.isSideEffectFree` was the cheaper reach and the wrong question: it refuses a field access outright, and a field read is exactly what the one convertible site's condition is. Six more flag gates, each pinned by a fixture proved to convert without it: a MUTABLE single declarator, an initializer literal OPPOSITE to the loop's, the loop as the declaration's immediate next sibling, a then-branch that IS the assignment (which also makes the `break` / `continue` / `return` refusal structural), that assignment targeting the declared name, and the loop's write being the flag's ONLY one in the enclosing statement list (`final` would not compile against a second). The GUARDED flag form and a GAP between declaration and loop are NOT claimed — measured zero reach.; `Info`, DEFAULT OFF (`"prefer-exists": { "enabled": true }`), with an autofix that also inserts a `using Lambda;` when the file lacks one. Also claims the GUARDED form `if (g) for (x in xs) if (cond) return true;` -> `return g && xs.exists(x -> cond);` — the most common shape in real code — and a fallback reached by FALLING OUT of enclosing `if` branches rather than as an immediate sibling (then the trailing `return` survives, since other paths still reach it). Soundness gates: the loop body is a single `else`-less `if` whose then-branch is exactly `return <bool literal>`; the fallback is the OPPOSITE literal (a non-literal fallback such as `return xs.length == 0;` is refused, and so is a repeat of the same literal); no key-value / range iterable, and a CALL iterable only when its type PROVES to be `Array` / `List` / `Iterable` — the proof is the run's own type layer (`CheckScan.typeNominalResolver`: `TypeInfoProvider` for the types written in this file, the run's `SymbolIndex` for a member's return type across files), never a compiler oracle, so `m.keys()` is refused BY TYPE (an `Iterator` is not an `Iterable`) while `text.split(' ')` is claimed — and so is a chain through a `using` STATIC EXTENSION (`text.trim().toLowerCase().split(' ')`), whose extension link the walk reads off the file's own `using` header in the compiler's reverse declaration order, and only after `typeProvablyLacksMember` PROVES the receiver's type declares no such member, since a real member beats an extension — and a call whose type does not resolve keeps the blanket refusal `prefer-find` still makes; the successor is dropped at every construct where falling off the end does not continue after it (loop body, `switch`, `try`, `#if` region). A receiver whose own type — or a supertype — DECLARES `exists` is refused outright (`SymbolIndex.memberShadowsExtension`), because Haxe binds a real member before any `using` extension: on a `Map` the lambda would land in `exists(key:K)`'s key slot and the rewrite cannot compile. The nominal is read in RECEIVER position, so a member-transparent `Null<Map<K, V>>` binding answers `Map` rather than `Null` — both measured sites on a real application were behind that wrapper on one of the two. `RiskyFix` + `GroupedFix` all the same, for the receivers the structural gate cannot type: the edit is verified against the oracle and reverted, and the inserted `using` is in the same atomic group so a revert cannot leave it orphaned

## `prefer-find`

a manual first-match `for` loop replaceable with `Lambda.find` — the user's rule: use `.find()` instead of manually iterating to find the first matching element; `Info`, REPORT-ONLY (the `xs.find(x -> cond)` rewrite needs `using Lambda` in scope, so the import surgery and shadow analysis are out of v1). Two shapes: Form A `for (x in xs) if (cond) return x;` whose immediately-following sibling is a value-returning `return` (the `if`-body bare or a `{ … }` wrapping one return, the `for`-body optionally a single-statement block) — a `return null;` fallback is the plain `xs.find(x -> cond)`, any other value fallback the `xs.find(x -> cond) ?? <fallback>`; and Form B `var r = null; for (x in xs) if (cond) { r = x; break; }` — a null-initialized local then a loop whose `if`-body is exactly the loop-variable-to-local assignment then a `break`. Grammar-agnostic over `RefShape.forStmtKind` / `returnStatementKind` / `blockStmtKind` / `nullLiteralKind` / `identKind` / `ifStatementKinds` (any unset → no-op), plus `opaqueKinds` to skip reification; Form B additionally needs `localDeclKinds` / `exprStatementKind` / `assignKind` / `breakStatementKind` (any unset disables the break form, return form still runs). Soundness gates: the returned / assigned value must be exactly the loop variable (`return x.field` or a transformed value is `map`/`filter` territory); the `if` must have no `else`; the Form-B body must be exactly assign-then-`break` (a `continue` would find the LAST match, so the dedicated break kind is required) with a `null` initializer; a key-value `for (k => v in m)` is skipped (`.find` iterates values, not KV pairs); and the two statements must be immediately adjacent block siblings; and the iterable's own type must not DECLARE `find` (`SymbolIndex.memberShadowsExtension`, read in RECEIVER position so a `Null<T>` binding answers `T`) — a real member beats a `using` extension, so such a rewrite would silently retarget. No container in the resolution scope declares `find`, so that gate refuses nothing on the stdlib and exists for a PROJECT type of that name

## `prefer-for-in`

a hand-rolled iterator protocol — `while (it.hasNext()) { final x = it.next(); … }` — that the language's own `for (x in it)` expresses directly; `Info`, `DefaultOff` (a modernization cleanup, not a defect), with a `--fix`. The rewrite is behaviour-preserving BY CONSTRUCTION: `for (x in it)` desugars to exactly that loop, so `break` / `continue` / `return` keep their meaning and the iterator is left equally exhausted — which is why the plain arm can leave the iterator binding standing and replace the loop alone. Shape: the condition is exactly `<ident>.hasNext()` (bare identifier receiver, no arguments) and the body is a BRACED block of at least two statements whose FIRST is a local declaration initialized to exactly `<the same ident>.next()` — that statement both supplies the `for` binder and proves `next()` runs once per iteration, which a `next()` nested deeper in the body would not. The iterator identifier must occur EXACTLY TWICE inside the loop (the two protocol receivers), so a second `it.next()`, a re-assignment or a `$it` interpolation refuses; everything else in the body is spliced VERBATIM minus the binding statement, so nested loops, `#if` regions and comments ride along. The binder's type annotation is dropped (`for (x:T in xs)` is not valid Haxe and the binder's type comes from the iterator anyway), and a `var` binder is fine — a `for` binder is WRITABLE in Haxe (measured on `--interp`, `-js` and `-cpp`). INLINING ARM: when the statement immediately before the loop declares the iterator and nothing else in the nearest enclosing BLOCK reads that name, the declaration is dropped and its initializer becomes the iterable. The scope is the nearest block from `ControlFlowSupport.blockKinds()` MINUS the conditional-branch projection, because a `#if` region is not a scope in Haxe and a declaration inside one is still visible after `#end` (a whole-FILE count would be sound too but leaves the arm dead: `it` / `iter` recur across functions); a comment in the decl-to-loop gap, or on the last line of the initializer, falls back to the plain arm rather than dropping the finding. Deliberate misses, each a legitimate `hasNext()` idiom: a bare non-emptiness test (`if (xml.elements().hasNext())`), the peek idiom (`it.hasNext() ? it.next() : null`), and a single-push drain loop (`while (it.hasNext()) out.push(it.next());`) — the last has no statement to take a binder from, and a fixer should not invent a name. Grammar-agnostic over `RefShape.whileStmtKind` / `blockStmtKind` / `callKind` / `fieldAccessKind` / `identKind` / `localDeclKinds` (any unset → no-op), plus `opaqueKinds` (skip macro reification) and `stringInterpIdentKind`; the two protocol method names and the `for (… in …)` header are literals, as in `map-keys-lookup` and `prefer-range-loop`

## `prefer-foreach`

a manual ALL-MATCH `for` loop replaceable with `Lambda.foreach` — `for (x in xs) if (cond) return false;` with a `return true;` fallback becomes `return xs.foreach(x -> !(cond));`, and the FLAG form `var f:Bool = true;` + `for (x in xs) if (cond) f = false;` becomes `final f:Bool = xs.foreach(x -> !(cond));`. `Lambda.foreach` short-circuits on the first `false` exactly as `exists` does on the first `true`, so the flag form's PURITY gate and its six shape gates are the twin's, unchanged; `Info`, DEFAULT OFF (`"prefer-foreach": { "enabled": true }`), same shape gates, successor propagation and `using Lambda;` insertion as its twin `prefer-exists`, over the shared `LambdaLoopScan`. The inversion is a WRAP, never De Morgan — distributing `!` through a chain reorders the operands a null narrowing depends on — except that an already-negated condition drops its `!` instead of gaining a second (`if (!p(x))` -> `xs.foreach(x -> p(x))`). The GUARDED variant is deliberately NOT claimed: it needs `!g`, and negating a null-test guard strands the narrowing. The same receiver-shadow gate as its twin (`SymbolIndex.memberShadowsExtension`) — no container in the resolution scope declares `foreach`, so on the stdlib it refuses nothing and it is a PROJECT type declaring the name that it exists for. Not a `RiskyFix`, for that same reason: no standard collection declares `foreach`, so the emitted call cannot be captured by a stdlib member. `Info` is also a perf statement — on hxcpp `Lambda.foreach` erases its `Iterable<A>` to `Dynamic` and the generated C++ makes reflective calls by field name every iteration, so the rewrite is declined in a measured hot spot

## `prefer-index-access`

a `Map` read / write spelled as a method call replaceable with index access — `m.get(k)` → `m[k]`, `m.set(k, v)` → `m[k] = v`; `Info`, `--fix` rewrites it. Type-aware and it must be: index access `x[k]` / `x[k] = v` lives on Haxe's `Map` ABSTRACT only (its `@:arrayAccess` operators), so the concrete `haxe.ds.StringMap` / `IntMap` / `ObjectMap` — which carry `.get` / `.set` but NO array access — are safe misses; the receiver may be a plain identifier OR a path of plain field accesses over one (`this.m`, `obj.m`, `a.b.c`), whose final-segment outer-nominal type — the identifier's own declared type, or each path segment resolved cross-file through `SymbolIndex` — is a `RefShape.mapAbstractTypeNames` (`Map`) or a `RefShape.nullableWrapperTypeNames` (`Null`) unwrapping to one (`Null<Map<…>>`); an unresolvable receiver (never flagged without positive Map proof, since `[]` on a non-`Map` is a compile error), a `StringMap` / `IntMap` / other concrete-map path, or a link that is a call / index / `?.` is left alone; requires `plugin is TypeInfoProvider`. The cross-file resolution means the rule runs full-scope in the `--fix` fixed-point loop. A `get` needs exactly one argument, a `set` exactly two; the `set` rewrite is an assignment so `--fix` emits it only in statement position (a `set` used as an expression is flagged but not fixed). Nested matches (`m.get(n.get(k))`) fix the outer first, the inner on the next `--fix` pass

## `prefer-keyvalue-loop`

an INDEXED `for` that only wanted the element — `for (i in 0...X.length)` whose body OPENS with `final v = X[i];` — which Haxe's key-value iteration writes directly: `for (i => v in X)`, with that first statement gone; `Info`, `--fix` splices the header and drops the declaration. DEFAULT OFF (`DefaultOff`) — the two spellings are equivalent, so which one a project wants is a style choice: opt in with `"prefer-keyvalue-loop": { "enabled": true }`. The index stays BOUND, which is what makes this worth having over `for (v in X)`: an inner `for (j in i + 1...X.length)`, an `i`-keyed lookup elsewhere in the body, a `trace(i)` all keep working untouched (a body that never reads `i` again is still rewritten to the key-value form — collapsing THAT case to `for (v in X)` is a different rewrite, and it is `prefer-value-loop`'s. The two are disjoint BY ENFORCEMENT rather than by shape luck: that rule's `claimedByKeyValueLoop` declines exactly the loops THIS one claims, so no loop is reported twice and the two autofixes cannot race). Grammar-agnostic over the shared `LoopScan` seams (`forStmtKind` / `blockStmtKind` / `fieldAccessKind` / `indexAccessKind` / `callKind` / `numericLiteralKinds` / `localDeclKinds`, plus `nullSafeAccessKind` / `forceFieldAccessKind`, `writeParentKinds`, `lambdaKinds` / `localFunctionKinds` and `opaqueKinds`) and `intervalKind`; any unset → no-op. `length` is the one language-specific token, spelled as a constant. Soundness gates (all required): the iterable is exactly `0...X.length` for a BARE IDENTIFIER `X` (a path receiver such as `this.items` is skipped — the type gate reads a BINDING's annotation and a check's `run` has no `SymbolIndex` to walk a path with; a bare identifier that binds to a FIELD does resolve and is accepted); the body is a braced block of ≥2 statements whose FIRST is a single-variable `var`/`final` (annotated or not, no multi-declaration comma) initialised by exactly `X[i]`; `X`'s LENGTH cannot move — every mention of `X` in the body must be a READ of `length` on it or an index READ `X[e]`, so a call on it (`X.push(v)`), a method VALUE taken off it (`f(X.pop)`), a bare mention handed to a callee (`f(X)`), a write to it and a write THROUGH it (`X.length = 0`, `X[k] = v`, which on Haxe arrays EXTENDS) are all refused — because `0...X.length` evaluates the bound ONCE while `for (i => v in X)` re-asks the iterator every step, so an append would turn a terminating loop into a runaway one. That scan is a whitelist of two positions, and its limit is that it is BODY-LOCAL: an alias handed out before the loop, or a call that mutates `X` through a field the callee owns, is outside what a per-file check can see — which is part of why the rule is `Info` and opt-in. Also required: EXACTLY ONE `X[i]` (any other would have to become `v`, a rename this rule does not attempt); nothing writes `i` or `v`; no statement after the consumed declaration re-declares `i`, `v` or `X` as a local `var`/`final` (binders of other kinds — a `catch` variable, a lambda parameter, a case capture, a nested loop binder — are not scanned and need not be: each shadows the moved header binding exactly as it shadowed the block-scoped one); and `i`, `v`, `X` are three distinct names. No closure gate is needed, unlike the sibling rule: a block-scoped `final v` and a Haxe loop binder are both fresh per iteration. A container that RESOLVES to something other than `Array` is not reported at all (the message would name a form that does not compile for it); an UNRESOLVED one still reports, and there the FIX additionally needs the element type PROVABLE, since it drops the declaration and with it any annotation: `X`'s binding must be declared `Array<E>` and the annotation — when present — exactly `E`. A widening annotation (`Dynamic`, a supertype), or a comment anywhere in the replaced region THROUGH THE END OF THE DECLARATION'S LINE (so a trailing comment cannot silently migrate onto the loop header), leaves the finding report-only. A SECOND, NO-OPENER arm covers the body with no such declaration: `for (i in 0...X.length)` that reads `X[i]` at least once AND uses `i` somewhere else too (`_points[i].pos = value[i].clone();`) becomes `for (i => v in X)` with EVERY `X[i]` re-spelled `v` — N+1 splices, the header through the end of the range plus one per read, shared with `prefer-value-loop` as `ElementLoopRewrite.elementReadEdits`, so a braced and an unbraced body take the same edits. The binder is `ElementLoopRewrite.singularOf` of the collection name with its LEADING UNDERSCORES dropped first (`_points` → `point`) — the one derivation, `ElementLoopRewrite.binderFor`, both element-loop rules use — whose plural may be any camelCase WORD, the last plural one winning (`gridLinesVertical` → `gridLineVertical`; the rules are in `prefer-value-loop`'s row). Disjoint by construction from both neighbours: a body OPENING with the binding is the opener arm's whatever that arm decides (`LoopScan.opensWithIndexBinding`, the same predicate `prefer-value-loop`'s `claimedByKeyValueLoop` reads), and a body whose every read of `i` is an `X[i]` is `prefer-value-loop`'s (`countReads == collectIndexReads`, the exact complement). Gates (no finding when any fails): the shared header; the stable-collection whitelist — which is also what refuses an `X[i]` WRITE target (`X[i] = v`, `X[i] += v`, `X[i]++`), since the binder is a copy; no write of `i`; no binder of `i` or `X` in the body (`bindsName`), so an `X[i]` under a nested `for (i in …)` is not taken for this loop's element; NO CLOSURE mentioning `X` (`capturedByClosure`) — measured on `--interp` and js, `fns.push(() -> a[i])` then `a[0] = 99` after the loop reads `99` where the key-value form reads the element of the iteration that made the closure; and a container that resolves to something other than `Array`. REPORT-ONLY (the finding stands, the fix is refused) when the container is unresolved, when no binder is derivable or the candidate is TAKEN — spelled anywhere in active text of the LOOP itself (header and body, the binder's whole scope), or bound by a declaration VISIBLE where the loop stands (a parameter, an earlier local, an enclosing loop's binder — asked through `ShadowingLocal.boundAt`, the same ancestor walk `shadowing-local` reports with; shadowing a name the body never mentions changes nothing the body reads, so this half is a readability refusal rather than a soundness gate), while a name bound only where the loop cannot see it — a sibling loop's own binder, a local of another block — is no clash; or declared as a member or module-level value anywhere in the file — and when the body holds a CALL THAT CAN REACH THE COLLECTION BEHIND THE LOOP'S BACK: a bare callee (an implicit-`this` method, a static, a local function), a `this.` / `super.` receiver, a static on an UPPER-initial receiver (`Main.grow()`, `pkg.Main.grow()` — a type, or a static constant; a static reaches a static collection, or a field through a singleton), and every `new` expression (a constructor runs arbitrary code — measured: `new Grower()` pushing onto `Main.sitems` turned `0=1;1=2;2=3;` into `…3=9;4=9;5=9;`). Such a callee can replace `X[i]` between the iteration start, where the key-value binder is read, and a later `X[i]` (measured: `replaceSlot(i); o += xs[i]` gives `1010;1020;1030;` against `10;20;30;`), or grow a field `X`, which the key-value iterator follows while the once-evaluated range bound does not (measured: 3 iterations against 6). The residual is stated precisely: a METHOD OF ANOTHER OBJECT THAT HOLDS A REFERENCE TO `X` (`value[i].clone()`, `sink.use(x)`) is admitted, as is a write through an alias made before the loop (`alias[i] = v` with `alias = X`) — the body-local limit the opener arm and `prefer-value-loop` already state. The opener arm takes the same gate (report-only): its binder is read where the declaration was, but a callee can still grow `X`, which the key-value iterator follows. The self-call gate is `ElementLoopRewrite.callsThroughSelf`, shared with `prefer-value-loop`, and it applies to a LOCAL or PARAMETER `X` as well as a field: measured on `--interp` and js, a parameter aliasing the field, a local initialised from it, a local stored into a field before the loop and a local captured by a local function the body calls bare all diverge (`1001;1002;1003;` against `1;2;3;`, a sum of `6` against `36`), and only a fresh local that never escaped is safe — telling it apart needs an escape analysis over the whole function, so the gate does not try. Every report-only finding of BOTH arms carries a `declineReason` naming its gate (no singular, the index, a reserved word, a taken name, a member of that name, an unresolved type, a call through the instance, a comment in a replaced region, and for the opener arm an element type the dropped declaration could change), which `lint --fix` prints instead of "withheld it, without saying why". With no binder the message reads "reads `X[i]`; it can be a key-value loop over `X`". The finding is spanned at the `for`

## `prefer-map-bind`

an array comprehension that maps each element through ONE call — `[for (x in xs) f(a, x)]` — replaceable with `xs.map(f.bind(a))`; `Info`. The loop binder must be exactly one argument, bare: in the last slot it is dropped (`f.bind(a)`), elsewhere it becomes `_` (`[for (x in xs) f(x, 2)]` → `xs.map(f.bind(_, 2))`), and alone it leaves the bare callee (`xs.map(f)`). A body that is anything else — an operator around the call, an `if`, a second loop — keeps the comprehension. The comprehension evaluates the callee and the other arguments once per element and `bind` once before the first, so both pass the proof `prefer-bind` gives a `() -> f(a, b)` wrapper: a literal or a local / parameter nothing writes, declared with a non-nullable type, and a callee proven a plain method (`PreferBind.partialApplication`). The iterable must be an `Array` (`List.map` returns a `List`, an iterator has no `map`) written as a postfix operand (an identifier, a member, a call, an index, a parenthesis). Equivalence assumes the callee does not resize the very array it is mapped over, and `o.m.bind(a)` reads `o.m` even when the array is empty. DEFAULT OFF (`DefaultOff`, a style preference: opt in with `"prefer-map-bind": { "enabled": true }`) and `RiskyFix`: a comprehension takes its element type from where it is written (`final ys: Array<Float> = [for (x in xs) f(x)]` with an `Int` result compiles) while `map` takes the callee's return type, which an invariant `Array` refuses — with a compiler oracle the rewrite stands where it compiles, without one the rule is report-only

## `prefer-map-literal`

an empty-argument `new Map()` / `new Map<K, V>()` replaceable with the map literal `[]`; `Info`, `--fix` rewrites it (same annotation caveat as `prefer-array-literal`)

## `prefer-range-loop`

a manual counter loop — a `var i = A;` (NOT `final`) immediately followed by `while (i < B) { … i++; }` — that a range `for` replaces: the user's rule is `for (i in A...B)` instead of a `while` with a manual `i++`; `Info`, REPORT-ONLY in v1 (the rewrite is sound only under every gate below, and several — `i`-not-read-after, no-other-write — are exactly the analyses most likely to hide a subtle bug, so the detector ships before the transform). The suggestion transcribes `A` and `B` verbatim from source as the range bounds. Grammar-agnostic over `RefShape.whileStmtKind` / `ltKind` / `postIncrKind` / `blockStmtKind` / `exprStatementKind` / `continueStatementKind` / `mutableLocalDeclKinds` (any unset → no-op), plus `identKind` / `writeParentKinds` (the write scan), `numericLiteralKinds` (a literal bound), `localDeclKinds` (the shadow gate) and `opaqueKinds` to skip macro reification. Soundness gates (all required): the declaration is a single-variable `var` (a `final` cannot `i++`, and a multi-declaration `var i, j = n` — top-level comma — is skipped) with one initializer child, the immediately-preceding block sibling of the `while`; the condition is exactly `i < B` with the loop variable on the LEFT (`i <= B`, a reversed `B > i` and a `!=` form are not a range); the body is a braced block whose LAST statement is exactly `i++;` (a `++i` / `i += 1` / `i = i + 1` is not matched) and no OTHER statement writes `i`; `i` is not read after the loop within the enclosing scope (a range `for` scopes `i` to the loop, whereas the `while` leaves `i == B` visible afterwards — positional `RefactorSupport.referencedInRange`); `B` is stable — a numeric literal, or a plain identifier that is not `i` and is never written in the body (`A...B` evaluates `B` ONCE, `while (i < B)` each iteration, so a call / field / array-access bound is skipped); the body contains no `continue` (which in the `while` form SKIPS the trailing `i++`, but in a range `for` advances — a `break` is fine); the body holds at least one statement besides the `i++`; and nothing in the body re-declares `i`. The finding is spanned at the `var i = A;` declaration

## `prefer-value-loop`

an INDEXED `for` whose index is never anything but an index into the collection it counts — `for (i in 0...X.length)` where every mention of `i` sits inside an `X[i]` — which Haxe writes directly as `for (v in X)`; `Info`, `--fix` splices the header and re-spells every `X[i]` as the binder. DEFAULT OFF (`DefaultOff`) — the two spellings are equivalent, so which one a project wants is a style choice: opt in with `"prefer-value-loop": { "enabled": true }`. The INDEX DISAPPEARS here, and every gate below follows from that: a rewrite that DELETES a binding owes COMPLETENESS about the name, not merely precision, which is the obligation its sibling `prefer-keyvalue-loop` does not carry. Disjoint from that sibling's NO-OPENER arm by construction (it demands a read of `i` outside every `X[i]`, which this rule refuses), and from its opener arm BY ENFORCEMENT rather than by shape luck: `claimedByKeyValueLoop` declines exactly what that arm claims — a braced body of at least two statements, opening with a single-variable `var`/`final` initialised by exactly `X[i]`, holding exactly one `X[i]`. The predicate must carry that claim ENTIRE and not just its OPENING, because the sibling's claim is NARROWER than the opening: deferring on the opening alone hands over loops the sibling then declines for one of its own gates (a second `X[i]`, a lone opener statement) and nobody reports them. The cost is stated rather than hidden — with `prefer-keyvalue-loop` disabled, a loop of exactly that shape is reported by neither rule — and a near miss stays here: a multi-declarator opener (`var v = X[i], w = 2;`) and an unbraced one are outside the sibling's claim, so this rule keeps them. A STATEMENT-POSITION `for` only: `ForExpr` (an array comprehension, a value-position `for`) is out of scope, as it is for the sibling. Grammar-agnostic over the shared `LoopScan` seams (as `prefer-keyvalue-loop` reads them) plus `intervalKind`, `stringInterpIdentKind` (the kind a `$name` read inside an interpolating string projects as) and the literal-text kinds `stringLiteralKinds` / `stringInterpTextKind`; any seam the scans cannot work without, unset → no-op. `length` is the one language-specific token, spelled as a constant. The HEADER is matched by `LoopScan.indexedHeaderOf`, shared with the sibling so `0...X.length` for a bare identifier `X` is ONE predicate for both rules; its arity check is also what rejects the key-value form the sibling PRODUCES, and it returns the body unexamined, because what a rule demands of a body is that rule's own claim and folding one rule's demand in there would make it everyone's. Soundness gates (all required): `X` is a BARE IDENTIFIER (a path receiver such as `a.b` is skipped — the type gate reads a BINDING's annotation); `X`'s LENGTH cannot move, by the same body-local stable-collection whitelist the sibling uses and with the same documented aliasing limit, because `0...X.length` evaluates the bound ONCE while `for (v in X)` re-asks the iterator every step; at least one `X[i]`; `i` and `X` are different names; and THREE NAME GATES that are COMPLEMENTARY, never layered redundancy — `LoopScan.countReads` equal to `LoopScan.countIndexReads` (every read of `i` is an `X[i]`), `LoopScan.bindsName` false for BOTH `i` and `X`, and a word-boundary TEXT scan of the body finding no other mention of `i`. None subsumes another, and each owns a slot the others cannot reach: a bare `'$i'` leaves NO standalone `i` token in the body bytes, so only the read count sees the `Ident` the grammar re-materialises for it; a binder the tree spells on a node of its own — a nested `for (i in …)`, a lambda parameter `i`, a `catch (i:…)`, a `case var i`, a key-value loop's value binder — reaches only `bindsName`, whose answer is a blacklist of the slots that provably cannot bind (the two READ kinds and the literal-TEXT kinds, so `'i'` is a string rather than a declaration of `i`) rather than a whitelist of the ones that can, since a binder shape a whitelist forgot lets an unsound rewrite through while an over-wide answer can only decline one; and what an `opaqueKinds` subtree PRUNES — a `macro` quotation, whose walk answers "the index is absent" where the honest answer is "unknown" — reaches only the TEXT scan, where a missed mention is a licence to DELETE the index. NOTHING text-scans `X` at all, so `bindsName` is the only gate against a body that REBINDS the collection. Both text scans run under `OccurrenceScan.inertMask`, hoisted once per file: the index scan passes the index-identifier spans inside the collected `X[i]` as its EXCLUDED set (those being the occurrences the rewrite itself re-spells), and `binderFor`'s candidate scan runs masked with no exclusions. What the mask removes from consideration is exactly the spans that cannot carry a read — line and block comments, a regex literal, and a string literal that does not interpolate — and `OccurrenceScan.literalInterpolates` gates on an ACTUAL `$` or a `DOLLAR_ESCAPES` spelling of one rather than on the quote character, so a `$`-free literal of EITHER quote style is inert and maskable while an INTERPOLATING single-quoted one stays visible whole, its bytes being a possible real read. Unmasked, a comment naming the index would silence the loop and one naming the singular would withhold the binder, both ordinary things to write over a loop body. One pathological FALSE decline is accepted rather than papered over: `macro $i{nm}` spells the reification marker with the same token a loop named `i` uses, and a macro body is active code no mask may hide. A container that RESOLVES to something other than `Array` is not reported at all, and that gate is load-bearing rather than decorative: `String` carries a `length` and is NOT iterable in Haxe, so `for (c in s)` does not compile and the advice would not either. An UNRESOLVED container still reports but is not FIXED. The BINDER NAME comes from `ElementLoopRewrite.singularOf`, an English identifier convention shared with the sibling's no-opener arm rather than a grammar seam, asked by `ElementLoopRewrite.binderFor` of the collection name with its LEADING UNDERSCORES dropped (`_points` → `point`, as in the sibling), over a name matching `^[a-z][A-Za-z0-9_]*$`, first rule that fires: a consonant before `ies` → `y` (`properties` → `property`, `bodies` → `body`); a vowel before `ies` → drop the `s`; `ses` / `xes` / `zes` / `ches` / `shes` → drop the `es` (`boxes` → `box`, `matches` → `match`); `ss` / `us` / `is` → NO singular (`class`, `status`, `axis` are not plurals); a trailing `s` → drop it (`points` → `point`); otherwise NO singular. The rules read the END of a prefix, and they are asked at every WORD END of the name — its end, and before every character that is not a lower-case letter (an upper-case letter, a digit, an underscore) — from the last end back; the first answer wins and the rest of the name is kept verbatim. So a plural at the end is answered exactly as the whole name always was, an earlier plural word is singularized in place when no later one is plural (`gridLinesVertical` → `gridLineVertical`, `itemsById` → `itemById`, `pointsScale` → `pointScale`, `points2d` → `point2d`), and a later plural beats an earlier one (`pointsLabels` → `pointsLabel`). Every ending is lower case, so a word closing on an upper-case letter is never plural (`useHTTPSList` has none) while an acronym taking a lower-case `s` is (`imageURLs` → `imageURL`, `userIDsByName` → `userIDByName`); a one-letter word needs no case of its own (`pointsX` → `pointX`). `RefShape.reservedWords` is the net under it, keeping out a derived name the parser would reject (`classes` → `class`, `news` → `new`), and two COSMETIC misses are accepted rather than answered with an exception list, since English has no orthographic rule separating them: `movies` → `movy` and `caches` → `cach`; reading inner words adds the same kind of miss for an `s`-final word that is no plural ahead of a non-plural tail (`posList` → `poList`, `wasVisited` → `waVisited`), none of which occurs among the loop findings of the haxelib corpus or of a large application corpus. Each costs an odd name, never a wrong rewrite: every collision gate below applies to the candidate as derived. REPORT-ONLY — the finding stands, the fix is refused — when no singular is derivable, when the candidate is a reserved word, when the body mentions the candidate in ACTIVE text, when the container is unresolved, or when a comment sits inside ANY region a splice would overwrite. The message says which case it is: a derived binder is named outright, and a withheld one reads "reads only `X[i]`; it can be a value loop over `X`", so the advice stays honest about the transform without inventing a name. The FIX is N+1 SPLICES per loop rather than one: `[for, end-of-range)` becomes `for (<binder> in X`, then each collected `X[i]` node's span becomes the binder. The closing paren and the body sit outside every span, which is why a braced and an unbraced body take the same edits, and `CanonicalEdit.dropContainedEdits` settles the set. The splices of nested loops never overlap — an outer header splice ends at its own range — but two NESTED loops that derive the SAME binder are not both fixed: every check reads the original source, so one pass would write `for (val in vals) for (val in vals)` and the inner binder would shadow the outer one. `ElementLoopRewrite.binderFor` therefore leaves a loop report-only when an enclosing or nested indexed loop, under either element-loop rule, derives the same name (by the same derivation, leading underscores dropped). Sibling loops are unaffected, each binder being scoped to its own loop. Two gates the key-value sibling's no-opener arm shares, both measured on `--interp` and js: NO CLOSURE mentioning `X` (`ElementLoopRewrite.bodyAdmitsElementLoop`, the body-gate chain both rules share; no finding) — `fns.push(() -> a[i])` run after `a[0] = 99` reads `99` where the value binder holds `1` — and a CALL THAT CAN REACH THE COLLECTION BEHIND THE LOOP'S BACK (`ElementLoopRewrite.callsThroughSelf`: a bare callee, a `this.` / `super.` receiver, a static on an UPPER-initial receiver — a type or a static constant — and every `new` expression; report-only, for a field, parameter or local `X` alike, for the escape reasons the sibling's row gives), since such a callee can replace `X[i]` after the binder was read (`1010;1020;1030;` against `10;20;30;`) or grow `X`, which `for (v in X)` follows (6 iterations against 3). Every report-only finding carries a `declineReason` naming the gate. The finding is spanned at the `for`

## `redundant-map-exists`

a map lookup spelled as a membership test plus an index read — `m.exists(k) ? m[k] : d` — replaceable with the null-coalescing lookup `m[k] ?? d`, halving the hash lookups; `Info`, DEFAULT OFF (`"redundant-map-exists": { "enabled": true }`), with an autofix that fires ONLY where a stored null value is proven impossible. ***The proof is the rule.*** The two forms diverge on exactly one input, a key PRESENT in the map whose stored VALUE is null: the ternary answers that `null`, `??` answers the default (measured on `--interp` AND `-cpp`, identical on both). So `MapValueScan` censuses the map binding and licenses the rewrite only when no null can reach it; where it cannot, the site is still reported, with a message saying so, and gets no edit. The census is a POSITIVE whitelist over EVERY occurrence of the binding — an occurrence is safe only as the declaration (with no initializer, or one that is `new Map()` or a map literal whose every entry value is a non-null LITERAL), an index read, an index write `m[k] = v` with a proven non-null `v`, the receiver of a Map member that can only read or REMOVE (`get` / `exists` / `keys` / `iterator` / `keyValueIterator` / `remove` / `clear` / `toString` / `copy`) or of `set(k, v)` with a proven non-null `v`, a `for` loop's iterable, or the left side of a whole-map assignment whose right side is a proven map expression. Everything else fails closed — an argument position above all, since `g(m)` hands the callee the same object to store a null through. The census is OWNER-scoped, not name-scoped, and that is load-bearing: a walk over every file MENTIONING the name reads a same-named binding in an unrelated type — or in the std library, which the resolution scope always carries — as evidence against this map (measured: 5 of 10 realistic map names, and EVERY single-letter name, refused on nothing but a std collision). So the reachable set is derived instead — a local is visible only in its own file, a non-public member only in its declaring file, its subtypes (`SymbolIndex.subtypeDeclMatches`, which is what sees a subclass constructor reassigning the inherited map) and an `@:access` grantee — and a public member, an `@:access` grant on the owner, a subtype REDECLARING the name and a `@:build` / `@:autoBuild` file each fail the proof outright. Whole-project scope required, exactly as `prefer-final-field` documents: over a narrower set a writer outside it is invisible, which is the UNSOUND direction here, so the rule is registered among the `--fix` loop's full-scope ids. Shape gates: the receiver must be a BARE IDENTIFIER whose declared type is the `Map` abstract (a path receiver names an object the census cannot follow), the two `m` and the two `k` occurrences must be textually identical, the key must be pure (it is evaluated twice by the ternary and once after; a call / `new` / assignment there means the original is already order-dependent), and a comment in either dropped region — `m.exists(k) ?` and the ` : ` — refuses rather than deletes it. A ternary fallback is parenthesized (`??` binds tighter than `?:`); nested matches flag outermost-first, the inner one on the next `--fix` pass. Sister forms NOT claimed, neither found in real code: `m.exists(k) ? m.get(k) : d` is `prefer-index-access`'s job one pass earlier, after which this rule matches; `!m.exists(k) ? d : m[k]` would add an inversion arm for a shape nothing writes. Requires `plugin is TypeInfoProvider`

## `redundant-map-iter-key`

a key-value `for` loop that discards its key with `_` (`for (_ => v in m)`), replaceable with `for (v in m)` since Haxe iterates values by default; `Info`, `--fix` drops the `_ => ` prefix — only where `ValueIterationProof` proves it: a std `Array` / `List` no import rebinds, not a reassigned local (`NominalTypes.valueIterationProvable`), or a std map (`Map`, `IntMap`, `StringMap`, `ObjectMap`, `EnumValueMap`, `BalancedTree` — `RefShape.keyedIterationTypes`, same gates, and no type outside the standard library extends a class a value of it may be: the type itself, and for `Map` each of `IntMap` / `StringMap` / `ObjectMap` / `EnumValueMap`, `RefShape.keyedIterationHolders`) whose loop BODY `MemberReach.mayMutateNamed` proves cannot change it: no `set` / `remove` / `clear` / `m[k] = v` on it, by its name or through any alias, in the body or anything it calls. A map's `keyValueIterator` re-reads each value by key, so an entry the body removes reads `null` there and the stale value through `iterator()`, and a replaced value reads new through one and old through the other; for a map nothing changes the two agree in values and order on `--interp`, js and hxcpp (measured, docs/decisions.md). The reach is asked by the fix only, so a map finding's message calls the drop conditional; any other answer leaves it report-only with the reach's reason as its `declineReason`, as is every other iterable (a type of unknown shape may have no `iterator()` at all), whose message describes the discarded key without recommending `for (v in m)`. A value-only `for (_ in m)` (no `=>`) is a legitimate ignore-value loop and is left alone

## `redundant-replace-loop`

a `while (x.indexOf(S) != -1) x = x.replace(S, B);` loop — redundant BY CONSTRUCTION, since `StringTools.replace` already replaces EVERY occurrence of `S` in one call (verified live), so the loop either does nothing extra or never stops. **DEFAULT OFF** (opt in via `apqlint.json` `"rules": { "redundant-replace-loop": { "enabled": true } }`, or an explicit `--rule`). Three arms. **Arm A — `S` and `B` both LITERALS, `B` does NOT contain `S`**: after one `replace` the guard is false, so the loop ran at most once; `Info`, `--fix` collapses the whole loop to the single unconditional assignment `x = x.replace(S, B);` — sound even for an input with zero occurrences, since `replace` returns a no-match string unchanged. **Arm B — both LITERALS, `B` CONTAINS `S`**: every replacement reinserts `S`, so the loop is INFINITE for any input that ever contains `S` — a real bug, `Warning`, report-only (there is no mechanical fix for "the author meant something else"). **Arm C — at least one of `S` / `B` is a PARAMETER of the enclosing function**: whether `B` contains `S` is the CALLER's choice (`replaceWord(line, 'a', 'aa')` loops forever, `replaceWord(line, 'a', 'b')` returns), so `Info`, report-only, with both operands' VERBATIM source in the message. That wording covers two parameters and the LITERAL `S` / PARAMETER `B` mix (`line.replace(' ', sep)`), where the literal says nothing about the caller's `sep`. **The reverse mix — a PARAMETER `S` with a LITERAL `B` — splits out of arm C, since the literal decides the verdict on its own** (arm C's phrasing produced plain nonsense on it: `stripWord(line, word)` looping on `line.replace(word, '')` was reported as "potential infinite loop when `''` contains word", though an empty literal contains no non-empty word and `replace(word, '')` REMOVES rather than reinserts). An **EMPTY literal `B`** makes the loop merely REDUNDANT — one `replace` deletes every occurrence, so a single unconditional assignment does the same work; `Info`, still REPORT-ONLY, because `indexOf('') == 0` means the ORIGINAL loop spins forever on a degenerate empty `S` while the collapsed form returns at once, and no autofix may silently trade a hang for a return (the message carries that hazard for the same reason). Being a redundancy verdict rather than a hazard one, it is the single arm no dominating guard suppresses. A **NON-EMPTY literal `B`** keeps the infinite-loop finding but states its condition exactly — the loop runs forever for precisely those `S` that occur in that literal, the equal `S == B` included, with the literal quoted verbatim — and keeps the full dominating-guard treatment (a containment guard suppresses it; an `S == B` equality guard rules out exactly one offending `S`, which its caveat clause says in those terms). The guard accepts three spellings of "does `x` contain `S`": `x.indexOf(S) != -1`, its reversed operand order `-1 != x.indexOf(S)`, and `x.contains(S)`. Each of `S` (the guard's argument AND `replace`'s first) and `B` (`replace`'s second) must be EITHER a plain string literal (`StringFoldSupport.literalOf` — no interpolation) OR a bare identifier bound to a PARAMETER of the enclosing function or LAMBDA (`RefShape.functionKinds` / `lambdaKinds` + `paramKinds` — a lambda's parameters are just as caller-chosen as a method's); a field access, a call, an index access, a LOCAL `var` and an unresolvable identifier are all left alone. The two `S` positions must be the SAME thing (equal literal content, or the same parameter binding — a literal / parameter MIX across them is not a match). The receiver `x` must be a single identifier — never `this.x` / `obj.x` — bound to the SAME declaration in the guard, the `replace` call and the assignment target (`TypeResolver.identBindingFrom`), and that declaration must carry an explicit `:String` annotation (`TypeInfoProvider.declaredTypes`); an untyped or non-`String` receiver is a silent miss, never a wrong flag. The body must be EXACTLY the one assignment (braced or bare) — any extra statement means the loop is doing more. **Arm C's one static suppression is a CONTAINMENT test that DOMINATES the loop**: `if (B.indexOf(S) != -1) return …;` / its reversed order / `if (B.contains(S)) …`, read by the same `matchGuard` and held to the same operand identity, whose then-branch unconditionally exits (`CheckScan.branchAlwaysExits` — a `return` / `throw` / `break` / `continue`, bare or as the LAST statement of a block, so `{ trace(…); return line; }` counts). Dominance is walked structurally: from the `while` UP through the enclosing statement lists (`ControlFlowSupport.blockKinds`), reading only the PRECEDING SIBLINGS at each level. Preceding in the TEXT is not enough — a guard nested inside another `if`, in an `else` arm, in a loop or `switch` body, inside a `#if` region (one `Conditional` node, never a statement list, so it protects ONE target and would silence every other), or in a nested function or lambda nothing calls, may never have run when the loop is reached. An EQUALITY guard never suppresses: `if (S == B) return …;` rules out only the degenerate `B == S` while every `B` that merely CONTAINS `S` still loops forever — it reads like protection, which is exactly why the finding survives it and the message says so. Arms A / B are untouched by either guard (with two literals the verdict is already decided). Grammar-agnostic, and the optional seams fail in OPPOSITE directions: `functionKinds` / `lambdaKinds` / `paramKinds` ENABLE arm C (unset → arm C unreachable, literals-only behaviour), while `ifStatementKinds`, `controlFlowSupport()` and `eqKind` drive the SUPPRESSION (unset → arm C reports strictly MORE; `eqKind` alone only drops the message caveat). `opaqueKinds` subtrees (macro reification) are not descended into

## `unused-loop-binder`

a `for` binder (statement or comprehension) that nothing in the loop body reads; `Info`, DEFAULT OFF (like `redundant-property-access` and the other loop rewrites), `--fix` spells it `_`: `for (i in 0...n)` → `for (_ in 0...n)`, an unread VALUE `for (k => v in m)` → `for (k => _ in m)`. An unread KEY is dropped outright (`for (k => v in xs)` → `for (v in xs)`, both unread → `for (_ in xs)`) only when `ValueIterationProof` proves it: the iterable is a std `Array` or `List` (`RefShape.valueIterationTypes` — their `iterator()` and `keyValueIterator()` walk the same index / node chain, so values, order and mutation behaviour agree) that no project type, `import` of another module or import alias (`as` / `in`, `RefShape.importAliasKinds`) rebinds, and not a local or parameter WRITTEN anywhere in its scope (closures included) — a value loop over a local re-reads the local each step while the key-value iterator captured it once, so `for (k => v in zs) { zs = …; }` diverges; a field is cached by both. A std map under the same gates (`RefShape.keyedIterationTypes`, vetoed when a non-std type extends a class it may hold) qualifies too when, at fix time, `MemberReach` proves the loop body cannot change it — the shared proof `redundant-map-iter-key` uses; its finding says the drop is conditional, and a map the reach cannot prove is renamed instead. Any other iterable gets `for (_ => v in m)` / `for (_ => _ in m)`. RESIDUAL: an alias declared in an ambient `import.hx`. "Unread" is decided by BINDING: every occurrence of the name in the body (outside comments and inert literals, not a dotted member tail) must be a declaration token of an inner binding or a reference `Refs` resolves to a binding INSIDE the body, so a shadowing re-declaration frees the binder and a read of the binder itself, or of a name the resolver cannot bind, keeps it — except an unbound name inside a case PATTERN, which is a pattern binder or the wildcard. A structure field NAME (`{ i: 1 }`) is a label, not a read. Refused on sight of the name: a `$name` / `${…}` interpolation, an unparsed `#if` region, a `macro` reification, an `untyped` subtree, a native-code carrier (`NativeCodeScan`: `__js__` / `Syntax.code` / `@:functionCode` …), and a closure or local function (a closure mentioning the name counts as a read, whatever it binds). `_` is itself a readable binder, so the rename is also refused when the body reads a `_` bound outside the loop or one the resolver cannot bind (an inherited field `_`); `case _:` does not count. ONE OWNER PER BINDER: a key already spelled `_` is `redundant-map-iter-key`'s to drop (statement loops only — nobody drops one from a comprehension), while this rule still renames such a loop's unread VALUE, the two edits composing to `for (_ in xs)` / `for (_ => _ in m)`; a loop `dead-binder-counter-loop` claims (`DeadBinderCounterLoop.claimer`) is left to it, since its rewrite drops the counter and the binder together — with that rule disabled such a loop is reported by neither (a missed finding, not a wrong edit); `prefer-value-loop` / `prefer-keyvalue-loop` match only a READ index and `unused-local` never looks at a loop binder, so neither overlaps. `naming` / `no-underscore-prefix` do not flag a bare `_` binder

## `while-true-condition`

a `while (true)` whose ONLY exit is a `break` that dominates the top of the body, lifted into the loop header so the loop says where it stops; `Info`, `DefaultOff` (a readability rewrite, not a defect), with a `--fix`. THREE FORMS OF ONE REWRITE, positive criterion rather than a blacklist: (a) `while (true) { if (C) break; A }` → `while (!C) { A }` (generalised — a braced guard `{ B; break; }` lifts `B` out too), (b) `while (true) if (C) { A } else { B; break; }` → `while (C) { A }` plus `B` after the loop, and (c) its mirror `while (true) if (C) { B; break; } else { A }` → `while (!C) { A }` plus `B`. GATES, all syntactic: the loop condition is the literal `true`; the guard `if` IS the body or is its FIRST statement — the header evaluates `C` in the ENCLOSING scope, so the body must have bound nothing yet, and this one gate refuses the whole LOOP-AND-A-HALF family, where the condition is COMPUTED in the body before the break (five of the seven `while (true)` in the reference corpus, each measured refused); the exiting branch's LAST statement is a `break` of THIS loop and it holds no other jump of it; and the KEPT branch holds no `break` of this loop (in the original such a break SKIPS `B`, afterwards `B` runs). A `continue` in the kept branch is deliberately allowed — originally top → `true` → `C`, afterwards straight to `C`, the same order — as are `return` / `throw`, which leave the function on both sides; side effects in `C` need no gate, its evaluation count and order being identical. An `else if` chain in the exiting position FAILS CLOSED (its node is an `if`, not a block ending in `break`). The jump scan is `LoopScan.escapesIteration`, shared with `guard-continue`, and it DESCENDS into `switch` bodies — in Haxe a `break` there breaks the LOOP, measured on `--interp` — while stopping at a nested loop, whose own `break` binds to it. The fix re-emits exactly three verbatim slices (condition, kept branch with its braces, the exiting branch's statement run), so body comments, `#if` regions and nested loops ride along; a comment in a slot none of them covers keeps the finding report-only, the one exception being a trailing comment on the dropped `break` (`break; // done`), hoisted onto the last lifted statement. Grammar-agnostic over `RefShape.whileStmtKind` / `ifStatementKinds` / `breakStatementKind` / `boolLitKind` and `ControlFlowSupport.blockKinds()` (any unset → no-op)
