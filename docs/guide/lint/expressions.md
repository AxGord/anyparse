# `expressions` rules

Locals, statement syntax, lambdas, the shape of a call. One section per rule, by id; each rule's language, default and fix marker are in the [rule index](../../lint-rules.md#expressions), and a suite test fails when a registered rule has no section here or a section names no rule of this category.

## `empty-block`

an empty control-flow block — an `if` / `else` / loop / `try` / `catch` body written as `{}` with no statements (a comment-only block is left alone, an empty function body is not flagged) — purely structural; `--fix` removes the provably-safe subset (an empty `else {}`, and an empty no-else `if (cond) {}` with a side-effect-free condition), leaving an empty loop / `try` / `catch` body report-only. Disabled for a file whose `checkstyle.json` `EmptyBlock.option` is `empty` (the project deliberately allows empty blocks)

## `empty-statement`

a stray empty statement (a lone `;`); `--fix` deletes it (the whole line when the `;` sits alone, otherwise just the `;`) — purely structural

## `hoist-embedded-assignment`

an assignment written INSIDE a data structure — an array or object literal being built as one expression — hoisted in front of the statement, leaving the bare name where it was: `content = new Col([new Row([new Label(a), _headerLabel = new Label(b)])]);` → `_headerLabel = new Label(b); content = new Col([new Row([new Label(a), _headerLabel])]);`. `Info`, DEFAULT OFF (holding a handle while building a layout tree is a house style), `RiskyFix` (see below). THE SEPARATING GATE IS DEPTH, NOT THE SHAPE OF THE ASSIGNMENT, and getting that wrong breaks a living idiom: `_container.addChild(_dot = create(x, y))` is an assignment in value position too, and hoisting it doubles the block for nothing — the write is already in plain sight, one node under the statement's own call. Measured on the projected tree the two shapes are not near-misses: `c.addChild(_d = mk(1))` is `ExprStmt > Call > Assign` (depth 2) while `content = new Col([new Row([a, _h = new L(2)])])` is `ExprStmt > Assign > NewExpr > ArrayExpr > NewExpr > ArrayExpr > Assign` (depth 6, through TWO `ArrayExpr` levels). So the criterion is POSITIVE: at least one CONTAINER LITERAL (`arrayLiteralKind` / `objectLiteralKind`) must separate the assignment from the statement root — a call's own argument list is not a data structure, an array literal is, and an argument-position assignment at ANY depth of plain calls stays untouched. The descent to a candidate is a WHITELIST of eagerly and unconditionally evaluated construction kinds (call / `new` / paren / field-access / object-literal field / the two containers); every other kind ends the descent, and ends it by REFUSING the whole statement if an assignment hides anywhere inside it. That is what keeps three unsound hoists out without naming any of them: a lambda body (`new Button(() -> _x = f())`) would run the write at construction time instead of call time, a ternary / short-circuit arm (`[c ? (_x = a) : b]`) would make it unconditional, and a conditional-compilation region inside the literal would lift the write out of its `#if` guard so a build excluding the branch gains a write it never had. Two evaluation-order gates bound what the reordering can change: the target is mentioned EXACTLY ONCE in the statement (so no neighbour reads the handle being written, and two candidates can never name each other), and the only assignments in the statement are the hoisted ones plus, optionally, the statement's OWN root assignment — anything else refuses. That root assignment needs no gate of its own: an r-value is fully evaluated before the l-value is written, so a candidate inside it already ran before that write and still does. With several candidates ALL of them hoist in source order; `fix` declines a subset, which would reverse two writes against each other. The host is an expression STATEMENT or a LOCAL DECLARATION that is a direct child of a statement list — a brace-less `if (c) content = new Col([_h = …]);` has nowhere to put a second statement, and a multi-variable continuation is part of the declaration ahead of it rather than a statement of its own. `RiskyFix` because the hoist is structurally sound and still not type-NEUTRAL, neither reason provable from the tree: under STRICT NULL SAFETY a field read IMMEDIATELY after its own assignment is still narrowed, so a lone hoist typechecks, but the second hoisted statement resets the first field's narrowing and the literal then rejects the `Null<T>` read (measured on Haxe 4.3.7: `_a = new L(); _b = new L(); new Row2([_a, _b]);` under `@:nullSafety(Strict)` gives `Null safety: Cannot use nullable value of Null<L> as an item in Array<L>`, while the same code with both assignments inside the literal compiles); and a PROPERTY target with an asymmetric accessor pair changes value, since `_h = v` yields what `set_h` returns while the hoisted literal reads `get_h()`. The hoist tends to SHORTEN the code rather than lengthen it — dropping four indent levels let the motivating client site's string concatenation fit on one line, taking its `Label` construction from six lines to four, and collapsed a nine-line `new Row([…])` to one

## `join-declaration-assignment`

a bare local declaration immediately followed by its first plain `=` assignment, joinable into an initialized declaration — `var x; x = e;` → `var x = e;`; `Info`, `--fix` rewrites it (keyword and `:type` preserved; the `var`→`final` upgrade is `prefer-final`'s job, so a full `--fix` yields `final x = e;`). Also finishes `prefer-if-expression-assignment` (which leaves `var x; x = if (…) …`). Only the IMMEDIATELY following assignment to the declared identifier itself qualifies (not `x.f =` / `x[i] =`, not a compound op); a declaration that already has an initializer, a statement between the two (evaluation would reorder), an r-value referencing the declared name (`var x; x = x + 1;` — a self-reference), a multi-declarator `var a, b;`, and a comment in a dropped region are all safe misses

## `join-override-chain`

a local declaration followed by a CHAIN of conditional overwrites of that local — two or more consecutive statement-position `switch`es, each assigning it on some paths and leaving it alone on the rest — collapsed into ONE declaration whose initializer nests them, LAST construct outermost: `var k:String = null; switch a.e { case A(s): k = s; case _: } switch b.e { case B(i): k = '$i'; case _: }` → `var k:String = switch b.e { case B(i): '$i'; case _: switch a.e { case A(s): s; case _: null; }; };`. `Info`, `--fix` rewrites it; DEFAULT OFF, because the collapse REVERSES reading order (the last override is read first) — the honest shape of "later wins", but not every project's taste; opt in with `"join-override-chain": { "enabled": true }`. The MULTI-STATEMENT axis of the assignment-collapse family (`prefer-switch-expression-assignment`, `prefer-if-expression-assignment`, `prefer-try-expression-assignment`, `prefer-ternary-assignment`, `join-declaration-assignment`, `cond-assign-merge`): each of those collapses ONE construct and refuses this shape precisely because the target is written by several. The load-bearing gate is EVALUATION ORDER, not arm shape — the merge moves the LAST subject in front of every earlier one and makes each earlier construct reachable only on the fallback path, so an earlier subject may not be evaluated at all and an earlier arm value that used to be computed and overwritten is now skipped. Everything the run evaluates must therefore be PURE: the initializer (it moves from "always" to "innermost fallback only"), every subject, every guard and every arm value, judged by the index-backed `PurityScan` (a plain field read passes, a resolvable property getter does not) widened by ONE shape — a bare `$name` interpolation hole, a plain variable read that both shared purity predicates refuse because its kind is neither the identifier kind nor a safe-skeleton one; a `${…}` hole is an arbitrary expression and stays refused. Each construct must spell its no-match path as a completely EMPTY `case _:` / `default:` — that arm is the seat everything earlier gets nested into, and a construct writing on EVERY path would make its predecessors dead code (a `dead-store` finding, not a merge); must assign the declared local and only it in every non-empty arm, as a hoistable unit (a plain `x = <expr>;` leaf, or recursively a nested `switch` / `if`-chain whose every leaf assigns it), with at least one leaf; and must not READ the local anywhere, which after the collapse would be a self-reference in its own initializer. The run needs at least TWO constructs — one is `prefer-switch-expression-assignment`'s shape and is left there. Every write of the local inside the collapsed region must be one of the counted arm leaves; a write that OUTLIVES the run is fine and keeps the declaration `var` (that surviving write is exactly what makes the single-construct rules refuse the shape), while a run holding every write promotes `var` → `final`. A statement between two constructs, a multi-declarator `var a, b;`, an impure anything, and a comment in a dropped region are all safe misses

## `join-return`

a local declaration whose value is immediately returned, joinable to a single return.

## `join-single-use-local`

a redundant intermediate local: an IMMUTABLE single-variable declaration whose initializer is a TRIVIAL PURE READ and whose one and only reference sits in the immediately following sibling statement, inlinable into that statement — `final logoBmd:Null<BitmapData> = _userLogoBmd; logoBmd?.dispose();` → `_userLogoBmd?.dispose();`; `Info`, `--fix` deletes the declaration line and substitutes the initializer at the read. Such a capture is usually residue of the strict-null-safety idiom (a FIELD does not narrow, so `if (x != null) x.dispose()` needed a local); once `prefer-safe-nav` rewrites the guard to `?.` the capture buys nothing, and a later `--fix` pass removes it. The third `join-` member beside `join-return` (which joins a declaration and its next RETURN) and `join-declaration-assignment` (its next ASSIGNMENT); registry order between them is free, since this rule refuses a next statement of exactly `return <name>;` — that pair is `join-return`'s, which owns the annotation-ascription decision. FAIL-CLOSED GATES: the declaration is a single-variable IMMUTABLE local (`localDeclKinds` minus `mutableLocalDeclKinds` minus `localDeclContinuationKinds`) with exactly one child, the initializer — a `var` is out of scope, it can be written between the capture and the read — and it OWNS its physical line (`RefactorSupport.lineExtendedSpan` must widen its span), since the fix deletes that line whole, so a shared line or a trailing comment refuses; the initializer is a bare identifier or a dotted field-read chain over one, a strict WHITELIST that refuses calls, `new`, index access, literals, casts, operators, lambdas and safe navigation (substituting `a?.b` into `x.c` turns an NPE into a silent short-circuit); the local has EXACTLY ONE reference and it is a Read (shared with `join-return` through `CheckScan.soleReferenceNameFrom` / `escapesConditionalRegion`, so a name declared in two `#if` branches and read past `#end` is refused); the name occurs NOWHERE ELSE past the declaration in the whole enclosing function other than at that one read — `Refs` indexes ordinary identifier references and nothing else, so a braceless `$name` string interpolation and a macro reification `$name` (`DollarIdentExpr`) each read a local invisibly and the fix would unbind the survivor, and rather than enumerate those channels (a negative list that leaks by category) the gate is inverted: any node carrying the name is a use unless provably not one (the read itself, or a kind whose `name` is a MEMBER — field / safe / force field access, object-literal key). The scan is scoped to the enclosing FUNCTION, not to the statement list: under the branch-aware projection that list may be a synthetic `CondBranch`, which is NOT a Haxe scope — a local declared inside `#if A … #end` stays visible past `#end`, and a `$name` read there would sit outside a block-scoped scan; no identifier the INITIALIZER reads is re-bound between the declaration and the read (`final x = n; try p catch (n:Dynamic) use(x);` would become `use(n)` reading the exception — output that COMPILES and is silently wrong); a bare read of a MUTABLE local refuses, since under strict null safety Haxe narrows an immutable binding but not a `var` a closure captures, so `final b = best; b?.span` compiles where the inlined `best?.span` does not — found by running the rule over its own source; conditional evaluation of the read (an `if` branch, a `&&` / `||` right operand, a ternary branch, a `case` body) is ACCEPTED for a bare-identifier initializer, whose read has no effect at all, and REFUSED (`RefShape.branchKinds`) for a field chain, where moving the read under a condition stops an eager null-dereference from throwing and stops a property getter's side effect from running — which is what protects the narrowing shape `final x = field; if (x != null) x.m();`, two reads, until `prefer-safe-nav` has collapsed it to one; that read sits in the IMMEDIATELY following sibling statement (an intervening statement could mutate the source); the read is evaluated AT MOST ONCE, EAGERLY — no node from that statement down to the read may be a nested function (a lambda / local `function` / `inline function` defers it past the eager capture) or a loop (statement, `do … while`, or the expression-position `for` / `while` of a comprehension — each re-evaluates the read while the body may mutate the source in between), while CONDITIONAL evaluation (an `if` branch, a `&&` / `||` right operand, a ternary branch, a `case` body) is deliberately ACCEPTED, the initializer being a pure read; NOTHING IMPURE is evaluated before the read — every earlier sibling of every node on that path must be `RefactorSupport.isSideEffectFree` or itself a trivial pure read, so `_obj.m(x)` and `log(x, reset())` pass while `log(reset(), x)` refuses (an ancestor's own effect never matters: a call calls after its arguments); and the `:Type` annotation is not doing conversion work — unannotated always passes, annotated only when the annotation RE-STATES the initializer's own resolved declared type (`TypeResolver.identDeclaredTypeSource`, whitespace-insensitive), since an abstract `@:from` conversion (`final c:pkg.Color = str;`) or an upcast (`final b:Base = _derived;`) is real work the substitution would drop, and a field-access initializer has no ident binding to resolve so an annotated one is always refused. A comment intersecting the deleted line refuses; one BETWEEN the two statements, or anywhere in the next statement, rides along. NO PARENTHESISATION is needed or added — by the initializer gate the substituted text is always an identifier or a field-access chain, both maximal-precedence primaries

## `lambda-branching-body-braces`

an arrow lambda OUTSIDE the trailing argument slot whose body branches internally (if/else, switch) but carries no block — the braces delimit the branches from what follows the lambda.

## `narrow-local-scope`

a bare local declaration whose every occurrence sits inside ONE nested block, sinkable into that block — `var midPoint:Int; while (u - l > 2) { midPoint = (l + u) >> 1; … }` → the declaration moves onto the line above `midPoint = …` inside the loop; `Info`, `--fix` rewrites it. It does ONE job, the move: `join-declaration-assignment` then pairs the declaration with the assignment it now precedes and `prefer-final` upgrades the keyword, so a full `--fix` converges on `final midPoint:Int = (l + u) >> 1;` inside the loop. The shape is what `dead-store` leaves behind — a placeholder initializer written only for a reader is dropped, and the bare declaration then sits a scope wider than anything reads it. Costs nothing at runtime: hxcpp transliterates a declaration 1:1 into the C++ scope it was written in, so a loop-body `int` is the same stack slot the hoisted form got, and heap traffic comes from the INITIALIZER, which ran inside the loop in both spellings. The load-bearing gate is the FIRST occurrence: it must be the l-value of a plain `name = rhs;` that is a DIRECT statement of the target block, which is what makes the sink sound when that block is a LOOP BODY — sinking gives every iteration its own binding, so a value carried ACROSS iterations would be lost, but a write that is a direct statement cannot be skipped by anything that lets a later occurrence run (the only way past it leaves the iteration entirely), so every read the new binding sees is written in its own iteration. It also rules out reading the name before it is written, which the compiler rejects outright once the declaration is inside. The host statement list and the target block must both be a real lexical scope (a kind in both `blockKinds` and `scopeKinds`), so a `CondBranch` of the branch-aware projection can host neither. REFUSED: an initialized declaration (its evaluation would move), a multi-declarator `var a, b;`, no occurrence at all (`unused-local`'s finding), occurrences straddling two siblings, a first occurrence that is a read / a compound assignment / a nested write / an `m = m + 1;` self-reference, a `Decl` occurrence — the block already binds the name, and a `for` iterator and a `catch` exception are `Decl`s too, so one test covers all three — a function of any kind between the list and the block OR holding an occurrence (a closure captures one binding today and a fresh per-iteration one after the sink), a conditional-compilation region on the same path (the declaration would exist only in the configurations that region compiles), a textual occurrence of the name between the declaration and the end of its scope outside the target block (`RefactorSupport.referencedInRange` is the completeness net for the channels `Refs` does not index — a macro-reification `$name` splice above all), a declaration that does not own its physical line or carries a comment, and a target statement that does not start its own line. Disjoint from `join-declaration-assignment` by construction (a join needs the assignment to be the declaration's IMMEDIATE sibling in the SAME list) and from `prefer-local-function` (which needs its assignment reached without crossing a `scopeKinds` node — the target block is one)

## `prefer-arrow-callback`

an anonymous `function` literal in CALL-ARGUMENT position (`f(function() { … })`, `new T(function(x) { … })`), replaceable with the arrow form (`f(() -> …)`); `Info`. Argument position only — a local `function name() {}` statement and a `var f = function() {}` initializer are out of scope by policy. `--fix` is gated on the silent type-drift hazard (an arrow implicitly returns its last expression, so in a generic position like `array.map` the conversion changes the inferred type parameter while still compiling): a type-preserving body (explicit `return` tail, syntactically-`Void` tail, empty body — a `throw` tail is NOT preserving, the arrow form infers an open monomorph) converts structurally; an open tail converts only when the callee's parameter resolves through the SymbolIndex (member / static / constructor / local binding, supertype chain and typedef aliases walked) to a function type returning literal `Void`; a return that resolves to a callee type PARAMETER is proven generic and not reported at all; an unresolvable callee stays report-only. A single-expression or single-`return` block collapses to the bare-expression arrow; a stranded comment blocks the rewrite

## `prefer-bind`

a zero-parameter arrow lambda wrapping a single call with arguments (`() -> f(a, b)`), replaceable with the partial application `f.bind(a, b)`; `Info`, `--fix` rewrites it. A parameter-bearing lambda (`x -> f(x)`), a block body, and a zero-argument `() -> f()` are left alone. `.bind` evaluates the callee and arguments at bind time rather than call time, so the check fires ONLY when every argument is a stable value (literal, non-interpolated string, identifier / dotted chain, negated numeric literal) — an argument that computes or allocates (`new X()`, a call, `'id-$x'`, `a + 1`) keeps the lambda, whose deferred evaluation is load-bearing

## `prefer-final`

a local `var x = …` never reassigned in its scope, replaceable with `final`; `Info`, `--fix` swaps `var`→`final`. Reassignment is detected with the scope-resolved write walker (complete — every write is a structural `=`/`+=`/`++` node), so the fix is always sound. Only a single `var` with an initializer is a candidate (a no-init or multi-declaration `var a = 1, b = 2` is skipped); a never-read `var` is left to `unused-local` (the read gate keeps the two from overlapping); a generic-typed `var x:Map<K, V>` is conservatively skipped (its type-parameter comma is indistinguishable from a declaration separator without tracking `<>`)

## `prefer-lambda-expression-body`

an ARROW lambda whose `{ … }` body holds exactly one statement — a value `return e;`, a bare expression `e;`, or a control-flow statement (`if` with or without `else`, `switch`, `for`, `while`, `throw`) — collapsible to an expression body: `(a, b) -> { return a - b; }` → `(a, b) -> a - b`, `() -> { if (c) f(); }` → `() -> if (c) f()`; `Info`, `--fix` rewrites it. Type-preserving by construction: a Haxe block IS an expression whose value is its last expression, so `(v) -> { push(v); }` already has the same type as `(v) -> push(v)`, and every accepted control-flow form is itself an expression (`() -> { if (c) 1 else 2; }` and `() -> if (c) 1 else 2` both yield `1`) — none of the expected-type machinery `prefer-arrow-callback` needs applies here. The `function` literal is deliberately NOT matched: `prefer-arrow-callback` owns that node and normalises it INTO an arrow form, which this check then collapses on the next fixed-point pass, so one site is never reported by both. A value-less `return;`, a declaration, a `do … while`, a `break` / `continue`, two statements and a `#if` region (one `Conditional` child, no accepted kind) all fail closed; a comment anywhere in the block but outside the copied expression blocks the rewrite. The emitted control-flow text drops the statement's own terminator STRUCTURALLY (a node whose span ends where its last child's does hands the question down; a terminator-bearing kind yields to its child's end) — an interior `;` before `else` survives, a bare `switch`'s `}` survives, and a shape whose terminator is not recoverable (`while (c);`, `if (c) return;`, or a `#if` region on the tail, whose `#end` is mandatory and whose `;` sits ahead of it) is refused. A lambda reachable at the tail of the brace-less then-branch of an `if` that HAS an `else` is refused when its body holds an else-less conditional: `if (x) cb = () -> { if (c) g(); }; else h();` collapsed would re-parent `else h()` onto the inner `if`, a semantics break whose output still parses. A `#if` region reaches that position too — its branches project as flat siblings, so a following sibling proves no separating token there and every child inherits the region's own exposure. The edit replaces the BLOCK's span only, so trailing trivia is untouched

## `prefer-local-function`

a function literal BOUND to a local — an anonymous `function (…) { … }` or an arrow lambda — rewritten into a local function DECLARATION sitting where the literal already was — `var handler:MouseEvent->Void; o.addEventListener(E.DOWN, handler = function(event:MouseEvent):Void { … }, true, 0);` → `function handler(event:MouseEvent):Void { … }` + `o.addEventListener(E.DOWN, handler, true, 0);`; `Info`, `--fix` rewrites it. Two entry shapes, one emitter: an ASSIGNMENT `name = <literal>` reached from a statement without crossing a `branchKinds` / `scopeKinds` node (so the literal is built exactly once whenever that statement runs) paired with an earlier BARE declaration of `name` in the same statement list, and a DECLARATION whose initializer IS the literal (`var g = function(x:Int):Int return x;`). Disjoint from `prefer-arrow-callback` / `prefer-lambda-expression-body` by construction: those own a literal that is a DIRECT call argument, and an assignment / declaration node always sits between here — which is exactly why the shape went uncovered. The gates come from the two ways a local function is NOT a variable: it cannot be reassigned, and it is invisible ABOVE its own declaration. Over the statement list that owns the binding (the exact extent of a Haxe local's scope) the check requires `name` to occur NOWHERE before the point the declaration moves to — this is what refuses the mutually-recursive-closure idiom (`var a = cast null; a = function() { … b … };`), whose whole reason for the `var` is the forward reference a declaration cannot express — to be WRITTEN only by the flagged assignment, and to be DECLARED exactly once. The declaration must be BARE or hold only the definite-assignment placeholder (`null`, `cast null`); a multi-declarator `var a, b;` never qualifies. EVERY parameter of the literal must carry a type: the expected type the declaration's annotation supplied is gone after the hoist, and an unannotated parameter whose body dereferences it no longer types (the RETURN needs no gate for a `function` literal — one with no explicit `return` is `Void` in both forms; a rest parameter is refused outright). A LAMBDA whose body is a BLOCK needs one more proof: `->` takes an expression and a block IS one, so its value is the block's last expression (`() -> { 5; }` returns `5`) while a declaration's block body has no implicit result at all (`function f() { 5; }` returns `Void`) — the hoist is allowed only where the declaration's written type names a `Void` result, and an unannotated binding proves nothing. A lambda's EXPRESSION body needs no proof: the emitted `return` carries the value over. The declaration's own annotation must be one the literal's signature REPRODUCES — absent, or a written FUNCTION type (a top-level `->`, so `Array<Int->Void>` / `Null<Void->Void>` do not count). A NOMINAL one is dropped silently and compilably: Pony's `var l:Listener1<Int> = null; l = function(n:Int):Void { … }` binds an abstract whose `@:from` wraps the literal ONCE, at the assignment, and hoisted, `l` is the raw function that every use site wraps again — so an `add(l)` / `remove(l)` pair that shared one wrapper stops doing so. When the assignment IS the whole statement the declaration REPLACES it (rewriting only the assignment would leave a `name;` no-op); a body that does not close on a brace regains the `;` its statement carried, and a lambda's expression body regains the `return` its arrow implied. A comment in a dropped span (the declaration statement, the `name = ` head, the initializer's `;`) blocks the rewrite, while one INSIDE the literal's body rides along with it; `opaqueKinds` subtrees are skipped whole. Composes with `join-declaration-assignment`, which claims the adjacent `var f; f = function(){};` pair first — this rule's edits are then deferred one fixed-point pass and land on the joined form

## `prefer-static-extension`

a STATIC UTILITY call on a configured module rewritable to extension-method style — `Lambda.map(xs, f)` -> `xs.map(f)`, `StringTools.trim(s)` -> `s.trim()`; `Info`, `--fix` rewrites it and inserts a `using <module>;` when the file lacks one. Configured per project (`"types"`, default `["Lambda", "StringTools"]`; `"addUsing"`, default true — with it false a file lacking the `using` is reported but never fixed, since the rewrite would not compile). A `types` entry may be QUALIFIED (`pkg.TextUtil`): the call site matches on the SIMPLE name, the full entry drives the `using` test / insert text / `knownExtensionMethods` lookup. Shape: a `callKind` whose callee is a `fieldAccessKind` over a single `identKind` named after a configured module, with at least one argument (a zero-arg `Ext.now()` has no receiver to move); the type identifier must not be VALUE-BOUND (a local named `Lambda` shadows the module), and when the grammar knows the module's extension methods the called method must be among them. THE SHADOW GATE is the heart of it: Haxe resolves an instance member BEFORE a static extension, so a receiver type (or supertype) declaring the same name — `Lambda.map(arr, f)` -> `arr.map(f)` silently becoming `Array.map`, which COMPILES while changing the result type — is dropped outright via `SymbolIndex.typeDeclaresMember` / `supertypeDeclaresMember`. A member reachable only through a link those two do not follow — a `typedef` alias, a `@:forward` abstract's underlying — is caught one gate later by `typeProvablyLacksMember` (which DOES follow both) failing to prove absence, and degrades to REPORT-ONLY rather than dropping. Likewise dropped: a `Dynamic` receiver (dispatches nothing at runtime) and a conflicting second `using` that could also supply the method (deliberate disambiguation). The receiver's nominal comes from `NominalTypes.expressionTypeNominal` in its DEEP mode plus `literalTypeNames` for a string literal — deep mode is what resolves a chain ending in a `using` static extension (`StringTools.endsWith(s.rtrim(), '()')`), a receiver that used to leave the site REPORT-ONLY. That includes an extension whose first parameter is `Iterable<A>` / `Iterator<A>` — the whole of `Lambda`'s surface — which every container in the language satisfies STRUCTURALLY and none by an `implements` clause, so `SymbolIndex.satisfiesIterable` / `satisfiesIterator` decide it by MEMBERSHIP (`iterator()` returning something that satisfies `Iterator`; `hasNext()` + `next()`) through the same supertype closure a member lookup walks, never by unification. That accept path carries one gate the nominal ones do not need: proving the receiver ITERABLE is not proving its ELEMENT type binds the signature, and a receiver nominal carries no element type, so it is taken only when the parameter's element is the signature's own FREE type parameter — `Iterable<Widget>` and `Iterable<Iterable<A>>` are refused, which claims `Lambda.map` / `array` / `list` / `has` / `exists` / `count` and refuses `flatten` (nested element), `filter` (std writes no return type at all) and `fold` / `foldi` / `find` (the answer names a bare type parameter or `Null<T>`, which resolves to no declaration and so degrades downstream). A container the index reaches only through a top-level `typedef` — `List`, `Map`, whose std modules re-point at a packaged type of the SAME simple name and import nothing — is followed by the alias's WRITTEN path (`TypeDeclInfo.aliasTargetRaw`), which is what the simple-name reduction beside it throws away; a `src/` module SHADOWING a same-named std one stays unproven, since two root-package declarations of the name make every simple-name resolution of it ambiguous. A ternary / `?.` chain / `Null<…>` type stays unresolved, as does a bare `this` OUTSIDE an abstract body — inside one it resolves to the underlying type the header names, since an abstract's own members are unreachable through `this` and the underlying type is what the shadow gate must weigh, and a NUMERIC literal is a deliberately skipped fixable class rather than an unresolvable one (`255.hex(2)` compiles fine under `using StringTools`, but `5.trim()` types as the float `5.` applied to `trim`, so safety depends on the literal's exact spelling), and an unresolved receiver or an unresolvable member closure degrades the finding to REPORT-ONLY with its own message. The fix emits TWO edits per site (delete `[call.from, recv.from)`, rewrite `[recv.to, rest.from)` to `.m(`), so nested candidates compose in ONE pass; a comment in either dropped region refuses the edit. The inserted `using` goes ABOVE any existing `using` run, never below: Haxe resolves static extensions in REVERSE declaration order, so appending would give the new module top priority and silently re-target the file's existing extension calls. When the module's WHOLE body sits inside one `#if … #end` region (a debug- or platform-only module, whose import run is inside the guard too), the insert joins THAT header rather than landing on an island between `package` and the `#if`, and a `using` already declared there counts as present — the same descent decides all three `UsingScan` questions. Three gates keep it sound: one region at the top level with no type declared outside it, the region declaring a type itself, and no `#else` / `#elseif` seam of its OWN (branches project as flat siblings, so an anchor cannot be told from one in another branch); any of them failing falls back to the top-level position. `fix` re-derives its gates against the plugin's RESOLUTION index in preference to the report-scoped one it is handed (the narrower scope would degrade every std-typed site to report-only). Blind spots: a fully qualified call site (`haxe.io.Path.withoutExtension(p)`) never matches the shape (the callee root is a field-access chain, not an identifier), and an `import.hx`-provided `using` is invisible. Requires `plugin is TypeInfoProvider`

## `redundant-lambda-wrapper`

ETA-REDUCTION: a lambda whose whole body is ONE call forwarding the lambda's own parameters, in order and nowhere else (`x -> f(x)`, `(a, b) -> f(a, b)`, `() -> f()`), rewritten to the bare `f`; `Info`, `--fix` rewrites it, default OFF. Readability only — on hxcpp the reduced form is measurably SLOWER, and the project's recorded position is that a codegen weakness is not a reason to write the worse expression. The callee must resolve to something whose VALUE equals the wrapper: a local function (not `inline`), a member of the enclosing type, a `static` of a type declared exactly once in scope, or a BINDER read on positive evidence — every binder of that name is a required parameter or a local declaration, each annotated with a function type of the same arity and every parameter positional, and the name is never written in the file. `prefer-bind` claims the disjoint zero-parameter-with-arguments case

## `redundant-parens`

parentheses that cannot affect the parse, in two shapes: one pair wrapped directly in another (`((e))` / `(((e)))`), and a LONE `(e)` in a DELIMITED position — a slot the surrounding construct already bounds on both sides, so no operator can bind across it (grammar-declared via `RefShape.delimitedAllChildKinds` / `delimitedTailChildKinds` and the existing condition seams: var / final initializer, assignment right-hand side, `return` value, call and `new T(…)` argument — never the callee — array element, object-literal field value, `if` / `while` / `do … while` condition). Precedence is irrelevant there (`f((a + b))` unwraps as safely as `f((x))`) but syntax is not: a construct that eats the slot's separator (`separatorGreedyExprKinds` — Haxe's `macro`-quoted declaration) and a reification whose arity depends on being un-wrapped (`spliceSensitiveExprKinds` — Haxe's `$a{…}`) keep their parens. `Info`, `--fix` unwraps to a single pair outside a delimited position and to nothing inside it (`final m = (-1);` → `final m = -1;`). A third shipped shape is PRECEDENCE-GATED: a lone `(e)` wrapping a TERNARY CONDITION (`(a < b) ? 1 : -1` → `a < b ? 1 : -1`) — an operand slot, not a delimited one, so the drop is proven per-content and fires only for a bare inner that binds strictly tighter than `?:` (`RefShape.ternaryConditionUnwrapKinds`), never for a loose or right-greedy inner (assignment, a nested ternary, an arrow, an `untyped` / `macro` / metadata wrapper) that would absorb the `? … : …` on unwrap. Left alone: the `switch` subject, `case` patterns and guards, and every operand of a unary or binary operator, where unwrapping re-associates (`(a + b) * c` ≢ `a + b * c`). One finding and one non-overlapping edit per site — the outermost paren of a chain is flagged and not descended into. Four further arms are OPT-IN per project and reach the OPERAND positions the shipped arms refuse, each replacing a precedence model with a per-site proof: `"atoms": true` drops a pair around an ATOM — a self-delimiting expression (`RefShape.atomExprKinds`: an identifier, `this`, a literal) or a chain of transparent links bottoming out in one (`RefShape.atomChainKinds`: a call-free dotted access) — which nothing outside can bind into, so it is inert in EVERY position (`(a) + c`, `-(a)`, `arr[(i)]`, `(g)(1)`, `c ? (a) : (b)`, and the common defensive divisor `(x - y) / (r.width)`); a call, an index or a `?.` step breaks the chain (`(a?.b).c` and `a?.b.c` disagree on the short-circuit) and a regex literal is excluded (its closing `/` welds onto a following `/` into a line comment). `"sameOperatorLeft": true` drops a pair around the LEFT operand of a binary operator whose content is a binary operator in the SAME left-associative precedence family (`RefShape.leftAssociativeBinaryFamilies` — Haxe `['Mul','Div']` and `['Add','Sub']`), which left-associativity already grouped that way, so `(a * b) / c` re-parses to the tree it had; the RIGHT operand is never a candidate (`a / (b * c)` is a different computation), families never mix (`(a + b) * c` stays), a parenthesized right operand VETOES the left one (`Math.abs((px - x) + (py - y - h))` — both pairs are one symmetry the author wrote and only the left is removable, so firing would leave the expression lopsided), and Haxe's `%` is in NO family — the language binds it tighter than `*` and `/` (`2 * 7 % 4` is 6) and the grammar models that as a prec-10 tier of its own for `%`, so `%` shares a tier with no other operator; a single-member `['Mod']` family is provable but not admitted. `"comparisonOperands": true` drops a pair sitting on EITHER side of a COMPARISON-tier binary operator (`RefShape.comparisonOperandHostKinds` — Haxe `Eq` / `NotEq` / `Lt` / `LtEq` / `Gt` / `GtEq`, the prec-5 value comparisons; `is` takes a type on its right and `...` abuts numeric-literal `.` lexing, so neither is a host) whose bare content is ARITHMETIC or a POSTFIX in/decrement (`RefShape.comparisonOperandUnwrapKinds` — Haxe `Add` / `Sub` / `Mul` / `Div` / `Mod` / `PostIncr` / `PostDecr`), a fail-closed whitelist of kinds binding strictly tighter than a comparison in Haxe AND in every C-family language, so `(px - x - w) > (py - y - h + r)` and `(a++) < 36` re-parse to the trees they already had on either reading. Both sides are judged TOGETHER: unlike `sameOperatorLeft` a parenthesized sibling is no blanket veto — one whose own content is on the whitelist is provable in its own right, so both pairs drop in the SAME pass; the veto fires only when the sibling pair is NOT provable, which is what keeps the arm from ever leaving a comparison lopsided (`(a - b) > (c ?? d)` keeps both). The BITWISE tier stays off the whitelist for CORRECTNESS — Haxe binds `&` / `|` / `^` tighter than a comparison but C binds them LOOSER than `==` / `!=`, so `(x & m) != 0` reads differently there without its pair, and that pair is cross-language insurance an author wrote on purpose; the SHIFT tier binds tighter than a comparison in C exactly as in Haxe and WOULD be provable on both readings, so it stays off on READABILITY alone — a shift operand is habitually parenthesized and the arm declines to take that away; the PREFIX `++x` / `--x` are provable too and stay off on a READABILITY ground of their own (`(++b) < 36` bare reads `++b < 36`), but only as a ROOT — unlike the leading minus, which `RefShape.unaryMinusKinds` refuses at any depth, a prefix in/decrement has no left-spine gate, so `(--b * c) > d` still drops; only the postfix spelling puts the operand first, and its own `++` / `--` token closes the content against a greedy tail; atom content is off it too — the `atoms` arm owns atoms, and the two converge over `--fix` passes. `"additiveOperands": true` is the same shape one ARM down: a pair on EITHER side of an ADDITIVE operator (`RefShape.additiveOperandHostKinds` — Haxe `Add` / `Sub`, the prec-8 tier) whose bare content is on the strictly tighter multiplicative tiers or is a POSTFIX in/decrement (`RefShape.additiveOperandUnwrapKinds` — Haxe `Mul` / `Div` (tier 9), `Mod` (tier 10) and `PostIncr` / `PostDecr`), which C agrees bind tighter than `+` and `-`, so `a * s - (w / 2.0)` and `(a++) + b` re-parse to the trees they already had on either reading; a chain's MIDDLE operand is reached on the same terms (an additive chain nests to the left, so a middle operand is simply the right child of the inner node), and the sibling SYMMETRY rule is `comparisonOperands`' unchanged — a parenthesized sibling that is itself provable (same whitelist, or an atom when `atoms` is on too) goes in the same pass, one that is not vetoes the drop, so `(a * b) + (c - d)` keeps both pairs rather than being left lopsided. Five exclusions, each with its own reason: SAME-TIER content (`a + (b - c)`, `a - (b + c)`) is out for CORRECTNESS — the drop RE-ASSOCIATES, changing float rounding and, under `-`, the value outright; content whose LEFTMOST token is a unary minus (`RefShape.unaryMinusKinds`) is provable and out on READABILITY, since the bare form reads `a - -b` — a LEFT-SPINE test rather than a root one, so `a + (-b * c)` is refused alongside `a - (-b)`, and `comparisonOperands` no longer drops `(-a) > b` either (a deliberate narrowing of shipped behaviour, one readability rule instead of a root test that could not see the nested case); the PREFIX `++x` / `--x` are left off on that same READABILITY ground (`a - (--b)` bare reads `a - --b`) but by the WEAKER mechanism of mere absence from the root whitelist, so — unlike the minus — they are not refused at depth and `a - (--b * c)` still drops; what that leaves on the whitelist is the POSTFIX spelling, which puts the operand first and whose own `++` / `--` token closes the content, so neither edge gate has anything to refuse; the multiplicative operators are deliberately NOT hosts — Haxe binds `%` tighter than `*` and `/` but C makes the three ONE tier, so a bare `a * b % c` reads `(a * b) % c` to a C-trained eye and the pair in `a * (b % c)` is what makes the two readings agree (the same cross-language trap as the bitwise exclusion above; `%` CONTENT under `+` / `-` is fine, C agrees there); and bitwise / shift are out on both sides for two DIFFERENT reasons — as CONTENT they bind LOOSER than the additive tier, so a drop re-associates outward, which the fail-closed whitelist settles; as HOSTS a drop would be provable (`(a * b) & c` bare re-parses to the tree it already had, here and in C) and they stay out on the READABILITY ground that keeps shifts off the comparison whitelist. Every PRECEDENCE-GATED slot — the three opt-in arms AND the shipped, default-on ternary condition — additionally refuses two things a content ROOT cannot see. A RIGHT-GREEDY TAIL (`RefShape.rightGreedyExprKinds` — Haxe's `untyped` / `macro` / `cast` / `throw` / `return` / `inline` prefixes, a metadata annotation, the function literals and arrow lambdas, `if … else` / `for` / `while` / `try` and the ternary's else branch): such a construct at the right edge of the content eats whatever followed the pair, so `a + (b * untyped c) - d` has an arithmetic root and still evaluates to 9 with the pair against 7 without. A METADATA PREFIX: this parser models `@:m` as wrapping everything that follows while the compiler binds it to the immediate primary, so a pair on the LEFT EDGE of an annotated expression is what holds the annotation over its operand — `@:privateAccess (a * b) + c` compiles and the bare form fails with `Cannot access private field`; a pair further right (`@:privateAccess a + (b * c)`) still drops. Both gates exist because a before/after AST comparison is BLIND to them — this parser's model of `cast` and of a metadata annotation disagrees with the compiler about exactly these extents, so both trees compare equal while the real ones do not (recorded on `HxExpr`'s `CastExpr` / `MetaExpr`). All four opt-in arms are additionally suppressed inside `RefShape.parenOpaqueSubtreeKinds` (a `macro` quotation, where a pair reifies as `EParenthesis` data; a case PATTERN, matched structurally) and at a direct child of `RefShape.parenRequiredHostKinds` (a `case` guard, a `switch` subject, metadata). Every arm refuses a pair whose parentheses are not flush against their content at each layer of the chain — the fix reproduces the content's source and drops the rest, so a comment between `(` and the expression would be deleted

## `redundant-this`

a `this.field` access whose `this.` is redundant — nothing in the enclosing member shadows `field`: not a local / parameter / loop or catch variable / local function, nor the three shapes that bind WITHOUT a named declaration node (a case-pattern capture, projected as a bare identifier inside the pattern or as a `case var x:` binder node beside it; the single bare parameter of a thin-arrow lambda; and the slots a binder header DROPS — the value of a key-value `for`, recovered from the header text) — and `field` is a member of the enclosing type, so it reduces to bare `field`; `Info`, `--fix` drops the `this.`. Membership is the same-file member scan first, then — on a miss — an in-scope `SymbolIndex` walk of the `extends` / `implements` chain (so `this.addChild(x)` in a class `extends Sprite` is flagged once OpenFL is in the lint scope). The membership gate is prove-or-stay-silent: it flags only on positive, UNAMBIGUOUS proof, resolving each supertype reference import / qualified-path aware, so a base outside the set, or a name that resolves to more than one same-simple-named type, stays silent — a `using` static-extension name (`this.getClass()` under `using Type`) is a member of nothing and is never stripped. A shadowed access (the `this.x = x` constructor pattern) is kept, and a compile-time `abstract`'s `this.field` (where `this` is the underlying value) is never matched

## `redundant-trailing-comma`

a `,` between the LAST element of a comma-separated list and its closing delimiter — `[1, 2,]`, `[k => v,]`, `{x: 1, y: 2,}`, `typedef T = {x:Int, y:Int,}`, `new D(1, 2,)`, `g(1, 2,)`, `function f(a:Int, b:Int,)`, `@:meta(a, b,)`, an enum constructor's parameter list. Haxe accepts one in every one of those positions and it means nothing there, so the removal preserves the parse AND the semantics (the positions that REJECT one — a type-parameter list, a `case` pattern list — never reach the check, having failed to parse). The third case — a separator that is MANDATORY after the last element — is declared out by `RefShape.mandatoryTrailingCommaChildKinds`: Haxe's anon-type extension entry, where `{> Base,}` compiles and `{> Base}` is `Expected ,` (with two entries only `{> A, > B,}` is accepted). The veto is keyed on the LAST ELEMENT, not on the host, because the same host mixes both — `{> Base, x:Int,}` ends in an ordinary field and its comma IS redundant. The writer already knows that fact from the other side (`anyparse.format.TrailingCommaPolicy`: such a construct never carries the removable flag), and the two layers must agree — a kind missing from the veto is a `--fix` that emits source the compiler rejects. Sibling of `empty-statement`'s absorbed `;`: the parser folds the comma into the HOST's own span, past its last child, so no node marks it and detection is span arithmetic rather than a tree walk. The trivia writer re-emits it verbatim for the literal hosts (`[1, 2,]` is writer-canonical), so before this rule the shape was invisible to BOTH `lint` and `fmt` — hence a lint rule with an autofix rather than a writer change, which would silently reformat every file carrying one. Two grammar-declared arms: `RefShape.trailingCommaHostKinds` names the hosts that OWN their closer as their own last byte, and requiring the comma to be the last significant thing before exactly that byte is what separates a trailing comma from a separator (a separator always has an element after it); `RefShape.paramKinds` reaches the parameter lists, whose host's span runs on past the `)` over a return type and a body, and whose closer is therefore asked of the source. `Info`, DEFAULT OFF (opt in via `apqlint.json` `"rules": { "redundant-trailing-comma": { "enabled": true } }`, or an explicit `--rule`) — whether a list ends on a comma is a project style call, not a defect, the same call `shorten-type-ref` makes about qualification, and anyparse's own house style KEEPS the trailing comma (1041 would-be findings across `src` + `test`). `--fix` deletes the comma — the whole physical line when it sits alone on one (no blank residue), otherwise just the comma; a comment between the comma and the closer is trivia and survives (`[1, 2, /* t */]` → `[1, 2 /* t */]`). Fail-closed misses: an empty list, and a `#if … #end` region as the last element — that region projects as one node ending AT `#end`, so the gap before the closer holds no comma, and the comma INSIDE the region is left alone (it terminates the list's last element only under some defines). For the hosts whose trivia the writer does NOT preserve (`Call`, `MetaCall`, an enum constructor's parameters) a finding can only appear in a file that is not yet writer-canonical, where `lint --fix` is refused by the canonical gate and `fmt --write` is the remedy — the report still names them so nothing is silently missed

## `redundant-void-return`

a value-less `return;` as the last statement of a function body — redundant, since control falls off the end to the same effect; `Info`, `--fix` deletes it (with its line). Only the body's final statement qualifies: a `return;` nested in an `if` / loop (where it guards the statements it would skip) and a value-returning `return e;` are left alone — purely structural

## `split-var-declaration`

a local declaration binding several variables in one statement, splittable into one declaration per statement — `var uid:StringBuf = new StringBuf(), a:Int = 8;` → `var uid:StringBuf = new StringBuf();` + `var a:Int = 8;`; `Info`, `--fix` rebuilds it. Each declarator is copied verbatim from its own source slice, so the keyword, a per-declarator `:type` and a bare (uninitialized) declarator all survive; the split is semantics-neutral because the declarators already evaluate left to right and a later one may still read an earlier one. The candidate gate asks the AST for a continuation node, so a comma inside a generic type (`var m:Map<Int, String> = null;`) — or inside a declarator's own value (`var a = f(1, 2), b = 3;`) — is not a declarator separator, and the rebuild walks the RIGHT-RECURSIVE continuation chain to the end (in `var a = 1, b = 2, c = 3;` the node for `c` is a CHILD of the node for `b`) so no binding is dropped. Safe misses: a comment overlapping the statement (nothing would be DROPPED — the slices cover every byte but the commas and the `;` — but a DANGLING line comment before the separator would swallow the appended `;`, so the veto stays blunt), a `#if` directive overlapping it (precautionary — every shape that would break the slice arithmetic is already a parse error), a statement with no trailing `;` (`{ var a = 1, b = 2 }` as a block expression's value), a reification subtree (`opaqueKinds`, matching `prefer-final` and `unused-local` — splitting there is churn no downstream check would follow, and the reified `EVars([a, b])` would become two nodes a macro can observe), a declaration that is not a direct child of a statement list (the bare body of an `if` / `while`, or a `case` branch's statement run — the first two would move the second declaration outside the branch, the third is merely not reached), and the `@:meta var a = 1, b = 2;` form, which IS such a child but projects as an expression statement rather than a declaration. A comment AFTER the `;` is outside the replaced span and stays on the last emitted declaration. Does ONE job — splitting — and thereby unblocks two checks that skip a multi-declarator wholesale: `prefer-final` upgrades each never-reassigned binding on the next pass (so one `--fix` yields `final uid:StringBuf = new StringBuf(); var a:Int = 8;`) and `unused-local`'s refusal to cut a binding that shares its declaration stops applying. Reads the BRANCH-AWARE projection, so a multi-declarator inside a `#if` region is split too

## `unnecessary-block`

a bare `{ … }` statement block written directly in a statement list (another block, a `case` / `default` arm body, or one `#if` branch's statement run) rather than used as a control-flow body, whose statements would read the same one indent to the left; `Info`, `--fix` unwraps it (splices the trimmed interior into the parent, so a comment anywhere inside the braces survives verbatim). Two common sources: the AS3-to-Haxe artifact `case X: { … }`, and this linter's own always-true-`if` fixes, which used to splice the body block whole. Three gates decide, and a block that binds nothing passes the last one trivially. The LONE gate refuses as soon as the container holds a SECOND bare block: a run of them is a sectioning device — the author is delimiting phases of a long body — and flattening one of a set destroys the scheme; one block among ordinary statements delimits nothing. The WEIGHT gate refuses past `CheckScan.BARE_BLOCK_MAX_STATEMENTS` top-level statements, where the braces start reading as a section marker rather than as noise around a couple of lines; the same constant gates the always-true-`if` unwrap, so the two fixers never disagree about one shape and emit what the other refuses to clean. The SCOPE gate refuses a block whose top-level binding carries a name already live in the frame it would unwrap into — Haxe permits same-scope shadowing, so a wrong unwrap COMPILES and no oracle catches it, silently rebinding every later read of the outer binding. The frame is read at the CONTAINER, not at the block: a block is itself a `RefShape.scopeKinds` node, so its own bindings are absent from the container's frame and a candidate never collides with itself. The binding set the gate reads is `ScopeFrames.bindingKinds` — `localDeclKinds` widened with the expression-position, static and function-declaration forms — and BOTH sides of the test read it, since a kind counted on one side only is a silent hole (`LocalInlineFnStmt`, the local-helper form this project's Haxe style prescribes, was exactly that). The body of an `if` / loop / `try` is never a candidate (its parent is the control-flow node, not a container), nor is `@:m { … }` (a metadata wrapper over a block EXPRESSION) or a metaprogramming-reification block. Both `run` and `fix` read the BRANCH-AWARE projection (`CheckScan.parseBranchAwareOrNull`), where every branch of a conditional-compilation region is its own `CondBranch` statement list: on the plain tree a block inside `#if … #end` has the `Conditional` node for a parent, matches no container kind, and was silently never flagged — which is exactly where the always-true-`if` fixer's leftover blocks accumulated, since that fixer sees inside a region and this cleanup did not. Each branch is its own container, so the LONE gate counts per branch; the SCOPE gate still reads the enclosing block's locals and the function's parameters (a `CondBranch` is NOT a `RefShape.scopeKinds` node, so a `#if` branch passes the frame through), while a SIBLING branch's bindings stay invisible — mutually exclusive configurations can never coexist. `fix` re-derives the gates from the re-parsed tree rather than trusting a violation span
