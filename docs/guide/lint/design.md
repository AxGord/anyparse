# `design` rules

Metrics, duplication, project contracts, concurrency. One section per rule, by id; each rule's language, default and fix marker are in the [rule index](../../lint-rules.md#design), and a suite test fails when a registered rule has no section here or a section names no rule of this category.

## `anon-type-dup`

An anonymous structure type written out at least `minOccurrences` times (default `3`) across the
lint run — a shape that has earned a name. `Info`, DEFAULT OFF and report-only: the typedef's name is a
human's choice, and `apq extract-typedef` performs the extraction. One finding per shape, at its
earliest occurrence, with the count and the number of files.

Shapes are compared structurally: field order, separators and whitespace do not matter, an optional
field differs from a required one, and nested structures compare the same way. A structure with
fewer than `minFields` fields (default `2`), one with an extension (`> Base`) or a `#if`, and the body
of a `typedef` itself do not count. The groups are cross-file, so lint the whole project: one file
alone shows only its own repeats.

```haxe
function a():{ x:Int, y:Int } …
function b(p:{ y:Int, x:Int }) …
var c:Array<{ x:Int, y:Int }>;   // one finding: 3 occurrences of { x:Int, y:Int }
```

## `complexity`

a function whose cyclomatic complexity exceeds the threshold — the built-in default (20), or a `CyclomaticComplexity` max adapted from a project's `checkstyle.json` (decision points: `if`/`while`/`for`/`catch`/`&&`/`||`/`?:`/`??`, plus a `switch` counted ONCE — cognitive-complexity style, identified by `RefShape.switchKinds` — rather than once per `case`, so a flat dispatcher / arg-parser is not a false hotspot; branches nested inside case BODIES still count) — report-only

## `duplicate-code`

a run of three or more consecutive statements that appears, identical up to whitespace, in two or more places within the SAME file — a copy-paste clone the user's rule says to always extract ("duplication is a bug, not a design choice"); `Info`, REPORT-ONLY (extraction is a refactoring — `hxq extract-method` — not a mechanical span edit). Purely structural (no type information). v1 scope, deliberate: IN-FILE only (cross-file clone detection is a future axis needing a project-wide index and noise control); WHITESPACE-ONLY normalization (statements compare by source text with every run of spaces / tabs / newlines collapsed to a single space and the ends trimmed — NO identifier / alpha-renaming normalization, so only exact-logic clones match and the check has zero false positives by construction; a comment inside a statement span makes it textually different — not a clone; a comment between statements is trivia and does not affect equality). A run is a maximal sequence of direct-child statements of a `ControlFlowSupport.blockKinds()` node (function body / nested block / block expression — the same seam `dead-code` uses); the two occurrences may sit in different blocks and different block kinds (a method body vs an `if` body). A five-statement clone is reported ONCE as its maximal run, not as three overlapping three-statement windows (span-containment drops the sub-windows). Occurrences of one clone family are NON-OVERLAPPING — the document-earliest is the original, each later non-overlapping occurrence is a finding, so three occurrences produce two findings and a self-repeat like `a; a; a; a` (whose only second window overlaps the first) yields none. Content gate: a run must total at least three statements AND at least 40 non-whitespace characters, so a triple of trivial one-liners (`i++; j++; k++;`) is not flagged. Runs entirely inside an `opaqueKinds` (macro reification) subtree are skipped. The finding is spanned from the first to the last statement of the duplicated run at the later occurrence, and the message points at the first occurrence's line. Grammar-agnostic: a grammar with no statement / block concept (a binary format) returns null from `controlFlowSupport` and the check is a no-op

## `duplicate-code-renamed`

The renamed reading of `duplicate-code`: runs of three or more statements that are the same
once every LOCAL name — parameters, locals, loop variables, `catch` binders, pattern captures — is
replaced by its position. Two copies that differ only in what their locals are called are one clone;
members, types, called names and literals must still match. `Info`, DEFAULT OFF and report-only:
renaming buys clones a reader may judge coincidental, and extraction is a design decision.

It is a separate rule id so its findings keep their own history and it can be switched off without
the exact reading. Everything else — block scope, layout-insensitive comparison, same-file and
cross-file passes, thresholds — is `duplicate-code`'s.

```haxe
for (item in items) { total += item.price; count++; seen.push(item); }
for (row in rows)   { total += row.price;  count++; seen.push(row); }   // one renamed clone
```

## `extract-repeated-expression`

A pure, non-trivial value expression that appears three or more times, identical up to whitespace,
within ONE function body — a candidate for `final x = <expr>;` so the value is computed once. `Info`,
report-only: whether the extraction reads better, and where the `final` goes, is the author's call.

A candidate is a field chain at least two hops deep, a call, or an index access; it must be pure (no
call that is not provably pure, no property getter). Repeats that sit in different branches of one
`if` / `switch` never run together and are not grouped; a method name in callee position and the
target of a write are not values; a shorter expression inside a longer repeated one is reported only
at the longer form. Occurrences must read one value: a write to any part of the expression between
two of them splits the group.

```haxe
w = layout.bounds.width * 2;
h = layout.bounds.width / ratio;
log(layout.bounds.width);   // reported: layout.bounds.width appears 3 times
```

## `listener-symmetry`

A listener method without its twin: a type declaring `add<Name>Listener` (or `…Listeners`) and no
`remove<Name>Listener`, or the reverse. Subscribing and unsubscribing belong together, and declared
side by side they keep each other in sync. `Info`, report-only. Three findings: the twin is missing;
the twin exists but only one of the pair is `static`; or the pair is valid but another member sits
between them.

The `<Name>` part is required — a bare `addListener` names no subscription — and interfaces are out
of scope, since they declare a contract rather than the helpers.

```haxe
class Button {
	public function addClickListener(f:Void->Void):Void { … }
	// reported: no removeClickListener
}
```

## `oversized-type`

a type declaration grown past a member-count or line-extent threshold — the first TYPE-level metric (the per-function checks cannot see a god-file): either limit trips ONE `Warning` on the type header naming every exceeded threshold — a decomposition candidate (see `hxq clusters`). Covers the grammar's class-like bodies (`RefShape.visibilityContainerKinds` — Haxe: class / abstract class / abstract; an interface / enum / enum abstract / typedef is deliberately out of scope — a grammar-sized enum is a definition table, not a decomposition candidate). Members are the type body's `RefShape.memberDeclKinds` children, `#if`-guarded members counted too (`RefShape.conditionalMemberKind` recursion, an `#if` and its `#else` branches all counting); modifier siblings are not counted. Both measurements count BEHAVIOUR: a CONSTANT is neither a member nor lines of its type, so a table of constants is not reported and a type mixing both is measured by its behaviour alone. A constant is a `static` final field with no accessor clause whose initializer is `inline` (the compiler refuses `inline` on anything it cannot fold) or a constant expression (a scalar or plain string literal, an operator or parentheses over constants, a name of another constant of the same type), or a value of an `@:enum abstract`; a `static var`, a property, an instance field, a function and a `static final` built at run time count as before. Every line of a type belongs to the member it ends (its doc, annotations and the blank lines above it), and a constant's lines are not counted except a line a behaviour member also starts on. Defaults 50 members / 2000 lines; an `apqlint.json` configures `maxMembers` / `maxLines` per rule. A type the project measured and keeps whole is GRANTED with a ceiling, `"grants": ["Renderer <= 71 members / 4150 lines: <reason>"]` (either ceiling alone is accepted, members first when both are given): the ceiling replaces the threshold for that type and dimension, so it is silent within it and reported again, naming the grant (`… (max 71) — beyond its grant 'Renderer <= 71 members / 4150 lines'`), once it grows past it. An entry with no reason, no ceiling (the earlier `Name: reason` shape, which silenced a type at any size), a ceiling not above the threshold, any other head, or a second grant for the same type is REFUSED: it grants nothing and is reported once per run as a file-less `Warning` saying how to write it. The reported span is the type's HEADER LINE only, so suppressing takes a deliberate `// noqa: oversized-type` on that line — an unrelated bare `// noqa` deep inside the body cannot silently swallow the type-level finding (with a whole-body span it would, and the god-files this check targets are exactly the ones that accumulate those). Report-only — splitting a type is a design decision (`hxq move-member` / `clusters` territory), not a mechanical autofix

## `owned-types`

a mention of a TYPE, or a read or call of a MEMBER, that the project's `ownedTypes` declaration gives to another layer, outside that layer's `owners` — `<path> belongs to <owners> — <why>`; `Warning`, report-only (`NoAutofix`), INERT until `apqlint.json` declares `ownedTypes`. A type is mentioned by an import / `using` (alias, field import and field wildcard included), by every type position `uses` sees (annotations, type arguments, heritage, `new T`, `cast(x, T)`, `x is T`) and by every expression naming it (`T.x`, a class value, a qualified `p.T`); a static member through its own type, an instance member through a receiver the shared typer types, a constructor through `new T`. What a name means is asked of `TypeNameBinding` / `TypeRefIndex` only: asked at the use site (a `#if`-guarded import decides a use in its own branch); bound elsewhere or bound by no tier is skipped, UNKNOWN is reported unless every candidate it may be is read and none is the owned type. Owners are qualified-name globs; the declaring module always owns its types (`docs/cli-query-tool.md` § "`owned-types`")

## `prefer-api-idiom`

adjacent writes of EVERY field a project-declared idiom names, on one receiver of EXACTLY the declared type, replaceable with the declared method — `p.x = a; p.y = b;` -> `p.setTo(a, b);`, `p.x = q.x; p.y = q.y;` -> `p.copyFrom(q);`; `Info`, `--fix` rewrites the window. INERT until `apqlint.json` declares the idioms, because the equivalence is the FRAMEWORK's and the project names it: `"prefer-api-idiom": {"idioms": [{"type": "openfl.geom.Point", "fields": ["x", "y"], "method": "setTo"}, {"type": "openfl.geom.Point", "fields": ["x", "y"], "copy": "copyFrom"}]}` (`method`: one argument per field, in the declared order; `copy`: one value of the type whose same-named fields are copied; `"subtypes": true` also accepts a subclass receiver, which a subclass's override of the method could otherwise falsify). Each idiom is checked against the resolution index first and dropped with one stderr line when it cannot be true: a type naming no single declaration, a field that is not a plain instance field (a property with an accessor, a static, a method), a method that is not an instance method of exactly that arity, a copy method that does not take the type; an entry the reader cannot parse is dropped the same way. The fix is safe BY DECLARATION (no `RiskyFix`); what the rule proves itself is the rest — the receiver's static type is the declared one (a local's or parameter's written annotation, or a field walked through the index; an unannotated local is refused), every receiver hop is a plain read (a getter would run a different number of times), every right-hand side is pure and none mentions a field written ABOVE it on ANY receiver (an alias reads the new value today and the old one in the call), no comment sits in the deleted bytes (a trailing comment on the last write included), and the window is not inside the declared type or a subtype (the method's own body would become a self-call). A partial write, an interrupted run or a compound `+=` is no finding; a longer run is matched window by window.

## `thread-safety`

config-driven thread-context analysis over the `CallGraph` — the two classic main-thread stall shapes: **(a)** a MAIN-context function directly calling a blocking `sink` — or handing one as a value to a call that runs it (`Lambda.iter(paths, File.getContent)`) — (chain evidence in the message), **(b)** a lock held across a call that transitively reaches a sink (`lockPairs: ["Type.lock/unlock"]`) — a function value handed on under the hold, there or deeper down, counts as run there when the call it is handed to runs it (`Lambda.iter(paths, load)`, a lambda, an unresolved call; not one a `spawns` / `marshals` call runs on another thread or a `registers` call keeps, nor one a project constructor only stores into a private `final` field — that value runs where the field is called; a public field, which std code may read as a structure's, or one the language calls by name — `iterator`, `keyValueIterator`, `toString`, `hxSerialize`… — keeps the value running where it is handed), as often as that call repeats it, reported when the main thread takes that lock somewhere and something can be waiting for the hold: a hold of a named lock that only the main thread runs (no background context, and a holder the walk reached rather than assumed) is no wait of the main thread's — it stays only when the main thread itself works long under the lock (a long sink or a repeating short call; a take of another lock is a wait, never own work), with that said in the message. **Outer-lock dominance**: lock M is dominated by lock L when every long hold of M holds L on the same object at each call that makes it long (a must-held lockset: own takes on every path to the call — through statement sequences and `if`s a parameter valuation decides — and the locks every caller holds on the way in, carried onto the callee's `this` only through `this`, a bare `final` field or `this.f`; killed by a give on the way that does not return first, a call into a function giving L back without taking it, or an unresolved call when code one may run can); a take of M while L is must-held on M's object, or inside a hold of L itself, is then brief. A hold that may outlive its function, cannot be traced, releases a hold begun elsewhere or works an object no `final` member names breaks it; an unresolved call is a long point unless a bare `shortSinks` name (`"trace"`) names it and no loop under the hold repeats it. `--explain-long` lists each dominated lock (`dominated`). A hold is judged ACROSS its callees: its lock, on the object it is held on, is carried into every call made on that object — a stable field of the running object or a stable field of one (`fileSystem.cloudDatabase`; stable = `final`, or an instance `var` read with no getter whose every write sits in its type's constructor body itself on the running object — a write in a lambda or a local function the constructor makes, another object's write, or any write of a `static var` makes it unstable — judged only when the run sees every write of the project, `closedWorld` covering it (below); a REFLECTIVE write (`Reflect.setField` / `setProperty` / `deleteField` off `Reflect`, as a `using` extension or handed on as a function value — `final set = Reflect.setField`; `DynamicAccess.set` / `remove`; `o[key] = v` into any value not declared an array, a map, a vector or a buffer — `untyped`, a cast to `Dynamic`, an unknown container) unsettles a `final` too — a literal name the field so named, a computed name every field — of every class of its target's class family (the class, its subclasses, the types on their chains), or of every class when the target's type places it on none (`Dynamic`, `Any`, a type parameter, a structure, an abstract, a library or unknown type); one index of the run's writes answers it, `FieldWrites`) — so a take there of a lock it dominates, or a re-take of a `reentrantLocks` lock, waits for no long hold; a callee that may give the lock back (or run unknown code that can) carries nothing. **Repetition has an owner**: a main-thread call of a short sink that is long only because a caller up the main thread's way repeats it is reported at `info` ("long only as repeated by X"), and the warning goes to EACH nearest repeating call — the ones at the least distance up its ways, a farther one counted in the note — its loop, recursion or a call handed a value it may repeat, keyed by that call's member and a NAME (one warning per call site, never one per loop above it); a call its own member repeats keeps its warning. Owners of one distance are ordered a way through calls alone first (one through a value handed on after), then by file, offset as a NUMBER, and target. Holds (b) are not moved: a hold spanning a repeated call is long whoever owns the loop. Repetition up the main thread's way is read over its STATES (a function under the values its callers hand its tracked parameters): a call a condition rules out under a caller's constant carries no repetition from that caller, and the owner is found only on ways that run the call. A hold only the main thread runs whose every long call finding (a) already warns of (the sink's own call, or the repeating call owning it — the holder's own included, such as a loop moving items one call at a time) is `info` — the main thread's own work is (a)'s. A hold taken inside a hold of the same lock every caller keeps (must-held at its take, over every state of its function) is `info` too: the enclosing hold's window spans the call into it. **Folding** (one warning per root cause, the rest kept at `info` naming it): a call a sink's own body makes — or a function only sink bodies call — is that sink's machinery (`GateMutex.lock`'s `Lock.wait`); every main-thread take of one named lock waits for the same holders, so one warns — the take inside a lock wrapper of it when there is one, else the first by member, file and offset — carrying what repeats each of the others; a hold taken inside another warned hold of the same function whose long calls that window spans too is the outer hold's finding — and so is the later of two holds one call of a multi-lock helper opens (a helper that takes a batch lock and then a mutation lock: the mutation lock after the batch lock), when its long calls are the window's too: the lock the helper takes first keeps the warning. A sink reached through a shared callee is already one finding, at its call inside that callee. **Locks long on their own**, judged by cost: an unresolved call under a hold makes its lock long only when no bare `shortSinks` name makes it brief once under the hold (`trace`) and, over the normal paths, a `catch` does not run it; a hold its function never gives back — no give of the lock there, no call of a function releasing it without taking it, and a window spanning some call (a function that only takes the lock hands it to its caller) — hands the lock off past the function's end and warns whatever its window spans. **Compiler facts** (opt-in, `"compilerFacts": true`; one graph serves the whole run, so one chain asking builds it with the facts for every file, and chains of one run that disagree are said): the graph is read through the run's oracle facts when it has them, a value the facts record as made where the syntax hands it to a call taking no thread of its own from the maker; off by default because a call the facts describe carries no receiver field, so the locks its takes work go unnamed (always long). **Receiver flow from `new`**: on a hold's walk, a dispatched call runs only the overrides the classes of its receiver resolve to, where the code says them — the class a `new` names, the running object's handed down a call on it, or a field every value of which is a `new` the project writes (declared value included; through `?:` and conditional compilation); a library class never runs a project override — a class the run declares nowhere counts as one only when the run covers a closed project and the file names it by a path or a plain import (an import alias, a type parameter: unknown); a field's set is sealed only when the run sees every write of the project. Any other receiver is unknown and runs every override. The main thread's witness chains (finding (a)) are not path-filtered. **Rethrow**: a `catch` that throws its own variable again (`catch (e) { m.release(); throw e; }`) lets what its `try` raised go on, so the function raises for its callers (finding (c)); any other `catch` keeps the exception, and a project function whose throw is data-dependent can be named in `throwers` like a primitive. **Multi-lock helpers** (a function taking two or more locks for its caller, such as `lockBoth`): each call of one opens a hold of every lock it takes, judged in the caller exactly as a single-lock wrapper's take is — its own takes, and the gives of its releasing twin, are its callers' (no B at the helper, no crossing release by the twin), and the hold carries every lock that call took. A lock no sealed member names is told apart by its pair's take member: a hold of one is reported only when the main thread takes that pair somewhere. **Takes that never wait**: a lock only ever taken through a `sharedLocks` member (`"sharedLocks": ["utils.RwSyncMutex.lockShared"]`) — every take of it, wrappers and helpers included — waits for no one and stalls no one (no finding at its takes, no hold of it reported); a take of an instance's own lock in its constructor before the object escapes (`uncontended`) never waits either. **One warning per repeating site**: the loop, recursion or `iterates` call that repeats short sinks owns ONE finding (a), keyed by a name, never a position: the header of the loop that repeats it (`for (s in sessions)`, whitespace collapsed, `#2` for a second loop of one header in one function), else the call a value is handed to (`Node.forEachChild`), else the target of the recursion — never a lambda's `#n` its file numbers; its message names every short sink below it, and the calls ONE loop repeats share one. The sink calls one main-thread way into one function runs (same function, same main path; lock takes aside) make one warning too, at the first by offset of the calls the function makes itself — a sink it only hands on as a value, which may be stored rather than run, comes after them — the others `info` naming it. **One warning per root cause across holds**: a hold warning whose every long call over the normal paths (a call only a `catch` runs is no reason it warns) is long only through what another warned hold reports is `info`, naming them — a wait for a lock every hold making that lock long (over the normal paths) has its long work reported (its own warning, kept or folded, or the warning its `info` names), or a sink call another warned hold is long by too and NAMES (the first way of each of its calls: its warning shows no other) and makes its own work — a hold around it in its function, or one on its way to the call; a hold of the same lock in another function across its own call to that sink is a stall of its own — a call counts as covered only when EVERY blocking call it reaches on any way does, and a hold on the way covers it only when every way passes that hold's function — the ways of all the hold's calls together, so one call through that hold covers no other call reaching the same sink outside it; a lock long by a hand-off, an unresolved call, a release in another function (a multi-lock helper twin's give excepted: it is its caller's release, as for the long-lock solve), a hold with no finding or a re-take of the holder's own lock is not covered. A hold waiting for a lock some hold makes long with no finding reporting its work can never fold, and stays from the start, so the holds waiting for its own lock fold onto it rather than a cycle keeping one of them (a multi-lock helper waiting for its second lock, whose holders wait for a lock a directory listing holds). Holds covering each other round a cycle keep the one nearest its work (fewest calls), then the first by member, file and offset. A finding an inline directive silences (`noqa`, `CHECKSTYLE:OFF`) reports nothing: no finding folds onto it — a hold, a hold inside or enclosed by it, a way's or a lock's main-thread calls — and the work a main-only hold spans stays the hold's. A hold turned `info` onto a finding that ended `info` itself says so. **Bounded repetition** (`"repeatBudgetMs": 50, "boundedRepeats": [{"site": "store.Catalog.listChildren", "loop": "for (child in children)", "max": 500, "costMs": 0.1, "evidence": "…"}]`, positive): an entry names ONE member (`site`, no pattern) and binds ONE repetition of its code — the member's and the functions it defines: the only one there, the loop whose header `"loop"` spells, or the one around the call `"call"` names (the call handed a value it may repeat, else the innermost loop around it) — which runs as ONCE when `max × costMs` stays under `repeatBudgetMs`; a call several bound repetitions enclose in one function runs the PRODUCT of their bounds against the budget once, while repetitions in different functions on one way are judged apart. A nested, sibling or lambda loop the entry does not bind keeps repeating; an entry binding none or several, or malformed (a field of the wrong type, `max` or `costMs` not positive, a `site` naming no member or several, a `call` naming nothing, an unknown key), is dropped whole, never widened, with a config-level `info` naming why (the file-less channel a malformed `lockPairs` entry uses); an unlisted repetition or a rule with no budget keeps repeating (the evidence belongs beside each entry, as `evidence`, never in code). **Fixed flags**: a parameter that decides two or more `if`s and that nothing in the function writes is fixed for the run, so a hold's window is traced once per value of each (at most three): `if (flush) lock(); … if (flush) unlock();` no longer leaves a path that takes without giving back. A `throw` inside the body of a `try` with a `catch` goes to that catch, not out of the function. **Windows walk in place**: a local declaration's initializer and an array literal's elements are walked as the code runs them, and a `break` / `continue` is a jump inside its loop, never a path out of the function (a `final x = try … catch` that releases before it rethrows, a comprehension with a `continue`, no longer leave the lock held). **Exhaustive switches**: the catch-all (`case _`, `default`) of a `switch` over a CLOSED `enum abstract` whose every value an earlier case names is no path — the subject a member read bare or off `this`, declared as the abstract itself (not `Null<…>`); closed = no `from` clause, and every function of it that hands back the abstract (`@:from` ones included) hands back only its values. A `cast` into the abstract elsewhere is the one hole, taken as absent. **Catches no exception reaches**: a `catch` whose `try` runs only calls a `nonThrowing` entry names (plus literals, comparisons, reads of a name and a field read off such a call's value) is no path — its calls run nowhere (`"nonThrowing": ["FileSystem.stat"]`: hxcpp builds a zeroed record for a missing path). **Error paths**: a finding long only through a call inside a `catch` body — the hold's long calls, a main-thread take's lock, or the main-thread sink call itself — is `info`, naming the catch (`only on an error path (catch at file:line)`): the same costs solved over the normal paths, where a call a `catch` runs leads nowhere, find nothing long; a long reason outside every catch keeps the warning, and `--explain-long` marks such a reason with `errorPath`. Locks are told apart by OBJECT — the sealed member holding one (every value from a `new`, every read a method-call receiver, and no reflective write that may store a value in it: one naming it by a literal, or a computed name on a value of a class whose chain declares it); anything else is an unknown lock. A computed reflective write on a value the run places on no class (`Dynamic`, `Any`, an unbounded type parameter, a value the declarations do not type — a library container's element, an un-annotated local of a library call) may store any lock in any lock member, so it unseals every one — the sound default, said in one `info` naming the functions making them. What keeps such a value placed is a POSITIVE exclusion, named with its reason in a second `info`: a `final` local bound to a structure literal (no class's) or to `new C(…)` (`C`'s chain); a `case` capture, typed by the parameter of its enum constructor only when the switch subject is declared of that enum (read through the file's imports and typedef aliases, one type on every build) and the pattern is a top-level one of its arm — a constructor matched by name alone may be another enum's (a library `Option`'s `Some` beside a project `Some`), and a parameter of the enum's own type parameter types nothing (a `Map` capture's index write is then an element write, no reflective one); a type parameter bounded by its constraint, or — a class's own, under `closedWorld` — by every instantiation of the class: each subtype's binding through its `extends` chain (a written type, `Void` for none, a parameter of its own by its constraint; a class extending a typedef alias counts), and the class itself or a subtype leaving the parameter free only when never made: no `new` of it and its name read as no value under any name a file means it by (an import alias, a typedef alias, a guarded import, a wildcard), no literal naming it handed to `Type.resolveClass`, no `new` of a name that resolves to no type (a type parameter, a typedef of a name declared nowhere — it may be an alias of any), and the top-level `reflectiveClasses` declared alike by every file of the run without naming it. An unplaced write still costs only the lock members what it STORES may be a lock of: nothing for a delete or `null`, a literal's type, an enum (asked of its declaration's kind: a typedef of a structure holds any object with its fields, an abstract what it wraps), or a class or interface sharing no subtype with the member's declared type (a library one such as `Mutex` only through a project subtype, unless the value's own chain leaves the run; a declared type only under a covered `closedWorld`, never one whose outer name is a type parameter in scope at the value, and never that of a local, a parameter or a field — by name — some initializer or write hands an unchecked `cast`, an `untyped` or a `Dynamic`/`Any` value: such a type is a claim the compiler never checked); a parameter, `Dynamic` or `Any` included, by what every call of its function hands it, the argument at its index (any up to it after an optional parameter, a skipped one moving the rest along) and by what its function itself writes to it, closures included (an `=` or `??=` its right side, a compound assignment or an increment a value of its own type — a number for a `Dynamic` one; a write of any other shape makes it any lock), when every invocation is a call the graph holds — closed from outside, no value of it handed on, the top-level `reflectiveMethodHolders` declared alike by every file without naming its class or a subtype, and no string literal of the run spelling its name. Anything else (`Dynamic`, `Any`, a type parameter, a structure, an abstract, a cast, a reflective read) may be any lock. An `info` names the writes so kept off every lock member with what they store, another those storing a lock of some member's type. Each finding of a hold or take whose lock lost its member name to a reflective write says so after its message, naming the member and the writers; an `info` counts those holds and, beside an unplaced write, names the precondition of the instantiation bound the run fails (`no closedWorld over the whole project`, `no reflectiveClasses`). ## `typed-event-constant`

a `static` FINAL `String` constant (`static final` / `static inline final`, string-literal initializer) of a class extending the project's declared event base, USED as an event type — the first argument of a declared listener method or of a `new` — that the project's typed event-type abstract can type: `CLOSE:String` on `class ModalEvent extends Event` -> `CLOSE:openfl.events.EventType<ModalEvent>`; `Info`, a `RiskyFix` (report-only without a `compilerOracle`). INERT until `apqlint.json` declares `"typed-event-constant": {"eventBase": "openfl.events.Event", "typeAbstract": "openfl.events.EventType", "listenerMethods": ["addEventListener", "removeEventListener", "hasEventListener"]}`; the abstract is checked against the index first (a plain abstract of ONE type parameter over `String`, converting `from String` and `to String` — what keeps every comparison, `String` argument and `case` pattern compiling) and the rule is inert with one stderr line otherwise. A use the retype would reject is the finding worth having: a listener PROVABLY typed for another event class (a lambda's written parameter, a method of the enclosing type, a local or parameter of a written function type — a SUPERTYPE parameter is fine, function parameters are contravariant) or an event dispatched as a class that does not extend the constant's (`new Event(ModalEvent.CLOSE)`) is a `Warning` at the use naming both types, and that constant is never retyped. What it cannot type, the compiler decides: each constant is its own edit, spelled with the abstract's qualified path unless the file already resolves its simple name (`shorten-type-ref` adds the import), so the verifier's bisect reverts exactly the constant a listener rejects and the rest stay applied.
