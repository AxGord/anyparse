# `types` rules

Type positions, casts, is-checks, Dynamic, exception types. One section per rule, by id; each rule's language, default and fix marker are in the [rule index](../../lint-rules.md#types), and a suite test fails when a registered rule has no section here or a section names no rule of this category.

## `avoid-dynamic`

A raw `Dynamic` in a declared type position — a field, parameter or return type, a type argument
(`Map<String, Dynamic>`), or an annotated local. `Dynamic` switches static checking off at that seam;
each one is a candidate for a narrower type or for `Any`, the sanctioned top type that requires an
explicit cast to use. `Info`. `haxe.DynamicAccess<T>` and `Any` are not flagged; extern types are
skipped, since interop legitimately needs `Dynamic`.

The fix is a `RiskyFix`, applied only under a configured `compilerOracle` that typechecks each edit
and reverts a breaking one. It narrows a LOCAL to the one plain class / interface / enum every write
provably stores (an abstract or typedef is refused — its implicit conversions would change runtime
behaviour); moves a parameter's type into the signature when every read is `(p : T)` for one `T`;
and turns a local or private field used only through `Reflect.field` / `setField` into
`haxe.DynamicAccess<T>` with map syntax. Fields, returns and type arguments stay report-only. A local
initialized from `Reflect` / `Json` gets a separate "narrow where consumed" message. Options:
`excludePaths`, `excludeMeta`, `boundaryCalls` (default `Reflect`, `Json`).

```haxe
var item:Dynamic = new Item();  // --fix (with an oracle): var item:Item = new Item();
```

## `catch-dynamic`

a `catch` clause whose declared exception type is `Dynamic` (or `Any`) — a raw catch-all — or that declares no type at all (`catch (e)`); the rule is `catch (<name>:Exception)`, whose wrapper binds a richer, uniform API rather than the raw thrown value, and the message names the `naming` rule's `catchVarName` (`exception` when unset). `Warning`. The type is read from the clause header source (between the first `:` and the closing `)`, bounded by the handler block) and reduced to a simple nominal name (`TypeResolver.simpleNominalName`); a hit against `RefShape.catchAllTypeNames` (`Dynamic` / `Any`) is flagged, and only the parameter region is spanned. A typed catch of any other name (`Exception`, a custom class, `String`) is left alone; a non-nominal type (generic / function) yields no simple name → safe miss.

`--fix` has three arms, each spelling `Exception` short (adding `import haxe.Exception;`) or fully qualified on a collision or inside `#if`:

- (a) unconditional: a catch-all whose variable the body never mentions swaps its type to `Exception` — nothing reads the value, so nothing changes;
- (b) opt-in, `"catch-dynamic": { "fixLoggingUses": true }`: a catch-all whose value is only logged (interpolated, `Std.string`, `trace`) swaps its type and renames its variable to `catchVarName` (`exception` when unset), skipping a body that already reads that name. It is opt-in because `catch (e:Dynamic)` binds the RAW thrown value while `catch (e:Exception)` binds a WRAPPER: the logged text agrees on Haxe 4.1+, but that is a runtime claim the project accepts by turning the option on. Any other use of the value — a field access, a `throw`, an argument to another call — stays report-only;
- (c) unconditional: a bare `catch (e)`, implicitly `haxe.Exception` since Haxe 4.1, gains the `:Exception` annotation and keeps its name.

## `explicit-local-type`

A local `var` / `final` declared without a `:Type` annotation; fields, parameters and returns
are `explicit-type`'s. In Haxe even a literal is not self-evident (`5` may be `Int`, `Float` or an
abstract with `@:from Int`), so the rule asks for every binding to state its type. `Warning`, DEFAULT
OFF: a per-project style; opt in with `"explicit-local-type": { "enabled": true }`.

`--fix` annotates only where the initializer pins the type, so the annotation re-states what the
compiler already infers: a literal, `new T(…)` of a provably non-generic `T` (or with written type
parameters), a typed cast `(x : T)`, a homogeneous non-empty array literal, a `String` method with a
fixed return (`split`, `indexOf`), a known static call (`Date.now()`), an index into a written
`Map<K, V>` / `Array<T>`, or a read of a binding whose type is written. The type is printed short
when visible, with an added `import` when its name is free in the file, fully qualified otherwise.
Anything else (`null`, a ternary, a generic call) stays report-only.

```haxe
final parts = line.split(',');   // --fix: final parts:Array<String> = line.split(',');
```

## `explicit-type`

a member field with no `:Type`, a function parameter with no `:Type`, or a function with no return type; `Warning`. `--fix` fills the statically-certain subset: an initializer that is a literal (`String` / `Int` / `Float` / `Bool`), a `new T<…>()` with written type params, or a typed cast / check-type yields its `:T` — enclosing parentheses are peeled first, so `(-1)` pins the same `Int` as `-1`; a block-bodied function whose own scope holds no value-return and no throw (nested functions and lambdas do not count; a throw-only body unifies with any type) gains `: Void` — anything else stays report-only. A missing NON-`Void` return type has no structural evidence at all, so it is the `OracleAssisted` pass: with a `compilerOracle` configured, a warm display server is asked for the method's own type at its name token, the printed `(params) -> Result` is split at its parameter group, its COMPILER-QUALIFIED names are reduced to what a source file can actually spell — shared with `explicit-local-type` and `avoid-dynamic` inside `normalizeWith`, so no oracle consumer can skip it. Three unwritable forms: a CLASS type parameter (`pkg.Box.T`), a METHOD type parameter (`pair.U`), and a PRIVATE module type (`pkg._Holder.Entry`). An upper-case segment anywhere but last marks the class form, since a secondary module type comes out as `pack.Sub`; the method form is stripped only for a function that DECLARES type parameters; a private type is spelled bare when the annotated file IS that module (package path compared, not just the basename) and the whole annotation is REFUSED when it belongs to another module, which nothing can name from here. The result is then normalised / import-shortened exactly as before; any file whose annotations break the build is reverted to report-only. Without the key the pass never runs. A constructor (`new`) is exempt from the return-type rule and enum-abstract values from the field rule; interface members are checked like any other. Stating types everywhere is a documented project rule. The enum-abstract-value exemption follows `checkstyle.json` `Type.ignoreEnumAbstractValues` (default `true`; set `false` to flag untyped enum-abstract values too)

## `impossible-cast`

the cast-sibling of `impossible-is-check`: a runtime-checked cast `cast(x, T)` that can never succeed — `x`'s declared type `S` and the target `T` are two **unrelated classes**, so the runtime `Std.isOfType` test always fails and the cast can never yield a usable `T` (it throws for any non-null value, yields `null` for a null one); `Warning`, report-only. Only the runtime `cast(x, T)` form (`RefShape.checkedCastKind` = `TypedCastExpr`) is inspected — the compile-time `(x : T)` ascription would simply not compile for unrelated types. Same soundness and conservative skips as `impossible-is-check` (both sides a unique indexed CLASS, distinct, unrelated with fully-resolved closures via `SymbolIndex.unrelatedClasses`); operand type via `TypeResolver.identTypeName`, target via the shared `TypeResolver.castTargetWithin`. No non-null proof needed. Report-only: correct the type / drop the cast is context-dependent

## `impossible-is-check`

an `is` type-check `x is T` that is provably ALWAYS FALSE — `x`'s declared type `S` and the checked type `T` are two **unrelated classes**, so under Haxe single inheritance no value of `S` can ever be a `T`; `Warning`, report-only. Sound via the cross-file class hierarchy `SymbolIndex` already indexes: flags only when BOTH `S` and `T` resolve to a unique indexed CLASS decl (interface / abstract / enum / typedef on either side → open world or implicit conversions → skip), are distinct, and neither is a transitive supertype of the other with BOTH supertype closures **fully resolved inside the index** (`SymbolIndex.unrelatedClasses`). An unindexed supertype link (an external type, or a project file not in the lint set) makes the relation unknown → skip; generics / parametric / `Null<…>` / `Dynamic` operands or checked types never resolve to an indexed class → skip. No non-null proof is needed (`null is T` is also `false`). Every skip is a safe miss. Report-only: the dead branch's right rewrite is context-dependent

## `map-as-set`

a local or a non-public field declared `Map<K, Bool>` that is only ever a SET of its keys: every value it stores is the literal `true` (an index write, `set`, a map literal) and every use asks membership — `exists`, an index read, `get`, `keys`, `remove`, `clear`, `copy`. An `Array<K>` with `contains` says the same with no value to misread. `Info`, report-only, DEFAULT OFF: the rewrite trades a hash lookup for a linear scan, which is the project's call. The proof is the occurrence census `redundant-map-exists` already runs (`MapValueScan`, here under its key-set claim): a stored `false`, a value iterated (`for (v in m)`, `keyValueIterator`), `toString`, the map passed, returned or bound elsewhere, a same-named parameter in the file, or a member reachable from a subtype, an `@:access` grantee or a `@:build` macro all leave it alone. Only a written annotation is read; a nullable wrapper is not asked.

## `prefer-is-operator`

A two-argument `Std.isOfType(x, T)` whose second argument names a type, replaceable with the
operator it is the sugar of, `x is T`. `Info`, Haxe only; `--fix` rewrites the call, and is not offered
when the project's declared `languageVersion` is older than 4.2.

The rewrite is made only where both spellings mean the same: `Std` must be the standard library's,
and `T` a bare name that binds no value — `Std.isOfType(x, kind)` over a `Class<T>` parameter stays.
Parentheses are added where the operand or a surrounding `!` needs them. A call carrying a comment,
or sitting in a metadata argument or a macro reification, is skipped.

```haxe
if (!Std.isOfType(node, Group)) return;   // --fix: if (!(node is Group)) return;
```

## `prefer-map-type`

a concrete `haxe.ds` map type written where the unified `Map<K, V>` syntax says the same thing — `IntMap<V>` → `Map<Int, V>`, `StringMap<V>` → `Map<String, V>`, `ObjectMap<K, V>` / `EnumValueMap<K, V>` → `Map<K, V>`, in an annotation (field / local / parameter / return / type argument) and in `new T<…>()`; `Info`, `--fix` rewrites it, `RiskyFix` (verified under a `compilerOracle`, report-only without one). `haxe.ds.WeakMap` is never touched — weakly-held entries are different semantics. A bare `new IntMap()` becomes `new Map()` only when an annotation pins the target type (`NewLiteral.pinnedByTypeHint`, shared with `prefer-map-literal`). Gates, all fail-closed: the short name must be PROVEN to mean the `haxe.ds` type (exact `import haxe.ds.IntMap;`, `import haxe.ds.*;`, or a fully-qualified reference — a module-declared, aliased or foreign-imported name is not reported at all); `Map` itself must be free (a file binding `Map` elsewhere yields a report-only finding); an `ObjectMap` / `EnumValueMap` key must send `Map`'s `@:multiType` chain (`K:String` → `K:Int` → `K:EnumValue` → `K:{}`) back to that same implementation, so `ObjectMap<Dynamic, V>` / `ObjectMap<String, V>` stay report-only (rewriting them yields a StringMap — it typechecks and throws at runtime); `#if` regions and non-empty constructor arguments are skipped. Positions where `Map` cannot stand — heritage, `is`, `cast`, `catch`, `(x : T)` and type-parameter constraints — are not reported: a concrete map class used AS a class is correct code. Imports are never rewritten (`unused-import` removes the dangling one on its own evidence, and `prefer-map-literal` then collapses an annotation-pinned `new Map()` to `[]`)

## `prefer-typed-throw`

a `throw` of a raw string LITERAL (`throw 'boom'`, `throw 'bad $id'`) replaceable with the canonical typed form `throw new Exception('…')`; `Info`, DEFAULT OFF (opt in via `apqlint.json` `"rules": { "prefer-typed-throw": { "enabled": true } }`, or an explicit `--rule`). Only a literal / interpolated string operand qualifies (parentheses peeled) — `throw <expr>` of any other shape is out of scope, being neither provably a raw String nor movable into a constructor without an evaluation-order question. `--fix` replaces the literal with `new <exception>(<literal verbatim>)`, the exception reference spelled by `TypeRefPrinter`: the short name when the type is already visible, the short name PLUS an inserted `import haxe.Exception;` when that name is free in the file, else the fully-qualified `haxe.Exception` — a file that already binds `Exception` to something else is never retargeted; a throw inside `#if … #end` always emits the qualified path and adds no import (the `catch-dynamic` convention). FAIL-CLOSED GATE: boxing stops a `catch (e:String)` — and a `catch (e:haxe.ValueException)`, the wrapper the runtime builds for a RAW throw — matching at all, and rebinds what a `catch (e:Dynamic)` / `catch (e:Any)` body sees, so the check scans the PROJECT half of the resolution scope (report files UNION the configured library roots) for such a clause — textually, since a parse of every indexed source would dominate the run and an over-match only degrades further — and DEGRADES WHOLESALE to report-only when one exists (a source the index could not PARSE is unreadable rather than absent, so a skipped project file degrades too; the `--fix` fixed-point loop runs the rule full-scope every pass). The auto-discovered Haxe std is EXCLUDED from that scan (`StdResolver.isStdFile`, keyed off the same discovered `stdDir` the scope was built from, never a `/std/` path-string guess): a `String` / `Dynamic` catch inside std guards std-internal throws within std's own call boundaries, and a project throw boxed into `haxe.Exception` cannot change which std-internal throws those clauses see — scanning them only imported a verdict about code the rewrite can never reach, and since the std ships ~31 such clauses across 10 files (`haxe.ds.BalancedTree` catches `String`; `haxe.io.Bytes`, `haxe.io.BytesInput`, `haxe.Template`, `sys.Http` catch `Dynamic`) the rule used to be report-only on every Haxe-equipped machine. Two known unsound misses: a clause typed through a `typedef Raw = String` alias (the scan does not resolve names), and a project callback handed INTO std and invoked inside a std `try` (bought deliberately by the std exclusion)

## `redundant-ascription`

a parenthesised ascription `(new T(...) : T)` whose ascribed type restates the constructed class name — the construction already has type `T`, so the ascription is a no-op; `Info`, `--fix` unwraps it to the bare `new T(...)`. **DEFAULT OFF** — opt in per project with `apqlint.json` `"rules": { "redundant-ascription": { "enabled": true } }`, or select it with `--rule redundant-ascription`. **HARD BOUNDARY**: only a direct `new T(...)` operand (`RefShape.newExprKind`) is ever flagged — an identifier, a call, a field access, or any OTHER ascribed expression is left alone no matter how its written type compares, because an identifier ascription can be load-bearing null-safety narrowing a construction can never need (`new T(...)` is never null, so there is nothing to narrow) — proven on real code, where removing a `(x : Int)` narrowing a `Null<Int>` local for a non-null-typed object-literal field fails to compile. Comparison is byte-equal (`TypeResolver.stripWs` equality on the two WRITTEN forms) and deliberately NOT reconciled through the file's imports the way `redundant-cast` is — `(new haxe.ds.StringMap() : StringMap)` is a safe miss even though both spellings name the same type. The ascribed type must also carry NO type parameters (`indexOf('<') == -1`), kept as an explicit gate independent of the equality check even though `HxNewExpr.type` itself never carries `<...>` (its type arguments are the separate `params` field). The fix deletes exactly the `(` head `[node.from, operand.from)` and the ` : T)` tail `[operand.to, node.to)`, so a comment marker in either region suppresses the finding outright — a comment inside the constructor call's own arguments rides along verbatim in the replacement text

## `redundant-cast`

a typed cast whose target type already equals its operand's declared type — `cast(x, T)` / `(x : T)` where `x` is declared `T`, a no-op; `Info`, `--fix` unwraps it to the operand. Type-aware: the operand must be a plain identifier whose declared-type SOURCE is recovered (`declaredTypeSources`) and the cast's target-type SOURCE via `castTargetSources`; the two written forms are compared whitespace-insensitively. That is sound within one file — a byte-identical type spelling cannot denote two different types — so it distinguishes `Array<Int>` from `Array<String>` and `haxe.io.Eof` from `sys.io.Eof`, and the unwrap autofix is safe. The untyped `cast x` (no target type), a type mismatch, a non-identifier operand, and an operand with no recovered type are left alone. A bare name and its qualified spelling ARE reconciled when an explicit `import` justifies it — `import haxe.io.Eof; … final x:haxe.io.Eof = cast(e, haxe.io.Eof)` where `e:Eof` is flagged — via `TypeInfoProvider.importMap` (imported simple name → FQN) + `TypeResolver.canonicalTypeName` (qualified path = its own FQN, bare name resolved through the import map, sound because an unqualified name binds to one type per file). A bare name with no matching import (wildcard / implicit-std), or a differing-spelling generic, stays a conservative miss

## `redundant-cast-type`

a runtime-CHECKED cast `cast(e, T)` whose POSITION is already annotated exactly `T`, so the type argument only restates the annotation; `Info`, `--fix` rewrites it to the unchecked `cast e` (`final s:Sprite = cast(x, Sprite);` → `final s:Sprite = cast x;`). **DEFAULT OFF** — opt in per project with `apqlint.json` `"rules": { "redundant-cast-type": { "enabled": true } }`, or select it with `--rule redundant-cast-type`. Three positions, and the cast must be a DIRECT child of the position node (a cast nested in a larger expression — a ternary branch, an operand — is out of scope): **(a)** a declaration initializer carrying its OWN written annotation (`localDeclKinds` `VarStmt` / `FinalStmt` / `VarMore`, or `fieldDeclKinds` `VarMember` / `FinalMember`), the annotation read as the earliest `declaredTypeSources` entry in `[decl.from, cast.from)`; **(b)** a `return` (`valueReturnKinds`) under a function with an explicit return annotation — the enclosing function is threaded down the walk, a node that OWNS a function body sets it and a `lambdaKinds` node CLEARS it, so a lambda return always bails. The owner test is DERIVED (a `functionKinds` kind, or any node with a direct `functionBodyKinds` child) rather than an enumerated kind list, which is what reaches the nested forms no seam names — Haxe `LocalInlineFnStmt` (the `inline function h():T {}` local-helper idiom) and `NamedFnExpr` — each of which carries its OWN return annotation; enumerating kinds let their unannotated returns inherit the outer function's annotation. The annotation itself is told from a type-parameter CONSTRAINT — which projects the very same `Named` node in the very same child slot — by POSITION relative to the parameter list: with at least one declared parameter the test is purely structural (every constraint precedes the first parameter, so the sole annotation child starting past the LAST one is the return type, whatever the header contains); a PARAMETERLESS function has no such landmark, so the empty list's `)` is located in the text between the annotation and its preceding sibling, refusing outright when a comment sits in that window — a `)` can also live inside a structural constraint (`<A:{ function n():Void; }, B:Foo>`) or a header comment, and either would otherwise promote a constraint to a return type; **(c)** a call-argument slot whose parameter is written `T`, gated hard: the callee must be a bare identifier (a field-access callee `o.m(…)` bails) resolving via `TypeResolver.resolveBindingFrom` to the innermost same-named `functionKinds` declaration in this file, and EVERY parameter up to and including the slot must be plain required with NO default value — Haxe lets a call SKIP a non-trailing optional argument (`f(?a:Foo, b:Int)` accepts `f(1)`) and skips a defaulted `a:Int = 1` the same way even though it projects as required, so either ahead of the slot leaves the positional argument-to-parameter mapping unproven, and a rest parameter absorbs every remaining slot. An optional or rest BEHIND the slot cannot shift it and is fine. Type identity is `TypeResolver.sameTypeSource` — whitespace-insensitive exact equality on the two WRITTEN forms plus FQN reconciliation through the file's imports for plain nominals — so a generic matches ONLY its own token-identical spelling (`Map<String, Int>` vs `cast(v, Map<String,Int>)` yes, vs `Map<String, Float>` no) — a linter-level distinction rather than a shape real code carries, since Haxe itself rejects a parameterised checked cast (`Cast type parameters must be Dynamic`) — while `import haxe.io.Eof; … final e:haxe.io.Eof = cast(v, Eof)` reconciles. **Generics veto on the argument slot only**: the parameter type must be a plain nominal that a `SymbolIndex` DECLARES, since a type PARAMETER (`function pick<T>(v:T):T`) is declared nowhere — that vetoes the one shape where the argument's type would DRIVE inference rather than be constrained by it; (a) and (b) need no veto because their annotation FIXES the type. Consequence: a builtin-typed parameter (`p:Int`) resolves only when the std / configured libraries are in the resolution scope, a safe miss otherwise. A target whose outer nominal is `Null` / `Dynamic` / `Any` (`nullableWrapperTypeNames`) is vetoed — such a check never throws, so there is no runtime check to trade away. **Comment guard**: the fix deletes exactly the `cast(` head `[cast.from, operand.from)` and the `, T)` tail `[operand.to, cast.to)`, so a comment marker in EITHER region suppresses the finding outright (comments inside the operand survive verbatim). The unchecked `cast e` and the `(e : T)` ascription are different node kinds and are never touched; macro-reification subtrees (`opaqueKinds`) are not descended into. **Semantic trade-off** (measured on Haxe 4 `--interp`, user-approved): `cast(null, Foo)` and `cast null` both yield `null` and neither throws, so a null value behaves identically — but `cast(<a Bar instance>, Foo)` THROWS while `cast <a Bar instance>` silently yields the `Bar`. The rewrite therefore trades a runtime type check for brevity, confined to a NON-NULL type mismatch; that is exactly why it fires only on provably-annotated positions and why it is default off. Overlapping with `redundant-cast` / `redundant-upcast` needs no gate: `Cli.computeFileLintEdits` defers a later check whose edits overlap an earlier one, and those siblings delete the cast entirely — a strictly better fix that converges on the next `--fix` pass

## `redundant-is-check`

an `is` type-check `x is T` that is provably ALWAYS TRUE — `x` is a plain identifier whose declared type already equals the checked type `T` AND is provably non-null; `Info`, report-only. Shares the non-null prover (`TypeResolver.isProvablyNonNull`) and the written-source type comparison (`TypeResolver.sameTypeSource`, whitespace- and import-aware — so `e:Eof is haxe.io.Eof` reconciles via `TypeInfoProvider.importMap`) with `redundant-cast`. Non-null is REQUIRED — `null is T` is `false`, so a nullable operand's check is not constant. Only the always-TRUE, exact-same-type case is flagged: a subtype check (`x:Sub is Base`) is a safe miss, while the always-FALSE direction (two unrelated classes) is handled by the sibling `impossible-is-check`. A `Null<…>` / `Dynamic` operand, an optional param, a non-identifier operand, and a differing checked type are left alone. Report-only: the right rewrite (drop the `if`, keep the body) is context-dependent

## `redundant-unchecked-cast`

An unchecked `cast e` whose position demands exactly the type `e` is already declared to be —
the cast converts nothing and tests nothing. `Info`; `--fix` drops `cast` and keeps the operand.
The position is an annotated declaration, an annotated `return`, an assignment to an annotated
variable or a call argument whose parameter type is written; the operand is a local, parameter or own
field with a written type, and the two must be the same written type.

A cast between two different spellings is never proposed — that is what an unchecked cast usually
exists for (an `Array<CheckBox>` passed as `Array<DisplayObject>`). A cast into `Null<T>`, `Dynamic`
or `Any` is real work and is not reported, nor is a cast from an optional parameter (`Null<T>` inside
the body), nor one with a comment between `cast` and its operand — that is where an author explains it.

```haxe
final sprite:Sprite = new Sprite();
render(cast sprite);   // render(target:Sprite) — --fix: render(sprite);
```

## `redundant-upcast`

completes the cast triad (same type → `redundant-cast`, subtype → this, unrelated → `impossible-cast`): a runtime-checked cast `cast(x, T)` whose operand type `S` is a strict **subtype** of `T`, so the test always passes and the cast is a no-op upcast (an `S` is usable as a `T` without casting); `Info`, report-only. The subtype relation is `SymbolIndex.isSubtype` (extends + implements), so an interface target `cast(impl, I)` is flagged too. Only the runtime `cast(x, T)` form is inspected; operand type via `TypeResolver.identTypeName`, target via `TypeResolver.castTargetWithin`. No non-null proof needed (a no-op for any value). Report-only: an explicit upcast is occasionally load-bearing (overload disambiguation), so removal is left to the author

## `swallowed-exception`

a statement-context `catch` (`try { … } catch (e) { … }`) whose non-empty block silently swallows the caught exception — it neither references the exception variable, rethrows, nor returns (a generic log, an unrelated side effect) — `Warning`, report-only; purely structural. Only the statement form is considered: an expression-position try (`var x = try … catch (e) fallback`) recovers by producing the catch value and is never a swallow. Skipped: an empty catch (left to `empty-block`), a body that uses the variable (handled), a body that rethrows / wraps-and-rethrows or returns a fallback (deliberate escalation / recovery), a `_`-named variable (the explicit intentional-discard convention), and a body that only records the failure as an OUTCOME — every statement assigns a constant (`true`, `-1`, `'failed'`, `null`) with plain `=` to a `var` / `final` local, and each of those locals is read in a later statement of a statement list enclosing the try, inside the innermost function around it (`threw = true;` … `assert(!threw)`). Anything else stays reported: a field or parameter target, a computed value, a call or a nested statement in the body, a local read only before the try, in another branch arm, outside the closure the try sits in, or only through another declaration of its name

## `unreachable-catch`

a `catch` clause that can never run because an EARLIER clause in the same `try` already catches everything it would; `Warning`, report-only. Three covered-by relations: a **catch-all** earlier clause (`RefShape.catchAllTypeNames` — `Dynamic` / `Any` — or an untyped `catch (e)`, which binds the exception root); a **duplicate** (same written type source, reconciled import-aware via `TypeResolver.sameTypeSource` — so `e:Eof` and `e:haxe.io.Eof` match); and **subtype-after-supertype** (the later type transitively extends/implements the earlier one — `SymbolIndex.isSubtype`, the cross-file hierarchy the index builds). The exception type is recovered from the clause header source (between the first `:` and the closing `)`, bounded by the handler block); a non-nominal type (generic / function / anon) yields no simple name → safe miss; the subtype check is simple-name based (an unindexed supertype link ends the chain — a safe miss). Report-only: removing the dead clause vs. fixing its type / order is context-dependent
