# `literals` rules

Strings, interpolation, magic numbers. One section per rule, by id; each rule's language, default and fix marker are in the [rule index](../../lint-rules.md#literals), and a suite test fails when a registered rule has no section here or a section names no rule of this category.

## `fold-adjacent-string-literals`

a string concatenation whose segmentation does not match the file's own `maxLineLength` (read from its `hxformat.json`). Both directions, one decision: adjacent literals and expression operands MERGE into one interpolated literal (`"a" + "b"` → `"ab"`, `'a' + name` → `'a$name'`), and a literal operand that prints alike on every target merges as TEXT (`0 + ' ' + n` → `'0 $n'`, not `'${0} $n'`), and a literal whose line overflows SPLITS back out at its seams — a `${ … }` interpolation, or an embedded `\n` ESCAPE, which stays with the left fragment (`'one\ntwo'` → `'one\n' + 'two'`). The `\n` seam is what makes a lone over-long string TOKEN layout-fixable at all: the writer can wrap a `+` chain, nothing can wrap one literal. `Info`, `--fix` re-segments; the candidate is VERIFIED through the writer, so a plan is only applied when it actually narrows the construct. A merge runs unconditionally; a split or a same-count re-cut needs the source lines to be genuinely over-long. Skips: reification and annotation arguments, `case` PATTERNS and parameter DEFAULTS (a concatenation is not legal there), enum-abstract VALUES (folding one costs the type its `case` patterns), a comment inside an OPERAND's own span (a comment BETWEEN operands is not a refusal — it locks that group boundary, and the gap's source is re-emitted verbatim, so a chain whose every line ends in a `//` still folds the adjacent pairs inside each line), and an operand that cannot enter a `${ … }` block, or that carries the interpolation's OWN quote — `'a' + f('b')` stays a chain, because `'a${f('b')}'` compiles and is value-identical but puts a `'` two levels inside a `'`-delimited literal, and every highlighter that does not implement the `${ … }` re-entry loses the rest of the line. A MACRO argument is reported but not fixed — a macro matching `EConst(CString)` breaks silently on a concatenation — unless the macro is named in `concatFoldingMacros` (`["pkg.Type.method"]`, the claim being that it folds an `OpAdd` chain of constants before it reads the string). An argument of a target INTRINSIC — a BARE callee spelled with `__` at both ends (`__lua__`, `__js__`, `__cpp__`, `__define_feature__`) — is likewise reported and never fixed, and `concatFoldingMacros` does NOT lift that one: such a name resolves to nothing anywhere, which is exactly why the two resolution refusals above cleared it, and on Haxe 4.3.7 `untyped __lua__("{x=" + "1}")` compiles with NO diagnostic and emits `__lua__(Std.string("{x=") .. Std.string("1}"))`, a call to a function no runtime declares. The exemption there is a plan rendering as a compile-time CONSTANT — one group, every segment text — and not merely a one-group plan, since `'a$k'` is a `+` chain the parser desugared

## `join-string-append`

Two or more adjacent statements appending to the same local: a run of `x += e;`, or `x = e0;`
followed by `x += e;` lines. The run joins into one statement whose right-hand side is the sum of the
pieces. `Info`, DEFAULT OFF: a readability simplification; opt in with
`"join-string-append": { "enabled": true }`. A follow-up `fold-adjacent-string-literals` pass can
then fold the sum into one interpolated string.

The target must be a bare local name — a field or index target may run a setter. A later piece that
reads the target ends the run before itself, since the joined form would read the old value. The sum
must be type-sound: a string literal among the pieces, or a target declared `String` or `Int`; a
`Float` target is refused, since `+` does not associate under rounding. A comment the rewrite would
drop refuses the run.

```haxe
str = cname;
str += '.';
str += meth;
// --fix: str = cname + '.' + meth;
```

## `magic-number`

a numeric literal (`IntLit` / `FloatLit` / `HexLit`) used in logic — inside a function body — whose value is not a small conventional one, which should be extracted into a named constant; `Warning`, report-only (a literal cannot be auto-named). Exempt: the values `{0, 1, 2}` (a negative literal parses as a negation over a non-negative one, so `-1` / `-2` are exempt too), plus any number in the `magic-number` `ignore` array of a discovered `apqlint.json`; a literal outside any function (a member field initializer, an enum-abstract value, a typedef default, a metadata argument), a literal directly naming a local binding (`var x = 5000` / `final x = 5000`, which already is the named extraction), a literal in the index slot of a subscript (`args[3]` — a position, not a hidden quantity), a literal in a size comparison against a collection-`length` field (`args.length == 3` / `>= 3` — a structural element count) or in additive arithmetic against one (`s.length - 3` — a count offset), and a literal reaching a string-position method argument (`RefShape.positionMethodNames` — `substr` / `substring` / `charAt` / `charCodeAt` / `indexOf` / `lastIndexOf` / `hex`), directly or through `+` / `-` offset arithmetic (`s.charCodeAt(i + 5)`, `s.substr(0, 4)` — a position, not a hidden quantity), are left alone. A project `checkstyle.json` `MagicNumber.ignoreNumbers` (default `[-1, 0, 1, 2]`, compared by magnitude) replaces the built-in exempt base; an `apqlint.json` `ignore` list adds to it. `ignoreCallArguments` (a list of call names) exempts a literal that is DIRECTLY an argument of a matching call — `t('Complete with AI', 10233)` under `["t"]`, where the number is a key the callee owns; a negated literal is a direct argument too (`f(-18)` — Haxe has no negative literal), while one nested in an argument expression (`t('x', 100 + k)`, `t('x', make(5))`) stays flagged. An entry matches the TAIL of the callee as written, segment for segment: a bare `t` matches every call whose last name is `t` (`t(…)`, `Lang.t(…)`, `this.t(…)`, `make().t(…)`); `Lang.t` matches `Lang.t(…)` and `pkg.Lang.t(…)` but not a bare `t(…)` imported by name, so list the spelling the code writes. A CONSTRUCTOR is listed as `T.new`, the spelling Haxe gives a constructor used as a value: `SpriteDescriptor.new` reaches `new SpriteDescriptor(…)` and `new data.SpriteDescriptor(…)` (type arguments are no part of the path), while a bare `SpriteDescriptor` names a call only — nothing is exempt unless configured. A value object built in place as a listed argument carries the callee's data — `new SpriteDescriptor(id, new Point(-18, -83.75))` exempts the `Point`'s literals under `["SpriteDescriptor.new"]` — through `new` alone; any other call or operator inside the argument resets it. `literalTables: true` (default `false`) also exempts the literals of a lookup TABLE (`LiteralTables`): a `switch` whose every arm maps literal patterns (`case 0x410300:`, `case 33 | 44:`, `case _:` / `default:`) to ONE literal value (`0xC0;`) — the subject stays logic (`switch base << 16` keeps its `16`), and a guard, a capture, a block body or a computed arm makes it no table — and a collection literal of literal data (numbers, negated numbers, plain strings, bools, map entries of those) that a name gives its meaning to: the direct initializer of a local (`final widths = [30, 45]`) or the sole return of a function (`function initDecodeChar() return [-1, 62, 63]`); an inline `draw([3, 4])` stays flagged

## `prefer-interpolation`

a single-argument `Std.string(x)` replaceable with string interpolation (`'$x'` for a simple identifier, `'${expr}'` for any other interpolation-safe expression); `Info`, `--fix` rewrites it (an argument whose source carries a quote or `$` is left alone). A string-producing `+` CONCATENATION chain containing at least one string literal folds into ONE single-quoted interpolated string — `'<xml>' + xhtml + '</xml>'` → `'<xml>$xhtml</xml>'` — with the semantics-critical guards: operands BEFORE the first string literal keep their arithmetic grouping (`a + b + 'x'` → `'${a + b}x'`, never `'$a${b}x'`); `$` in literal parts escapes to `$$`; a double-quoted part merges with `'`→`\'` and `\"`→`"`; a bare identifier renders `$name`, any other operand `${expr}`; `Std.string(x)` inside a chain unwraps to `${x}`. Conservative skips: an operand already interpolating, an interp-source carrying `$` or a newline, a comment between operands, macro/reification contexts, and a pure-literal chain (`fold-adjacent-string-literals`'s job — no double report). Descends into `${…}` interpolation blocks: a call that is the block's sole expression is PEELED (`'v=${Std.string(x)}'` → `'v=${x}'`), a deeper one (ternary branch) nests `'${expr}'` — compile-verified at any depth. An INTERPOLATED CONSTANT is flagged too — a block holding only a literal that prints alike on every target (an `Int` within the non-negative 32-bit range, `true` / `false`, `null`; never a `Float`, which prints `1` on js and `1.0` on python) — and the fix re-renders the whole literal through the fold seam: `'${0} ${i + 1}'` → `'0 ${i + 1}'`, `'$x${0}'` → `'${x}0'`; an annotation argument is skipped. Every finding inside an argument of a macro or compiler intrinsic (the `MacroGate` the fold rule refuses by — a macro keyed by a literal's text, like a translation lookup, sees any rewrite as a different key) is REPORTED and never fixed, whitelist or not. `RiskyFix`+`OracleRelaxable`: with a `compilerOracle` the null-safety gate drops (bare field access becomes a candidate) through the typecheck-and-revert pipeline; without one the safe subset applies unchanged

## `prefer-lpad`

a zero-pad LADDER -- a value-position `if` chain picking a hand-written run of `0`s by digit count -- written as one `lpad` call: `for (i in 1...145) items.push(if (i < 10) 'cones3d000$i' else if (i < 100) 'cones3d00$i' else 'cones3d0$i');` -> `for (i in 1...145) items.push('cones3d' + '$i'.lpad('0', 4));`. `Info`, `--fix` rewrites it and inserts `using StringTools;` when the file lacks one; DEFAULT OFF, because spelling the padding out is a legitimate house style. THE REWRITE IS EXACT ONLY INSIDE A RANGE, and that -- not the shape matching -- is the whole difficulty. `lpad` pads to a FIXED total width while the ladder pads by digit count, so the two agree exactly while the value has as many digits as its branch assumes and diverge the moment it does not: a NEGATIVE value makes the first branch write `'000-5'` where `lpad` writes `'00-5'`, and ABOVE THE LADDER'S TOP the `else` branch keeps prepending its zeros so a four-digit value writes `'01000'` where `lpad`, already at width, writes `'1000'`. Measured rather than argued, on `--interp` AND `-cpp` with byte-identical results: over ladders of 2..4 branches, widths W..W+2, three prefixes and two suffixes, x from -1050 to 10^n+1050, all 199800 IN-RANGE pairs agreed with ZERO divergences, all 56700 negative pairs diverged, and 37836 of 56754 above-top pairs diverged. So the equivalence interval is exactly `0 <= x < 10^n` (n = branch count), and that interval IS the gate. The ONLY range this check can prove is a `for` binder over a LITERAL interval -- `for (x in a...b)` with `a` and `b` plain decimal integer literals, `a >= 0` and `b <= 10^n`; Haxe forbids writing a loop binder at all (`Loop variable cannot be modified`), so proving the range at the `for` header proves it at every read in the body and no write scan is needed. Two things still hold structurally rather than by resolution: the binder must not be REDECLARED anywhere in the loop body (a nested `for`, a local, a lambda parameter of the same name), and the ladder's condition subject must be the same identifier as the string's hole. The redeclaration scan refuses on ANY node inside the body carrying the binder's name whose kind is not a plain identifier read -- deliberately wider than the declaration kinds, since a false refusal costs one missed rewrite and a false acceptance costs a wrong one. OUTSIDE a provable range the finding is REPORT-ONLY: it names the interval the rewrite would need and emits no edit, so a `--fix` run changes exactly the sites whose range is proved. The accepted SHAPE is an `if` / `else if` / `else` chain in value position, 2 to 9 branches, whose conditions are `x < 10`, `x < 100`, ... -- consecutive powers of ten starting at ten, on one and the same bare identifier, because any other threshold breaks the digit-band decomposition the rewrite rests on (`if (x < 20) ...` covers one- AND two-digit values, which no fixed width fits) -- whose LAST branch is a real `else` (a chain without one has no value on the tail path), whose branch values are single-quoted interpolating strings holding exactly ONE hole, that hole being the same identifier, with at most one literal segment on each side of it (a double-quoted literal projects no segments and is refused, as is a `$$` escape, which projects its own node), and whose leading segments share one base text plus a run of `0`s decreasing by exactly one per branch while the trailing segments are identical across branches; the width is `zeros(first) + 1`. The `0`-run is taken GREEDILY off the end of the leading segment, so a base that itself ends in `0` (`'v10'` + `'000'`) still splits consistently -- every branch loses the same base -- and a segment holding a BACKSLASH is refused rather than split, since `'\x30'` ends in a `0` character that is not a zero digit and a character-level cut there would corrupt the escape. A comment anywhere inside the ladder's span refuses that site, because the splice would drop it. Emission is `'<base>' + '$x'.lpad('0', W) + '<suffix>'` with each empty affix omitted; a rival `using` that could also supply `lpad` refuses every edit in the file (the inserted one would lose to it and the call would silently retarget). Replacing an `if`-expression with a `+` chain can only ever bind TIGHTER than what it replaces -- `if` is the loosest expression form in the grammar -- so no parenthesisation is needed and any parens the source already carried lie outside the replaced span. Registered AHEAD of `prefer-comprehension`, whose array-comprehension rewrite can cover the loop a ladder sits in: `Cli.computeFileLintEdits` keeps the first of two overlapping edits, so this one lands and the comprehension is re-detected on the next `--fix` pass, whereas the reverse order loses the `for` header and with it the literal range this fix is gated on. No other builtin claims a value-position `if` chain of string literals (`prefer-ternary-expression` refuses a three-branch chain), measured on the real tree

## `prefer-single-quotes`

a double-quoted string literal that can use single quotes (the Haxe default); `Info`, `--fix` swaps the delimiters. A literal whose content has a `$` (the double quotes deliberately suppress interpolation that single quotes would trigger) or a `'` (which would terminate the single-quoted form) is left alone; every other escape (`\"`, `\n`, …) stays valid verbatim, so only the two delimiter characters change. Without types the rare case of a macro that branches on a literal's quote kind cannot be detected — hence `Info` + opt-in `--fix`, never auto-applied. Disabled for a file whose `checkstyle.json` `StringLiteral.policy` prefers double quotes (`onlyDouble` / `doubleAndInterpolation`)

## `redundant-tostring`

a `.toString()` call sitting in a position that ALREADY stringifies, so the call only restates what the language does anyway; `Info`, `--fix` drops the call. **DEFAULT OFF** — opt in per project with `apqlint.json` `"rules": { "redundant-tostring": { "enabled": true } }`, or select it with `--rule redundant-tostring`. Four stringifying contexts: **interpolation** (`'${x.toString()}'` → `'$x'` for a plain identifier, `'${expr.toString()}'` → `'${expr}'` otherwise — the `$name` shorthand is used only when the block holds the call and nothing else, the next character does not continue an identifier (`'${x.toString()}abc'` would otherwise become a read of `xabc`), and the literal carries no `\x` / `\u` escape — Haxe DECODES escapes before scanning for interpolation, so `'${x.toString()}\x61'` prints `KKKa` while the collapsed `'$x\x61'` is a read of `xa`); **concatenation** — a DIRECT operand of a `+` whose OTHER operand is String-typed (a string literal, an identifier whose recovered nominal type is `String`, or a nested `+` with a String-typed operand — `+` yields a String as soon as either side is one), `s + x.toString()` → `s + x`; **`Std.string(...)`** — `Std.string(x.toString())` → `Std.string(x)`; and **identity** — the receiver is itself String-typed, so the call returns it unchanged (`s.toString()` → `s`), the one arm needing no surrounding context. A bare `.toString()` in a STRING-REQUIRED position is deliberately NOT an arm — Haxe has no implicit stringification where a `String` is EXPECTED, so `var now:String = Date.now().toString();`, `f(d.toString())` into a `String` parameter and `return d.toString();` from a `:String` function all stay silent; that silence falls out of the arms being CONTEXT-gated rather than receiver-gated, so there is no separate veto to keep in sync. **Three proofs gate the FIX; a site missing one is still REPORTED**, with the message naming the missing proof, and carries no edit — so `--fix` only ever acts on a site all three cover. **(1) The receiver is non-null**: removing the call turns a null receiver from a crash into the text `null` (compile-and-run verified on js — `o.toString()` throws where `'$o'`, `Std.string(o)` and `'x' + o` all yield `"null"`), so a fix needs a plain identifier the shared prover accepts (`TypeResolver.isProvablyNonNull`: a `nonNullableTypeNames` value type, or any recovered nominal while `@:nullSafety` is active at both its declaration and the read; an optional / default-null parameter or a `Null<…>` / `Dynamic` / `Any` type refuses), a `new T(...)` (a constructor cannot yield null), a literal, or a call whose declared return type is recovered and is not a nullable wrapper — from the curated `RefShape.staticMethodReturns` table, or through `SymbolIndex.returnNominalOf` for an instance call, which additionally requires `@:nullSafety` active at the call site. The null LITERAL is excluded explicitly rather than by its absence from `literalTypeNames`, an omission maintained for another consumer. A field access (which never narrows), an index read and an unannotated local all fall short here. **(2) The coercion calls the DECLARED `toString`** (the three context arms; the identity arm performs no coercion): the receiver's type must be declared in the analysed scope with NO `extern` declaration. This gate is load-bearing, not defensive — measured on Haxe 4.3.7 / js, `extern class Date`'s `d.toString()` yields `2023-11-15 00:13:20` where `'$d'`, `Std.string(d)` and `'' + d` all yield the native `Wed Nov 15 2023 …`, and `extern class Array`'s `a.toString()` yields `1,2` where the same three yield `[1,2]`; a NON-extern type is compiled by the compiler that also emits the coercion, so there is one `toString` and every context reaches it (verified for a class, an inherited `toString`, an `abstract` over `Array` and over `Date`, and an `enum abstract`). Consequence: a stdlib receiver resolves only when the std is in the resolution scope, and `Date` / `Array` / `haxe.Exception` stay report-only either way. **(3) `+` on the receiver really is concatenation** (the `+` arm only): its type must be a CLASS, since an `abstract` may overload `@:op(A + B)` and the overload is resolved before the String-concatenation rule (verified: an `abstract Tag(String)` with `@:op(A + B)` and `@:to String` silently changes the value once the explicit call is dropped). **A custom `toString` needs no separate gate**: once proof (2) holds the receiver's type is one the compiler itself compiles, so the method runs exactly once either way and a side-effecting `toString` is neither silenced nor duplicated. Shape gates: the call takes NO arguments (so Haxe's static `CallStack.toString(stack)` is excluded by arity) and its receiver must be a VALUE (a zero-argument static `Type.toString()` is excluded by `TypeResolver.receiverRootIsUnboundType` — dropping it would leave a bare type reference); the call must be the DIRECT operand / argument of its context node, so `s + x.toString().substr(0)` is untouched; a comment anywhere in the removed `.toString()` text suppresses the fix while keeping the finding; macro-reification subtrees (`opaqueKinds`) are not descended into

## `string-literal-dup`

A plain string literal repeated at least `minOccurrences` times (default `3`) in one file — a
value that belongs in one named constant so an edit happens once. One finding per value, at its
first occurrence, with the count. `Info`, report-only: the constant's NAME is a human's choice, and
`apq extract-constant` performs the hoist once it is chosen.

Literals shorter than `minLength` (default `4`) are exempt, as are interpolated strings, strings in
metadata arguments (`@:native('…')`) and entries of a data table — an array or map literal made only
of literals, which already is the one named place. Quote style does not matter: `"foo"` and `'foo'`
group together.

```haxe
if (mode == 'preview') … ;
setMode('preview');
log('preview');      // reported once: 'preview' appears 3 times
```
