# Scope-correct refactoring

All resolve against real scopes (never by-name text replace), preserve formatting
(span-splice; everything else verbatim), and are re-parse-validated.

They also see members a `#if` region declares. A member-position conditional projects as ONE node
holding every branch's members, so a scan of a type's direct children exempts them — which used to
make these ops answer "no such member" on a member that plainly exists, or (worse) succeed on an
incomplete set. They now scan through `MemberBranchScan.eachTypeMember`, each member carrying its
own branch's modifier run. An op that MOVES a member out of its type refuses a guarded one instead:
cutting it out of its branch and pasting it elsewhere unguarded would hand it to builds that never
had it. Deleting a member that is the ONLY declaration of its region takes the region with it, so no bare `#if … #end` is left behind; a region whose other branch still declares something keeps its directives.

| Command | Operation |
|---|---|
| `rename` | rename the binding at the cursor + its in-file occurrences. A cursor on a TYPE declaration renames the TYPE NAMESPACE (the forms listed for `--scope` below) confined to the file — `Refs` indexes value bindings only, so without this a type rename rewrote the declaration alone and emitted source that does not compile; references in OTHER files keep the old name and dangle into a compile error, which the advisory names, pointing at `--scope`. The in-file form is for a type no other file names, and for one whose simple name `--scope` would reject as ambiguous (measured: 166 of anyparse `src`'s 1305 type declarations collide by simple name inside their own directory). A cursor on a MEMBER declaration takes the same route through the MEMBER namespace, again confined to the file — value-binding resolution binds a name lexically and never through a receiver's type, so without this a member rename rewrote the declaration and left every `obj.member` access on the old name (measured on a compilable fixture: 10 of 12 member declarations emitted source that does not compile, none silently changed the program's output). It carries the op's own refusals — a constructor, an `override`, a member some ancestor in the file declares, a name the type already has, a case-pattern capture sharing the name — an identifier the language cannot BIND in a pattern (Haxe rejects an upper-case one outright) is a constant reference, not a capture, and no longer refuses. `--scope <dir>` renames cross-file whatever the cursor lands on — a **type** (decl, type positions, `new`/cast/`extends`, struct extensions `{ > T, … }` — nested in an annotation too, `Array<{ > T, }>` —, import/using segments, an import whose path runs THROUGH the type (`import pkg.T.f;`, `import pkg.T.*;`) and an ALIAS import's path (`import pkg.T as U;` — the alias is another name and stays), access grants by the TYPE path (`@:access(pkg.T)`, `@:allow(pkg.T.f)`; for a sub-module type that is `pkg.T`, never `pkg.Mod.T`, which the compiler grants nothing for — and a stale grant compiles, so it is the one position whose miss was silent), a dotted path used as a VALUE (`var c:Class<pkg.T> = pkg.T;`) unless its root identifier is a local, `T.staticMethod()`, and every position naming the type THROUGH its module path — `pkg.Mod.T` from anywhere, `Mod.T` from a file in the module's own package (compiler-checked: an `import pkg.Mod;` does NOT make the short form legal elsewhere), the module path itself for a MAIN type, and a dotted static receiver `pkg.Mod.CONST` including every `macro pkg.Mod.Ctor(…)` reification. Each candidate path is matched WHOLE, never by last segment, so a same-simple-name type from another module stays untouched; renaming a module's MAIN type renames the module path with it, so the FILE must be renamed to match; a BARE type name in VALUE position — `var c = T;`, `Std.isOfType(x, T)` — is the one position left unrewritten: unqualified it cannot be told from a nullary enum constructor or an inherited member without a typer, so it dangles into a compile error the advisory names) or a **member** (method/field: decl, in-type refs, `Src.member` for statics, `obj.member` for type-resolved instance receivers — including a receiver typed as a SUBTYPE, and a `new T()` receiver, which names its own type and needs no binding at all; an `enum abstract` VALUE is static without saying so — Haxe rejects an instance data field in an abstract — so it takes the static path, and a bare `case VALUE:` renames too wherever the switch SUBJECT resolves to that abstract, which is what keeps a same-named value of a DIFFERENT abstract in the same file untouched. A bare VALUE in RETURN position renames on the same footing: Haxe resolves an unqualified enum-abstract value from the EXPECTED type, so the proof is the enclosing function's DECLARED return type — read verbatim from its own span, one `Null<…>` wrapper unwrapped, and resolved FROM THE READING FILE through the index's whole-path / import / package rules, never by last segment — reached through the type-transparent slots under a `return` (a parenthesis, both arms of a ternary and of an `if` expression, the last statement of a `switch`-expression arm). A nested function owns its own return type and stops the proof there, and a member the enclosing type or an ancestor declares SHADOWS the expected-type reading (compiler-checked) and is left alone) atomically. A `#if` region is a member HOST, not a member, so a guarded member resolves like any other, and a member the region declares once per BRANCH is one logical member whose every declaration moves in the same edit set — rewriting only the cursor's branch leaves the other build targets with accesses no declaration matches, which no single-target compile catches. A member the cursor sits on that is itself an `override` is refused with a pointer to the base, and so is one that implements a declaration on an ancestor IN the scope — an implementation of an `abstract` method or an interface method carries no `override` modifier, so the keyword-based guard alone never saw it and the rename left the base declaring a member nothing implements; renaming that base carries the whole PROVEN override family — each override's declaration and each subtype's own reads — in the same atomic set, and refuses outright when a same-named declaration can be proven neither family nor unrelated |
| `inline` / `inline-method` | inline a local variable into its reads / a single-return function into its call sites |
| `extract-var` / `extract-method` | hoist an expression into a `final`, or a statement run into a local function — or, with `--member`, into a new private member of the enclosing type (read locals become typed parameters, locals read after the run the typed return value; the inverse of `inline-method`) |
| `extract-constant` | a literal to a named constant — every occurrence in a type (`--type`) or across a scope into a constants module (`--into`); ADDRESSED (`--select` / `--match` with `--to <Type>` or `--into <module.hx>`): ONE expression, or a local's / field's initializer, into a `static final` of a type in any module or package, leaving `Type.NAME` and the import. Only a compile-time constant that reads nothing moves (an array / object literal of them under `--shared`); a scalar literal becomes `static inline final`; refused in metadata, a `case` pattern, a non-folding parameter default, and where the bare type name would bind something else |
| `move-elements` | move a slice `--range a..b` of one array literal into another (another member or `--into` another module): appended in order (`--append '<target>'`) or sorted in (`--sorted '<target>'`, the `add-element --sorted` rules); the result is checked (the source lost exactly the slice, the target gained it) and `--dry-run` prints the moved entries with their MD5 digest, so a split can be verified mechanically; elements that read a name, or name a non-std type across modules, are refused |
| `change-sig` / `add-param` / `remove-param` | reorder params + call-site args / append a backward-compatible param / drop a param + its arguments |
| `move` | move a type declaration to another file (any package), carrying deps and repointing every importer's import path (`a.T` → `b.T`); a cross-package move refuses a fully-qualified `pkg.T` code reference that would dangle |
| `move-member` | move one or more members to another type — the Apply verb of the `clusters` decomposition loop. Static: `Src.member` callers rewritten across `--scope`, bare in-file callers qualified, sibling references qualified back (`@:access` for private targets). Instance (sibling-fields contract): remaining bare callers rewired through a `--via` field of type Dest (auto-detected when unique), final-field reads kept bare when the destination declares the same field, calls inside the moved set kept bare. `--closure` first grows the move set to the transitive closure of the instance methods the seed members call, so a self-contained cycle moves in one shot instead of one refusal per missing dependency. `--scaffold` generates a missing destination final field + constructor and a missing via field (with `new Dest(...)` wiring in the source constructor, placed right after the last statement writing a field it is built from, so a `@:nullSafety(Strict)` constructor that binds a method later still compiles) into an empty destination instead of refusing. An instance member of the source's inheritance family is refused — an `override`, the implementation of a supertype's member, one a subtype overrides, one an unresolved `implements` target may declare — and a receiver-qualified caller is left alone only when its receiver is a CLASS or INTERFACE provably unrelated to the source (an abstract, an `enum abstract`, a structure refuse). Visibility promoted when callers remain, imports carried — imports first, sorted, then the `using` lines in the source's order, and a `using` whose known extension methods the moved code calls none of stays behind (a call binding a MEMBER of its receiver's type — `a.concat(b)` on an `Array` under `using Lambda` — is none of them: the same member-first door `unused-import` asks); atomic (all rewritten files re-parse or none). A STATIC-only move may cross packages, dotted callers included — a qualified receiver is repointed at the destination's root-anchored path, legal from every file and needing no import. Every other import is one rule's call (`RefactorSupport.bareNameResolves`): a rewritten caller, the source file and the destination file each gain an import of the type they now name BARE unless that bare name resolves there on its own — sharing a package is not proof, a SUB-MODULE type is invisible bare even to a sibling file in its own package |
| `move-to-helper` | move members of a CLASS into a static helper type — an existing one, or a `final class` created beside the source — that takes the class as an explicit first parameter: the op for a member that READS the source's state, which `move-member` refuses (`this`) and `--scaffold` would copy. A moved instance method becomes `static` with a first parameter `<param>: <Src>` (`--param`, default the type name lower-cased); in its body, found through `Refs`, never a text scan, a member staying behind (own or inherited) becomes `<param>.x`, a bare `this` becomes `<param>`, a staying static `Src.x`, and a call between moved members gains `<param>`; every caller becomes `Helper.m(this, …)` or `Helper.m(recv, …)` for a receiver proven to be a source (`MoveMemberReceivers`), a subtype's bare call included. A private constant and a module-private type only the moved code names travel with it. The helper reads private members through `@:access(<pkg>.<Src>)` (on the member, or on the helper for two or more — `move-member`'s rule), not `@:allow` on the source. Refused with the reason: a non-class or generic source; an override, an overridden member, an interface implementation; `dynamic` / `macro` / `extern` / `overload`; a property accessor; an instance field; a moved member used as a function value; `super`; an unresolved name; a module-level value of the source module; a private type the staying code names too; a parameter name the moved code spells. `--dry-run` prints every file as it would be written; `--arms <registry.json>` prints the mutation-arm retarget hint (an arm on a moved member, an arm whose `find` no longer cuts its member) — a hint, the registry is not edited. Atomic |
| `extract-interface` | generate an interface from a class's public instance methods (or a `--members` subset) and make the class `implements` it — signatures sliced `[FnMember, body)`, referenced imports carried, the interface written to a sibling file; no call sites change (additive) |
| `pull-up` / `push-down` | move an instance member along the inheritance axis (to a direct super/subclass) — no call sites change (inheritance keeps it visible); pull-up refuses when the body references a subclass-only member, push-down warns that superclass-typed callers stop compiling |
| `extract-superclass` | generate a superclass, pull a chosen `--members` set up into it (bodies + carried imports), and make the class `extends` it — no constructor on the superclass (the source constructor is unchanged), no call sites change; refuses stranded references and a class that already extends one |
| `safe-delete` | remove a member only when no reference to it survives across the scope — the guarded, cross-file, any-visibility form of `remove-member`; any `x.member` access or bare in-type reference blocks the deletion (self-recursion excluded) and is listed |
| `encapsulate-field` | turn a stored `var` field into an `@:isVar` property with `get_`/`set_` accessors — the field stays the backing storage so no reference is renamed; requires a plain, non-final, non-static, explicitly-typed instance field |
| `make-final` | turn a mutable `var` field into `final` when it is never reassigned after its single initialisation (any write outside the constructor, cross-file `obj.field =` included, refuses) — unblocks the `move-member` instance path, whose final-fields contract needs it |
| `introduce-parameter-object` | replace a contiguous run of a function's parameters with one object parameter of a generated `typedef` — rewrites the signature, the body's references (`x` → `point.x`), and every resolvable in-file call site (`f(1, 2)` → `f({x: 1, y: 2})`); reuses the `remove-param` call-site completeness proof; a short `$x` string-interpolation use is refused |
| `symbols` / `importers` / `declares` | list top-level type declarations across a scope / files importing a module / the declaration site(s) of one named type |
