# The calibrated Fast-parse bench corpus: 99 files, ~7% of the parse cost of
# the two reference trees, chosen so that A/B deltas measured on it reproduce
# the deltas on the full trees. Feed it to tools/ParseProf.hx:
#
#   TM_SRC=<other-tree>/src node bin/parse-prof.js tparse tools/bench-corpus.txt 6 hxformat.json
#
# Half the corpus lives in a tree that is not in this repository, written
# ${TM_SRC}/... - those lines are skipped when TM_SRC is unset, leaving the
# anyparse-only half, which is still stratified but no longer calibrated.
#
# HOW IT WAS CHOSEN (reproduce with `perfile` + the recipe in
# /Users/axg/anyparse-o1-parse-profile.md):
#   1. `node bin/parse-prof.js perfile <tree> 3 hxformat.json` on both trees -
#      per-file bytes, lines, parse us, round-trip us, node count and a
#      node-kind census.
#   2. Stratify into 4 size buckets (<2K, <8K, <32K, >=32K) x 4 construct
#      classes (conditional-heavy, macro/metadata-heavy, string-heavy, plain).
#   3. Give each stratum its share of a fixed corpus PARSE-COST budget, picking
#      files at evenly spaced cost ranks inside the stratum; tune the budget
#      until the file count lands near 100. Sampling at a uniform FILE rate
#      instead drifts the cost mix by up to 19 points, because five files carry
#      8% of all parse cost.
#
# CALIBRATION against the full trees (measured 2026-08-17, medians of 5
# interleaved rounds): parse-cost mix within 3.9 points on every stratum;
# rt/parse 3.43 against 3.38; A/B deltas within ~2-3 points for effects >=10%.
# Use reps>=6 for timing (amortises JIT tier-up) and reps=1 for --cpu-prof
# (the primitive mix then matches the full trees within ~2 points; at reps=10
# V8 over-optimises and expectLit's share drops by 10).
